--- title: DeepInfer Explained summary: A study guide to the DeepInfer inference engine for Python developers who know little about machine learning. It starts simple and goes down to the exact code. ---

DeepInfer is DeepSeek's inference framework: the program that runs a trained model and makes its answers. It "powers DeepSeek's large-scale production services" ({{cite README.md:3}}). This open-source release runs one model, DeepSeek-V4.1-Flash, on NVIDIA SM100 {{term gpu | GPUs}} and on Huawei Ascend 950 {{term npu | NPUs}} ({{cite README.md:5-7}}, {{cite README.md:33-36}}). It does offline inference: your Python script gives it a list of prompts and gets the answers back ({{cite README.md:3}}). DeepInfer "was originally built primarily on vLLM" ({{cite README.md:95}}), and many files still say "Derived from vLLM; modified by DeepSeek."

This site explains the code at commit 9bd9cf2. To get exactly this version of the code, read The code version this site explains. You need to know Python. You do not need to know machine learning: Part 1 teaches the basics first.

What is not in this release

The README lists three parts that a complete inference service needs, but that this release does not include ({{cite README.md:38-42}}):

  1. A KV cache system that keeps the KV cache of old requests for reuse. The Q&A says that this part is tied to DeepSeek's internal systems and is not open source yet ({{cite doc/inference_deployment_qa.md:21}}). The production service stores it on a 3FS storage cluster ({{cite doc/inference_deployment_qa.md:141}}).
  2. VE/Prefill/Decode disaggregation ({{term epd | E/P/D}}): separate services for the image encoder, for prefill and for decode. The README says that "most required engine functionality is already implemented". You can see empty hook methods for it in {{link code/llm-engine | LLMEngine}}.
  3. Load balancing across data-parallel replicas, for prefill and for decode.

The picture below comes from the deployment Q&A in doc/. It shows the whole production system. This repository contains the engine that runs inside these services, with its expert-parallel load balancer ({{link concepts/eplb | EPLB}}). In this release, one NORMAL engine does prefill and decode in the same process ({{cite deepinfer/engine/arg_utils.py:41}}), and the model runs the image encoder itself ({{cite deepinfer/model_executor/models/deepseek_vl.py:26-34}}). The entrypoint, the DeepSeek Recipe, the three load balancers and the external KV cache storage are not in this repository.

The fast kernels for attention, matrix multiply and expert communication come from separate libraries: FlashMLA, DeepGEMM, DeepEP and DeepSelect, plus Ascend versions ({{cite .gitmodules}}). They are git submodules and are not checked out here. The site explains how DeepInfer calls them: which function, which arguments, which shapes. It does not explain how they work inside.
