Purpose

The eplb package keeps the expert tables that the gate reads, counts the tokens of every slot, and every N steps moves expert copies so that the EP ranks get about the same work.

Filesdeepinfer/model_executor/eplb/__init__.py (434 lines): state, timing, statistics, manager. policy.py (140 lines): the placement algorithm. shuffle.py (218 lines): the weight moves. Most comments and docstrings are in Chinese; this page translates them.
Main classExpertLoadBalancer ({{cite deepinfer/model_executor/eplb/__init__.py:42}}), one per group of MoE layers with the same layout. ExpertLoadBalancerManager ({{cite deepinfer/model_executor/eplb/__init__.py:352}}) holds them all.
Runs inEvery rank process. The counting is on the device. The policy runs on the device tensors with a Python loop. A rearrangement synchronizes the device.
Called byDeepseekForCausalLM (set-up and step after sampling), DeepseekMoE (tables and counters), the model loader (extra-slot rounding), the HF weight loader (first layout), examples/benchmark.py.
Callstorch.distributed (all-reduce, all-gather, batched P2P, barriers), torch.distributed._symmetric_memory, PG.is_within_nvl_domain.
Not in this packageThe token counting itself (DeepEP and DeepGEMM kernels add into expert_count), and the choice of one copy per token (the gate kernel).

Where it sits

Who calls it

  • Model loader. _configure_moe_redundancy calls resolve_num_extra_experts for the main and DFlash layouts ({{cite deepinfer/model_executor/model_loader.py:83-106}}).
  • HF weight loader. _local_expert_ids calls get_initial_global_physical_to_logical_map to know which checkpoint experts go into each local slot ({{cite deepinfer/hugging_face/weights.py:248-271}}).
  • Model set-up. DeepseekForCausalLM._init_eplb groups the MoE layers by layout, makes one ExpertLoadBalancer per group, and installs the manager with set_current ({{cite deepinfer/model_executor/models/deepseek.py:323-365}}).
  • Every step. DeepseekForCausalLM.sample calls eplb.current().step(is_prompt) and later moves the load ratio into the sampler output ({{cite deepinfer/model_executor/models/deepseek.py:402-409}}).
  • Every MoE layer. DeepseekMoE._eplb_layer() reads the tables and the counter of its layer ({{cite deepinfer/model_executor/models/v4_modules/mlp.py:326-327}}).
  • Benchmark. steps_until_lb_stat_flush lets the benchmark avoid the statistics all-gather in its measurement window ({{cite examples/benchmark.py:411-415}}).

What it calls

  • dist.all_reduce of the window counts over the EP group ({{cite deepinfer/model_executor/eplb/__init__.py:254}}) and dist.all_gather_into_tensor for statistics ({{cite deepinfer/model_executor/eplb/__init__.py:188}}).
  • symm_mem.empty and symm_mem.rendezvous for the mirror ({{cite deepinfer/model_executor/eplb/__init__.py:206-209}}).
  • dist.batch_isend_irecv in the P2P shuffle ({{cite deepinfer/model_executor/eplb/shuffle.py:135-138}}), and ep.barrier() in the intranode shuffle ({{cite deepinfer/model_executor/eplb/shuffle.py:192-195}}).

Walk through the main methods

DEEPINFER_EXPERT_REARRANGEMENT_STEP_INTERVAL defaults to 0 ({{cite deepinfer/environ.py:116}}). Then _update_rearrangement returns at once, and only counting and statistics run.

ExpertLoadBalancer.__init__

All layers copy the same initial map. Bring the first rearrange forward to 1/4 of the period, to correct the cold-start imbalance early.
  1. Lines 83-84: two flags for a NORMAL engine: rearrange after prefill, or skip prefill steps.
  2. Lines 86-95: build logical_to_physical_map from the first layout. Each logical expert lists its slots; unused entries stay -1.
  3. Lines 98-100: one copy of the tables per layer, made contiguous so that each layer can change its own row later.
  4. Lines 104-111: the window must be from 1 to the interval when rearrangement is on.
  5. Lines 122-123: the first rearrangement after a quarter of the interval.
  6. Lines 125-129: the statistics interval must be positive.

step and _update_rearrangement

Called by DeepseekForCausalLM.sample in every step; updates the rearrangement and the load statistics. Steps until the next LB statistics flush (EP all_gather); None when EP = 1 and there are no statistics. Rearrange at once in the next non-prefill step.

The order matters: the rearrangement reads the window before line 138 clears expert_count. The concept page {{link concepts/eplb}} explains the timing with an example.

_rearrange_experts

Token counts of each logical expert in the window: aggregate the local physical slots, then all-reduce over the EP group.
  1. Line 222: @allow_cuda_sync() lifts DeepInfer's guard against device synchronization for this method ({{cite deepinfer/utils.py:135-140}}).
  2. Line 227: rank 0 synchronizes first, to time the method.
  3. Lines 238-253: scatter_add_ turns the local slot counts [W, Lm, n_loc] into logical counts [W, Lm, E], with the current layout.
  4. Line 254: the all-reduce adds the counts of all EP ranks. All ranks then run the policy on the same input and get the same layout.
  5. Lines 261-275: the shuffle moves the weights while the old layout is still in physical_to_logical_map.
  6. Lines 276-278: copy_ writes the new tables into the same tensors, so the views that the MoE layers hold stay valid.

rebalance_experts_global

Global load balancing: give redundant copies to hot logical experts, then balance all copies over the GPUs. [num_moe_layers, num_logical_experts, num_redundant_experts + 1], unused entries -1 [num_moe_layers, num_logical_experts], copies of each logical expert

The replication loop is at lines 105-123 and the placement at lines 125-138. The concept page reads both line by line, with a worked example and the diagram of the policy.

The two shuffle functions

Copies on this device: origin to buffer. Cross-device P2P, bucketed by (peer rank difference mod number of groups), each bucket sent in one batch. TODO: prefer intra-machine traffic and broadcast here. Send: for each expert that this device holds, send it to the receivers that are paired with this device. Receive: for each missing expert, receive from the paired sender into the buffer (one expert with several slots is received once). Finish: buffer to the slots of this device.

The intranode version has the same plan, but reads the peer mirrors directly ({{cite deepinfer/model_executor/eplb/shuffle.py:178-218}}). The concept page has the step list of both.

The unit test checks the table invariants: logical_count equals the valid entries of logical_to_physical_map, every slot is in the list of its expert, and the counts add up to P ({{cite tests/models/test_eplb_policy.py:27-42}}).
  • Each rank has its own balancers. All EP ranks call step in the same order, because the all-reduce and all-gather are collectives.
  • steps_until_lb_stat_flush asserts that all balancers of the manager have the same countdown ({{cite deepinfer/model_executor/eplb/__init__.py:397-401}}).
  • The statistics sums move to the CPU with non_blocking=True. They are read later, in a post function of the sampler output ({{cite deepinfer/model_executor/models/deepseek.py:406-409}}).
  • The rearrangement uses .tolist() on the layouts in the shuffle ({{cite deepinfer/model_executor/eplb/shuffle.py:84-88}}), which synchronizes. This is why the method runs under allow_cuda_sync.
  • _initialize_shuffle calls torch.cuda.empty_cache() before the first move, "to prevent OOM" (translated, {{cite deepinfer/model_executor/eplb/__init__.py:196-198}}).

examples/_config.py with EPLB on: window 3, interval 30, after-prefill on, lower limit 32 ({{cite examples/_config.py:77-83}}). EP 8, a NORMAL engine, and a toy expert count of 64.

  1. Extra slots: -(64 + 32) % 8 = 0, so 32. Slots: 96, 12 per rank. The first layout copies experts 0 to 31 into slots 64 to 95.
  2. Window [3, Lm, 12] int32 per rank. Lm is the number of main MoE layers. DFlash layers with a different layout have their own balancer.
  3. Counter start: 30 − max(1, 7) = 23.
  4. A prefill step: the window gets the prefill counts, the counter becomes 29. The next decode step: the window gets its counts, the counter reaches 30, and the layout is recomputed from the last 3 steps.
  5. The policy gives the 32 extra slots to the experts with the highest load per copy, then places 96 copies on 8 ranks.
  6. Every 128 steps (the default), the ranks all-gather [8, 128, Lm] int64 and the logger can show moe_lb.

Which function rounds DEEPINFER_OVERRIDE_NUM_EXTRA_EXPERTS, and who calls it?

resolve_num_extra_experts ({{cite deepinfer/model_executor/eplb/__init__.py:21-28}}). The model loader calls it in _configure_moe_redundancy, once for the main layers and once for DFlash ({{cite deepinfer/model_executor/model_loader.py:93-106}}).

 Why do all EP ranks compute the same new layout without sending it to each other?

Line 254 all-reduces the window counts, so every rank has the same input. The policy has no randomness and fixed tie rules, so every rank gets the same output ({{cite deepinfer/model_executor/eplb/__init__.py:254-260}}, {{cite tests/models/test_eplb_policy.py:53-62}}).

 The main model and the DFlash layers have different expert counts. How many balancers are there?

One per layout, so at least two. _init_eplb groups layers by the layout key (expert counts, EP group, weight shapes and types) and makes one ExpertLoadBalancer per group ({{cite deepinfer/model_executor/models/deepseek.py:331-364}}). Different expert counts give different keys.

 Why can _rearrange_experts overwrite the maps with copy_ instead of new tensors?

The MoE layers hold views of the balancer tensors: ExpertLoadBalancerLayerState returns row i of each tensor ({{cite deepinfer/model_executor/eplb/__init__.py:370-376}}). A new tensor would leave the layers with the old one. copy_ changes the data in place ({{cite deepinfer/model_executor/eplb/__init__.py:276-278}}). A captured CUDA graph also keeps the device addresses of its inputs, so the data must change in place.
