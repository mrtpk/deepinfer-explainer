It adds the vision encoder to DeepseekForCausalLM, prepares image metadata in the multimodal worker process (multi_modal_mapper), and computes the input embeddings of every prefill. ---

Purpose

DeepseekVLForCausalLM extends the text model with images: it owns the vision encoder, it turns the image part of a request into tensors, and it merges the image vectors into the prefill embeddings.

Walk through the main methods

multi_modal_mapper (worker process)

The worker is forked at start-up ({{cite deepinfer/ve/multimodal_processor.py:93-103}}). multi_modal_mapper must not touch the device or engine state. It gets a dict through a queue and returns a dict.

 A ve_failed request (image_bytes=None) does not go through overwrite_prompt; pass it on unchanged. Read the cache information that multi_modal_processor.add() computed, and try to cut off the cached prefix. The tokens themselves stay in the engine; the processor only makes the modality tensors (mm_token_type and image keys).
  1. Lines 110-111: no segment_input means that the engine did not expand the prompt. The dict goes back as it is.
  2. Lines 117-119: the cached counts come from MultimodalProcessor.add. In this release the engine passes no cache length, so num_cached_images is 0 ({{cite deepinfer/engine/llm_engine.py:625}}).
  3. Line 130: each segment goes to its processor. Text segments give mm_token_type zeros; image segments give the layout tensors and a lazy image loader ({{cite deepinfer/ve/processor/text_processor.py:10-13}}, {{cite deepinfer/ve/processor/image_processor.py:282-306}}).
  1. Line 149: _load_image_raw_bytes runs the lazy loaders: decode, then the CPU resize. With more than one image it uses a thread pool ({{cite deepinfer/model_executor/models/deepseek_vl.py:81-89}}).
  2. Lines 159-164: cu_raw_bytes is the running sum of width × height × 3 in int64. The comment says the byte offsets do not have the int32 limit of the token counts.
  3. Lines 170-171: image_starts and image_lens are the token spans of the images. The chunk slicer uses them, then drops them.
  4. Line 179: images_seq_mask is true where mm_token_type ≥ IMAGE: IMAGE, IMAGE_START, IMAGE_END, IMAGE_NEW_LINE and IMAGE_PAD ({{cite deepinfer/multimodal_tokens.py:31-41}}).
  5. Lines 184-186: the key set must equal MM_METADATA_KEYS of ve/schema.py, else AssertionError.

get_input_embeddings and forward

Invalid ids (negative, and the special image tokens at or above vocab_size) are set to zero by the gather kernel, so no mask is needed first. The ViT is loaded with the LLM; in this process, first pad the raw RGB bytes into patches, then encode. When no sequence of the batch has multi_modal_data (text only / profile run), the mapper makes no images_seq_mask. Build it from input_ids, so that the MoE gate and Engram take the same masked path as a batch with images.
  1. Line 200: the normal embedding. The comment says that the gather kernel gives zero rows for ids at or above vocab_size; the kernel itself is in TileLang.
  2. Lines 202-218: only when the batch has image bytes, the tuner runs the vision encoder and writes the image vectors in place. A chunk without images has images_raw = None.
  3. Lines 221-222: the mask always exists after this method.
  4. Lines 232-233: the VL class computes the embeddings in every prefill, also text-only. So the embedding line of DeepseekModel.forward runs only in decode ({{cite deepinfer/model_executor/models/deepseek.py:161-162}}).

load_model and derive_image_transform_cfg

The device kernel rgb_pad_to_patches uses one mean, one std and one pad value for all three channels, so the method asserts equal channels and a nonzero std. It also asserts that the processor dtype is bfloat16. The HF processor config sets mean and std to 0.5 ({{cite deepinfer/hugging_face/processor.py:34-35}}). So the pad colour is int(0.5 × 255) = 127. The comment says int() truncates, to match the processor.

The tuner reads these keys with cfg["..."] and no default. A comment explains: a default would let the ViT silently get pixels in [0, 1] that are not normalized, so a missing value must raise KeyError ({{cite deepinfer/model_executor/models/vision_encoder/vl_aligner.py:22-27}}).

With the pool on, the worker replaces each tensor by a pool handle before the queue ({{cite deepinfer/ve/multimodal_processor.py:202-211}}).

The mapper can skip images that the KV cache already holds. MultimodalProcessor.add counts the images that lie fully inside the cached token prefix and drops their bytes ({{cite deepinfer/ve/multimodal_processor.py:219-246}}). The mapper then replaces the cached segments with one TextLengthInput of the same length ({{cite deepinfer/model_executor/models/deepseek_vl.py:62-72}}). It adds zero rows in images_spatial_crop and images_input_size for the cached images, so that the per-image indices stay aligned ({{cite deepinfer/model_executor/models/deepseek_vl.py:133-158}}).

The only caller in the package, _enqueue, does not pass num_cached_tokens ({{cite deepinfer/engine/llm_engine.py:625}}). So in this release the cached count is always 0. A test calls only the first part, _compute_and_strip_cached_images, directly ({{cite tests/engine/test_mm_overwrite_prompt.py:128-137}}). No test in the repo calls _split_cached_prefix.

In which process does multi_modal_mapper run?

In the forked multimodal worker process, not in the rank process ({{cite deepinfer/ve/multimodal_processor.py:197-201}}).

 A batch has only text prompts. Why does images_seq_mask still exist after get_input_embeddings?

Lines 221-222 build it from the ids when the mapper made none. The comment says this keeps the MoE gate and Engram on the same masked path as a batch with images ({{cite deepinfer/model_executor/models/deepseek_vl.py:219-222}}).

 Why does derive_image_transform_cfg reject a mean of (0.48, 0.46, 0.41)?

The device kernel rgb_pad_to_patches takes one scalar mean, one std and one pad value for all channels ({{cite deepinfer/model_executor/layers/tilelang_ops/image_embed_ops.py:51-53}}). So the method asserts equal channel values ({{cite deepinfer/model_executor/models/deepseek_vl.py:251-253}}).
