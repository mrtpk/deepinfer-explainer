Purpose

cross_layer.py decides, once at start-up, which layer is the source of each shared value, and carries those values from layer to layer during a forward.

Where it sits

Who calls it

  • The builder makes a topology to decide which containers get PackedWkv and an indexer ({{cite deepinfer/model_executor/models/v4_modules/builder.py:100-106}}, {{cite deepinfer/model_executor/models/v4_modules/builder.py:63-73}}).
  • DeepseekForCausalLM.__init__ makes it again for the runtime modules and passes it to every layer ({{cite deepinfer/model_executor/models/deepseek.py:266-269}}, {{cite deepinfer/model_executor/models/decoder_layer.py:85}}).
  • ModelMetadata calls build_shared_layer_metadata ({{cite deepinfer/model_executor/model_metadata_utils.py:75}}). The C++ FlopsEstimator reads the flag lists from it ({{cite csrc/engine/flops_estimator.hpp:158-171}}).
  • DeepseekModel.forward makes one CrossLayerRuntime per forward ({{cite deepinfer/model_executor/models/deepseek.py:165-166}}). A decoder layer called without one makes its own ({{cite deepinfer/model_executor/models/decoder_layer.py:108-109}}).

What it calls

iter_runtime_attn_modules walks the attention list and skips the lm-head entry, so main and draft layers get one runtime number each ({{cite deepinfer/model_executor/layer_utils.py:6-16}}). Nothing else: this file has no tensor work.

Walk through the main methods

_process_cfg: one shared config

  1. Lines 66-69: every runtime layer that carries layer_info_shared_cfg joins the list. The HF loader gives it to every compressed layer ({{cite deepinfer/hugging_face/config.py:129}}).
  2. Line 71: at least one layer must carry it. build_shared_layer_topology checks this first and returns None instead ({{cite deepinfer/model_executor/models/v4_modules/cross_layer.py:346-351}}).
  3. Lines 74-75: all copies must be equal; the first one is the canonical config.

_build_layer_map: dense maps

  1. Lines 145-146: without its own map, index K follows the top-k map. (The HF loader always writes an index-K map, by default equal to the KV map: {{cite deepinfer/hugging_face/config.py:74}}.)
  2. Lines 148-150: every id must be a valid layer.
  3. Line 151: a layer that is not in the map is its own source.
  4. Lines 152-154: the draft (MTP) layers must not share.

_validate: the checks

  1. Lines 97-113: for each map, check the segments, then check each consumer: it carries the config, and it matches its source.
  2. Lines 114-116: the first YOCO consumer layer is a KV source (see {{link concepts/yoco-swa-replay}}).
  3. Lines 117-118: the nesting check and the candidate checks.

All checks are assert statements, so a bad config stops the start-up with an AssertionError and a message that names the layer.

CrossLayerRuntime: the per-forward values

The docstring explains why one slot per value is enough: the segments are contiguous and the layers run in order, so the value in the slot always comes from the nearest source ({{cite deepinfer/model_executor/models/v4_modules/cross_layer.py:284-287}}). The object is not returned through the layer outputs; the same reference goes to every layer ({{cite deepinfer/model_executor/models/v4_modules/cross_layer.py:281-282}}).

  3. _validate_segmented_map walks the list: 0 is a source, 1 is a source, 2 → 1 equals the last source, and so on. Pass.

  5. YOCO: the ratios are [0, 2, 2, 2, 2, 1, 2, 2], so n_prefill_layer = 5 and layer_kv_map[5] = 5. Pass.
  6. build_shared_layer_metadata gives is_kv_source_list = [T, T, F, T, F, T, T, F, T] and the same for index K; is_index_source_list differs only at layer 2 (T).

The same config is turned into a topology at three places: in the builder (containers), in DeepseekForCausalLM.__init__ (runtime modules) and in each ModelMetadata (flag lists). The cache engine does not use the class at all: it reads the raw maps from each layer's layer_info_shared_cfg ({{cite deepinfer/worker/cache_engine.py:141-162}}). The code keeps these in agreement by convention, and the comment on lines 106-109 explains the one case that would break it: a consumer without the shared config.

The layer count also differs in form: the builder passes num_hidden_layers + nextn ({{cite deepinfer/model_executor/models/v4_modules/builder.py:102}}); the model counts its modules minus the embedding and the lm head ({{cite deepinfer/model_executor/models/deepseek.py:267-269}}). Both give the number of main plus draft layers.

How many CrossLayerRuntime objects does one forward of the main model use?

One. DeepseekModel.forward makes it and passes the same reference to every layer ({{cite deepinfer/model_executor/models/deepseek.py:165-166}}, {{cite deepinfer/model_executor/models/v4_modules/cross_layer.py:281-282}}).

 A layer is missing from layer_kv_map in the config. What does SharedLayerTopology make of it?

A KV source: raw.get(layer_id, layer_id) ({{cite deepinfer/model_executor/models/v4_modules/cross_layer.py:151}}). If the layer sits between a source and its consumers, the segment check then fails ({{cite deepinfer/model_executor/models/v4_modules/cross_layer.py:44-47}}).

 Why does a single slot per value work in CrossLayerRuntime?

The maps are contiguous segments and the layers run in order of their id. So when a consumer runs, the last value written is the one of its nearest source ({{cite deepinfer/model_executor/models/v4_modules/cross_layer.py:284-287}}, {{cite deepinfer/model_executor/models/v4_modules/cross_layer.py:169-179}}).

 In the worked example, what are is_kv_source_list and is_index_source_list, and why does layer 2 differ?

is_kv_source_list = [T, T, F, T, F, T, T, F, T]; is_index_source_list is the same except T at layer 2 ({{cite deepinfer/model_executor/models/v4_modules/cross_layer.py:370-374}}). Layer 2 is in index_source_layer_ids but not in kv_source_layer_ids, so it runs its own indexer on the KV and index keys of layer 1. See the deep dive "Worked example".
