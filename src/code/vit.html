Purpose

These three files are the {{term vision-encoder | vision encoder}}: they turn the raw pixels of the images in a prefill batch into one vector per image token and write those vectors into the input embeddings.

Where it sits

Who calls it

  • HFModelParameters.__init__ makes VisionTransformer(**cfg.vision.params) and MlpProjector(cfg.mlp_projector.params) on the device, because the ViT builds its RoPE table in the constructor ({{cite deepinfer/model_executor/models/v4_modules/containers.py:50-54}}).
  • DeepseekVLForCausalLM.__init__ makes the tuner from these modules and the three special-token vectors of the embedding module ({{cite deepinfer/model_executor/models/deepseek_vl.py:35-39}}).
  • get_input_embeddings calls the tuner when the batch has image bytes ({{cite deepinfer/model_executor/models/deepseek_vl.py:202-218}}).
  • examples/_ve_helper.py loads only these weights for tests and timing ({{cite examples/_ve_helper.py:1-5}}).

What it calls

  • image_embed_ops.rgb_pad_to_patches, batch_downsample and replace_input_embeds ({{cite deepinfer/model_executor/models/vision_encoder/vl_aligner.py:5}}, {{cite deepinfer/model_executor/models/vision_encoder/vl_aligner.py:116}}).
  • _flash_attn_fwd from flash_attn.cute, deep_gemm.bf16_gemm_nt or cublaslt_gemm_nt, tile_kernels SwiGLU and rotary ({{cite deepinfer/model_executor/models/vision_encoder/vit.py:10-20}}).

Walk through the main methods

Attention.forward

The flash-attn versions and builds return different numbers of outputs (2-3 or 5); take only the first.
  1. Line 100: one GEMM for Q, K and V (1024 → 3072, with bias).
  2. Line 105: rotary embedding on Q and K, in place.
  3. Lines 107-122: cu_seqlens holds the patch ranges of the images. With causal=False and no window, every patch attends to every patch of the same image and to no patch of another image.

npu_ops replaces this _flash_attn_fwd with a wrapper around torch_npu.npu_fusion_attention ({{cite deepinfer/npu_ops/vit_attn.py:8-31}}). That call needs the segment ends as a host list, so VisionTransformer.forward passes vit_attn_cu_seqlens when it is set ({{cite deepinfer/model_executor/models/vision_encoder/vit.py:224-225}}).

Block.forward: a lazy residual

Returns (x, residual); a non-None residual means the next block's norm kernel adds it. Both norms bypass RMSNorm.forward: the fused residual add returns two values, which the single-value nn.Module forward cannot.

A block normally does not add the residual itself. It gives the residual to the next RMSNorm kernel, which adds it and normalizes in one pass (_norm, {{cite deepinfer/model_executor/models/vision_encoder/vit.py:54-58}}). Every recomputing_every_layer-th block and the last block add it themselves (line 164) ({{cite deepinfer/model_executor/models/vision_encoder/vit.py:187-190}}). The HF loader sets recomputing_every_layer = 2 ({{cite deepinfer/hugging_face/config.py:221-224}}). The comment says the BF16 add order changes the result bit by bit, so these points are fixed.

VisionTransformer.forward

  1. Lines 196-198: the RoPE table holds cos and sin for positions 0 to 4095, 16 frequencies each (1024 / 16 / 2 = 32 dims, step 2).
  2. Line 203: each patch has (row, column). The gather gives [n, 64] in the order cos_row, cos_col, sin_row, sin_col. So half of each 64-wide head encodes the row and half the column.
  3. Lines 220-221: the input must be [n, 3, 14, 14].
  4. Lines 227-230: 32 blocks, then the final RMSNorm. The output is [n, 1024].

VisionLanguageInstructTuner.forward

Pad the raw RGB bytes from the worker into image patches (centre pad + normalize), encode them, and merge them into input_embeds. This runs in the forward section: no filtering and no CUDA synchronization.
  1. Lines 118-129: rgb_pad_to_patches reads each image's HWC uint8 bytes, centres the image in its patch grid, fills the border with the pad colour, normalizes with (x / 255 − mean) / std, and writes bf16 [total_patches, 3, 14, 14] ({{cite deepinfer/model_executor/layers/tilelang_ops/image_embed_ops.py:55-78}}; formula in the reference code, {{cite deepinfer/model_executor/layers/tilelang_ops/image_embed_ops.py:440-452}}).
  2. Lines 130-138: _encode_images runs the ViT, batch_downsample and the projector ({{cite deepinfer/model_executor/models/vision_encoder/vl_aligner.py:61-77}}).
  3. Line 139: replace_input_embeds gets mm_token_type in place of ids. The i-th row of type IMAGE gets the i-th image vector. Rows of type IMAGE_NEW_LINE, IMAGE_START and IMAGE_END get the learned vectors image_newline, image_start and image_end ({{cite deepinfer/model_executor/models/vision_encoder/vl_aligner.py:34-45}}, {{cite deepinfer/model_executor/layers/tilelang_ops/image_embed_ops.py:19-40}}).

MlpProjector

Line 14 accepts only downsample_mlp_gelu. The first layer takes input_dim × r × r values, the width after batch_downsample joins an r × r block of patch vectors (line 16 comment). The HF loader sets input_dim to the ViT width, hidden_size to the LLM hidden size, and depth = 2 ({{cite deepinfer/hugging_face/config.py:225-233}}). With depth 2 the loop on line 18 does nothing, so the result is Linear(1024·r², H) → GELU → Linear(H, H).

The MLP width: int(1024 × 2.7) = 2764, rounded up to a multiple of 128 gives 2816 ({{cite deepinfer/model_executor/models/vision_encoder/vit.py:129}}).

The downsample pads the patch grid to a multiple of r with zeros: 35 × 46 → 36 × 48, which gives 12 × 16 = 192 blocks ({{cite deepinfer/model_executor/layers/tilelang_ops/image_embed_ops.py:513-515}}, reference code {{cite deepinfer/model_executor/layers/tilelang_ops/image_embed_ops.py:573-580}}).
  • With a bias (QKV and the attention output projection), the code uses torch.addmm. The patch embedding does not use _linear; it calls F.linear ({{cite deepinfer/model_executor/models/vision_encoder/vit.py:76}}).
  • Without a bias (the two SwiGLU linears), on SM100 GPUs or Ascend, with BF16 inputs, it uses deep_gemm.bf16_gemm_nt. The output row stride is padded to 16 bytes.
  • Else it uses deep_gemm.cublaslt_gemm_nt.

The cfg.vision keys other than recomputing_every_layer do nothing: the structure is fixed by the constants ({{cite deepinfer/model_executor/models/vision_encoder/vit.py:171-175}}). The processor reads patch_size from config.json ({{cite deepinfer/hugging_face/processor.py:28}}), but the tuner uses the ViT constant ({{cite deepinfer/model_executor/models/vision_encoder/vl_aligner.py:28-29}}). The code does not check that the two values agree.

tests/models/test_ve_batch_invariant.py runs only the image encoding. For each image size it compares the vectors of an image alone with the vectors of the same image in a batch of equal images and in a batch of mixed sizes. It requires torch.equal, so bit-identical results ({{cite tests/models/test_ve_batch_invariant.py:1-13}}). The fixed residual points of Block serve this goal.

These files read no environment variable. The platform (accelerator_kind, is_sm_major_10) picks the GEMM ({{cite deepinfer/model_executor/models/vision_encoder/vit.py:42}}).

How many transformer blocks does the ViT have, and where does this number come from?

32, from the constant DEPTH in vit.py. The config does not change it ({{cite deepinfer/model_executor/models/vision_encoder/vit.py:29}}, {{cite deepinfer/model_executor/models/vision_encoder/vit.py:174}}).

 Can a patch of image 1 attend to a patch of image 2 in the same batch?

No. The attention gets cu_seqlens with the patch range of each image, so each image is its own sequence ({{cite deepinfer/model_executor/models/vision_encoder/vit.py:107-117}}).

 An image takes 206 prompt positions but only 192 image vectors. Which vectors fill the other 14 rows?

The learned vectors image_start (1 row), image_end (1 row) and image_newline (12 rows), chosen by mm_token_type ({{cite deepinfer/model_executor/models/vision_encoder/vl_aligner.py:34-45}}, {{cite deepinfer/model_executor/models/vision_encoder/vl_aligner.py:86-93}}).

 With r = 3, what is the input width of the first projector layer, and why?

1024 × 3 × 3 = 9216. batch_downsample in mode downsample_mlp_gelu joins the 9 patch vectors of each 3 × 3 block along the channel axis ({{cite deepinfer/model_executor/layers/tilelang_ops/image_embed_ops.py:537-541}}), and the first linear layer takes input_dim × r × r ({{cite deepinfer/model_executor/models/vision_encoder/mlp_projector.py:17}}).
