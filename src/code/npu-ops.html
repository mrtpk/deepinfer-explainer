From then on, from-imports of deep_select.interface.topk and flash_attn.cute.interface._flash_attn_fwd get NPU versions, loaded lazily. The package is marked as temporary. ---

Purpose

npu_ops gives Ascend processes their own version of two {{term vendor-library}} functions, without a change to the files that import them.

Filesdeepinfer/npu_ops/__init__.py (12 lines, the patch map), patch_imports.py (142 lines, the hook), deep_select.py (26 lines), vit_attn.py (31 lines).
Main functionspatch_imports ({{cite deepinfer/npu_ops/patch_imports.py:96}}), _hooked_import ({{cite deepinfer/npu_ops/patch_imports.py:55}}), class Lazy ({{cite deepinfer/npu_ops/patch_imports.py:33}}).
Runs inOnly processes with a PlatformNPU. The package runs once, when the platform is made. After that, the hook runs on every import statement in the process, but it acts only on from … import … statements.
Called byPlatformNPU.__init__, with import deepinfer.npu_ops and the note TODO(NPU): Intended to be removed. ({{cite deepinfer/platform.py:140-141}}). Nothing else imports it.
Callsbuiltins.__import__, importlib.import_module, torch.topk, the vendor deep_select.interface.topk, and torch_npu.npu_fusion_attention.
Not in this folderThe torch.cuda → torch.npu mapping (that is torch_npu.contrib.transfer_to_npu, {{cite deepinfer/platform.py:120-121}}), and the TileLang kernels for Ascend (tilelang_ops/asc/).

The page {{link concepts/hardware-platforms}} introduces the hook in its deep dive "The npu_ops import hook in detail". This page gives the full map, the call sites and the risks.

Where it sits

Who calls it, and who is affected

  • Installer. Only PlatformNPU.__init__ ({{cite deepinfer/platform.py:140-141}}). On NVIDIA nothing imports the package.
  • Importers of deep_select.interface.topk: the sampler ({{cite deepinfer/model_executor/layers/sampler.py:12}}), the sampler helpers ({{cite deepinfer/model_executor/layers/sampler_utils.py:4}}), and the sparse-attention indexer ({{cite deepinfer/model_executor/models/v4_modules/index_attn.py:12}}).
  • Importer of flash_attn.cute.interface._flash_attn_fwd: the vision encoder ({{cite deepinfer/model_executor/models/vision_encoder/vit.py:13}}).

What it calls

  • The original builtins.__import__, saved before the swap ({{cite deepinfer/npu_ops/patch_imports.py:12}}, {{cite deepinfer/npu_ops/patch_imports.py:141-142}}).
  • importlib.import_module, when a Lazy wrapper is used the first time ({{cite deepinfer/npu_ops/patch_imports.py:39-43}}).

The patch map

The keys are the source modules (where the replacement lives). The values say which name in which target module to replace. So from deep_select.interface import topk gets deepinfer.npu_ops.deep_select.topk.

patch_imports

  1. Lines 114-116: a second call raises RuntimeError. Python caches modules, so import deepinfer.npu_ops runs this only once anyway.
  2. Line 118: a side effect. It adds a process-wide filter that hides the "pkg_resources is deprecated" DeprecationWarning.
  3. Lines 123-130: a None key maps each target to a function with the suffix _ref in the same module. The map in this release does not use this form.
  4. Lines 133-135: the normal form. _add raises ValueError for a target that occurs twice ({{cite deepinfer/npu_ops/patch_imports.py:18-19}}).
  5. Lines 137-138: the list of patches goes out as an ImportWarning. Python hides ImportWarning by default, so you see it only with -W default or a similar option.
  6. Lines 140-142: store the map, save the current __import__, and install the hook. The hook stays for the life of the process.

_hooked_import

Handle only from name import a, b (not *). fromlist can be None. Get the original target module. Imports inside it are still patched. When src itself imports back the matching target, give it the original object.
  1. Lines 63-64: a relative import or a plain import X goes to the original import.
  2. Lines 66-69: if the target module is not in the map, or no patched name is in the list, the original import runs too.
  3. Line 71: the caller is the module that runs the statement, from its __name__.
  4. Lines 82-91: for each patched name, a caller inside the source module gets the original object (so npu_ops/deep_select.py can call the vendor topk). Any other caller gets a Lazy wrapper.
  5. Line 92: other names of the target module come from the real module, through the module-level __getattr__ of the new module object.

The two replacements

Only calls with return_value=False reach the vendor kernel. The indexer passes it on all three of its calls ({{cite deepinfer/model_executor/models/v4_modules/index_attn.py:216-226}}, {{cite deepinfer/model_executor/models/v4_modules/index_attn.py:361-372}}, {{cite deepinfer/model_executor/models/v4_modules/index_attn.py:494-503}}). The sampler calls do not pass it, so they use torch.topk ({{cite deepinfer/model_executor/layers/sampler.py:643}}, {{cite deepinfer/model_executor/layers/sampler_utils.py:68}}, {{cite deepinfer/model_executor/layers/sampler_utils.py:167}}). These calls pass a third positional argument (True or False), which _torch_topk takes as sorted.

Varlen attention for the ViT: not causal, full attention inside each segment. cu_seqlens_q: a host list (InputMetadataVL.vit_attn_cu_seqlens, the cumulative end of each segment).

The ViT calls _flash_attn_fwd with causal=False, the same lengths for queries and keys, and softmax_scale=None ({{cite deepinfer/model_executor/models/vision_encoder/vit.py:107-121}}). The replacement ignores those keyword arguments (**kwargs). It uses cu_seqlens_q for both lengths, no mask (sparse_mode=0) and the scale 1/sqrt(head_dim). It returns (out, None); the ViT keeps only the first value.

Deep dive

The sections below give the full detail. Open them one at a time, or use Open all deep dives at the top of the page.

The hook is installed. Three statements run in this order:

  1. index_attn.py, line 12: from deep_select.interface import topk. The name is deep_select.interface, the fromlist is ("topk",), level 0. The map has the target. The caller deepinfer.model_executor.models.v4_modules.index_attn is not the source. Result: a new module object whose topk is <Lazy import patch deep_select.interface.topk -> deepinfer.npu_ops.deep_select.topk>. Nothing is imported yet.
  2. The first call topk(p_sum, …, return_value=False). Lazy._load imports deepinfer.npu_ops.deep_select. That module runs from deep_select.interface import topk as _topk. Now the caller is the source module, so it gets the original vendor topk. Then return_value=False sends the call to it.
  3. sampler.py, line 12: the same statement gives a new Lazy wrapper (the hook does not cache module objects). Its first call loads the same, already imported, NPU module. The call topk(logprobs, k, True, indices_type=torch.int32) has no return_value. So it runs torch.topk(logprobs, k, dim=-1, sorted=True) and converts the indices to int32.

Types. _torch_topk returns (values, indices) with the dtype of the input for the values and indices_type for the indices, shape [..., k] ({{cite deepinfer/npu_ops/deep_select.py:7-17}}).

The hook changes only import statements that run after it is installed. A module that already ran from deep_select.interface import topk keeps the vendor function in its globals. The hook does not put its own module objects into sys.modules either. The docstring says, translated: "Only from-imports are intercepted; sys.modules is not faked. src loads only when the patched object is first used" ({{cite deepinfer/npu_ops/patch_imports.py:109-110}}).

In the normal start, the engine import makes the platform early. llm_engine.py imports profile_server.py, which imports utils.py, which imports timer.py, which reads PLATFORM ({{cite deepinfer/engine/llm_engine.py:35}}, {{cite deepinfer/engine/profile_server.py:33}}, {{cite deepinfer/utils.py:22}}, {{cite deepinfer/timer.py:13}}). The model modules load later, through the model registry ({{cite deepinfer/model_executor/models/__init__.py:27}}). We found this order by reading the import statements, not by a run.

On Ascend, a test or a script can import sampler.py, sampler_utils.py, index_attn.py or vit.py before it reads deepinfer.PLATFORM. Then these modules keep the vendor functions. To be safe, read deepinfer.PLATFORM first, after you set the visible devices.

import deep_select.interface as m and m.topk are also not patched: the hook handles only the from form (line 63).
  • Every import statement in the process goes through _hooked_import, also in PyTorch and other libraries. A plain import X costs one check. A from-import of a module that is not in the map costs a few checks, a small tuple and one dict lookup (lines 63-69).
  • Each patched import makes a new ModuleType object. Two importers therefore get two different Lazy objects. Both load the same source module, because importlib caches it.
  • Lazy forwards calls and attribute reads ({{cite deepinfer/npu_ops/patch_imports.py:45-49}}). Code that checks the type or the identity of the function sees a Lazy object, not a function.
  • The package has no function that removes the hook. patch_imports keeps the old import in the module global _orig_import (line 141), but no code puts it back. Only a new process starts clean.

Which two vendor names does npu_ops replace?

deep_select.interface.topk and flash_attn.cute.interface._flash_attn_fwd ({{cite deepinfer/npu_ops/__init__.py:3-12}}).

 Is the hook active in an NVIDIA process?

No. Only PlatformNPU.__init__ imports deepinfer.npu_ops ({{cite deepinfer/platform.py:140-141}}).

 On Ascend, which topk runs for the sampler's top logprobs, and which for the indexer?

The sampler call has no return_value argument, so the replacement runs torch.topk ({{cite deepinfer/model_executor/layers/sampler.py:643}}, {{cite deepinfer/npu_ops/deep_select.py:22-24}}). The indexer passes return_value=False, so it gets the vendor kernel ({{cite deepinfer/model_executor/models/v4_modules/index_attn.py:225}}).

 Why does npu_ops/deep_select.py not call itself in an endless loop, although it imports topk from the patched module?

The hook checks the caller. The importing module can be the source module deepinfer.npu_ops.deep_select or a submodule of it. Then the hook gives the original vendor object, not a Lazy wrapper ({{cite deepinfer/npu_ops/patch_imports.py:86-89}}). So _topk is the real vendor function.
