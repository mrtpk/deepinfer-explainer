Purpose

This file has one public function, prepare_sampler_inputs. It makes the {{term sampler-inputs}} of one step: the rows of the model output that the sampler reads, and the values that each sequence brings.

Where it sits

Who calls it

  • ModelRunner.prepare_sampler_inputs on the driver. It passes the sequence list without graph padding, nextn, and the YOCO mode (prefill) or OFF (decode) ({{cite deepinfer/worker/model_runner.py:238-249}}).
  • The binding with default arguments: yoco_prefill_truncation_mode=OFF, yoco_prefill_keep_tokens=0 ({{cite csrc/engine/pybind_output.cpp:133-135}}).

Who reads the result

  • The sampler gathers the selected hidden-state rows first: gather(hidden_states, selected_token_indices) ({{cite deepinfer/model_executor/layers/sampler.py:125}}, {{cite deepinfer/model_executor/layers/sampler.py:141}}). So it computes logits only for these rows.
  • The prefill EOS rows ({{cite deepinfer/model_executor/layers/sampler.py:184}}), the speculative rows ({{cite deepinfer/model_executor/layers/sampler.py:456}}) and the golden tokens ({{cite deepinfer/model_executor/layers/sampler.py:665-671}}).
  • With context parallelism, the followers get only the row indices by broadcast ({{cite deepinfer/worker/model_runner.py:250-259}}).

Walk through the main methods

Checks and sizes

  1. Line 42: the function runs without the GIL, so other Python threads can run.
  2. Lines 48-49: a prefill step has no draft tokens to verify, so nextn_token_cnt is 0 there.
  3. Line 61: all sequences must be prefill or all decode.
  4. Lines 72-77: prefill samples one row per sequence; decode samples every row (seqlen_q rows per sequence).

Allocation

Line 82: the number of parameter entries is the number of sequences in both cases. So temperatures, top_ps, top_ks, seq_seeds and sample_positions have one entry per sequence, not per row. All arrays are pinned CPU tensors.

The prefill branch

Rows of this request in the model output: keep_len when compaction is on (compact layout), else seqlen_q (full layout). The upper bound seqlen_q - 1 means keep_len >= 1: every prefill chunk sends its last token through sampling (the result of a non-final chunk is dropped later), so a chunk that is fully cut still keeps 1 placeholder token, and selected_token_indices always points at a valid model-output row. In the full layout model_output_offset equals query_token_offset - seqlen_q; under compaction prompt_logprobs is already turned off by the assert above.
  1. Lines 168-180: with YOCO compact, the model output has only the kept rows. The same clip_prefix formula as in the input builder gives their count.
  2. Lines 181-189: prompt log-probabilities. Row j of the chunk predicts prompt token q_start + j + 1.
  3. Lines 192-195: on the last chunk with first_n_token_no_eos == 1, the sampler must not pick EOS.
  4. Lines 197-199: the sampled row is the last row of the chunk; sample_positions is seqlen_k, the position of the next token.

The decode branch and the speculative fields

  1. Lines 203-205: every row of the sequence is sampled. Row j (0 to 4) gives the distribution that checks draft j + 1. The last row samples a new token after the last draft (see lines 221-225).
  2. Line 206: sample_positions is the position after the last real token.
  3. Lines 210-212: every decode sequence must have exactly nextn draft tokens, and at most 1 + nextn rows.
  4. Lines 221-225: rows 0 to seqlen_q − 2 read the draft information of the sequence's MTP slot. The last row reads slot 0, the padding slot.

The first loop also writes mtp_first_token_positions and mtp_seqlens_q for every decode sequence ({{cite csrc/engine/prepare_sample.cpp:151-154}}). With ZOS, the Worker first corrects seqlen_q on the CPU metadata from the device values, so these arrays match the real step ({{cite deepinfer/worker/worker.py:147-152}}).

Golden tokens and the copies

Golden tokens force the sampled result for testing ("golden teacher forcing", {{cite deepinfer/model_executor/layers/sampler.py:92}}). -1 means "sample normally". At the end, every array starts a non-blocking copy to the default device. The CPU does not wait for these copies.

How many temperature values does a decode step with 3 sequences of 6 rows get?

Three, one per sequence. num_sampling_positions is num_seqs in decode ({{cite csrc/engine/prepare_sample.cpp:82}}, {{cite csrc/engine/prepare_sample.cpp:84}}).

 A prefill batch has chunks with seqlen_q 60 and 200. Which output rows does the sampler read?

Rows 59 and 259: the last row of each chunk, model_output_offset + out_len − 1 ({{cite csrc/engine/prepare_sample.cpp:197}}).

 In a decode step with nextn = 5, why does the last row of each sequence read MTP slot 0?

The last row has no draft to verify: it samples a fresh token. The comment says "The final row is a fresh sample and reads padding from slot 0" ({{cite csrc/engine/prepare_sample.cpp:224-225}}). Slot 0 is the padding slot that no request uses ({{cite csrc/engine/scheduler.hpp:125-126}}). This is in the deep dive "Worked example".
