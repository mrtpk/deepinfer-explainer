Purpose

This page is a map of the whole repository. Use it to find where a part of DeepInfer lives before you read its code. Click a folder to open it. Each folder shows its number of files, its number of lines, a short description and links to the pages that explain it.

  • Total: 342 files and 63,629 text lines at commit 9bd9cf2.
  • The engine package deepinfer/ has 223 files and 47,174 lines: three quarters of all lines.
  • The C++ code in csrc/ has 33 files and 5,908 lines.
  • The kernel libraries are not in the repository. vendor/ holds six empty {{term git-submodule | git submodules}}.

Most module pages are not written yet. Their links are grey. The tree is complete, so you can use it now, and the links become live when the pages exist.

The folder tree

Counts include all files below a folder. "Lines" are text lines, as wc -l counts them. Images count as files with 0 lines.

  • DeepInfer/342 files · 63,629 lines

    The repository root. 14 files at the top level (889 lines): the build entry build.sh, setup.py, the Makefile, four requirements*.txt files, pyproject.toml, README.md, CONTRIBUTING.md, LICENSE, .gitmodules, .gitignore and .clang-format.

    • deepinfer/223 files · 47,174 linesPython

      The Python package. It holds all code that runs at inference time, except the C++ extension and the kernel libraries. Start with {{link code/entrypoints-llm}} and {{link code/llm-engine}}.

        Pages: {{link code/config}} · {{link code/environ}} · {{link code/platform}} · {{link code/sequence}} · {{link code/sampling-params}} · {{link code/shared-memory}} · {{link reference/env-vars}}

    • examples/18 files · 3,286 lines

      Scripts that run the engine. offline_inference.py is the README example ({{cite README.md:72}}). _launch.py starts one process per data-parallel rank ({{cite examples/_launch.py:26-50}}). benchmark.py drives llm.llm_engine.step() directly. Sub-folders: sweep/ (3 files, 405 lines) for throughput-latency curves, yoco/ (3 files, 1,111 lines) to compare the YOCO modes, images/ (2 JPEG test images).

      Pages: {{link tours/life-of-a-request}} · {{link concepts/yoco-swa-replay}}

    • eval/17 files · 2,003 lines

      Accuracy benchmarks AIME 2026, HLE and GPQA Diamond. Generation and scoring are separate steps ({{cite eval/README.md:3-11}}). The scripts reuse examples/_config.py to make the engine. common/ has 7 files (562 lines).

    • tests/20 files · 3,207 lines

      pytest tests. models/ (9 files, 1,172 lines) runs the whole model, for example batch invariance and the sampler. worker/ (2, 828), engine/ (3, 490), distributed/ (2, 289) and ve/ (1, 189) test single parts. Kernel tests are not here: 28 files in tilelang_ops/ hold their own test_ functions, and conftest.py there skips a test when the backend has no such kernel ({{cite deepinfer/model_executor/layers/tilelang_ops/conftest.py:100-113}}).

    • scripts/4 files · 194 lines

      Build scripts. build_vendor.sh builds the vendor libraries ({{cite scripts/build_vendor.sh:7-22}}). build.sh builds csrc/ into deepinfer/_so/<accelerator>-<arch>/ ({{cite scripts/build.sh:11-29}}). Two more scripts format the C++ code and make the .pyi stubs.

    • doc/5 files · 312 lines

      The deployment Q&A (inference_deployment_qa.md) and four images: the architecture picture and three performance charts.

      Pages: {{link reference/faq}}

    • vendor/0 files here · 6 submodulesnot checked out

      Six git submodules: DeepSelect, FlashMLA, DeepEP, DeepGEMM, DeepEP-Ascend and DeepGEMM-Ascend ({{cite .gitmodules}}). A plain clone leaves the folders empty. This site explains only how DeepInfer calls these libraries, not how they work inside. Two more kernel libraries come from pip: tilelang==0.1.15 and tile-kernels==2.1.0 ({{cite requirements.txt:16-17}}).

How the folders depend on each other

Read panel 1 from the top. The arrows go from the code that imports to the code that it imports. No arrow points up: deepinfer/ does not import examples/, eval/ or tests/. 77 files in deepinfer/ import tilelang or tile_kernels, and 18 files import a vendor library: 86 files in all, because some files import both.

Panel 2 shows ./build.sh. It installs the Python requirements, builds the vendor wheels, then builds the C++ extension ({{cite build.sh:13-25}}).

How the numbers were measured

The counts come from the checkout at commit 9bd9cf2, without the .git folder. Run these commands in the repository root to check them:

find . -path ./.git -prune -o -type f -print | wc -l          # 342 files
find deepinfer -type f | wc -l                                # 223 files
find deepinfer -type f -print0 | xargs -0 grep -Il "" | tr '\n' '\0' | xargs -0 cat | wc -l   # 47174 text lines

The import counts come from grep -rlE "^\s*(from|import) (tilelang|tile_kernels)" deepinfer and the same search for deep_ep, deep_gemm, flash_mla and deep_select.
