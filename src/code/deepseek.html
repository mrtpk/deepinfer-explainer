Purpose

deepseek.py builds the whole language model from the loaded weights and runs its forward: embedding, N decoder layers, final mHC mix and norm. The sampler call and the weight loading are here too.

Filedeepinfer/model_executor/models/deepseek.py, 525 lines of Python. No "Derived from vLLM" header.
Main classesDeepseekModel ({{cite deepinfer/model_executor/models/deepseek.py:59}}) and DeepseekForCausalLM ({{cite deepinfer/model_executor/models/deepseek.py:251}}). The registered class DeepseekVLForCausalLM is a subclass in deepseek_vl.py.
Runs inEvery worker process: the driver and each context-parallel follower. The forward launches device kernels on the current CUDA stream; in decode it usually runs inside a CUDA graph.
Called bymodel_loader.get_model (load), ModelRunner (forward and sample), CudaGraphRunner (capture).
CallsDeepseekDecoderLayer, HCHead / mhc_pre_apply_mix, DFlash, EngramRuntime, Sampler, eplb, userbuffer, the HF loading functions.
Not in this fileThe math of attention, MoE and mHC (in v4_modules/), the layer body (decoder_layer.py), the image path (deepseek_vl.py), the KV cache (worker/cache_engine.py).

Where it sits

Who calls it

  • Loading. get_model looks up the class in the registry and calls model_class.load_model(...) ({{cite deepinfer/model_executor/model_loader.py:65-79}}). The class is DeepseekVLForCausalLM ({{cite deepinfer/model_executor/models/__init__.py:15-17}}). Its load_model reads the image processor config and then calls this file's load_model ({{cite deepinfer/model_executor/models/deepseek_vl.py:237-245}}).
  • Forward. ModelRunner calls self.model(kv_caches=..., input_metadata=...), or replays a CUDA graph ({{cite deepinfer/worker/model_runner.py:326-329}}). The graph runner calls the model in the same way at capture time ({{cite deepinfer/worker/cuda_graph_runner.py:66}}).
  • Sampling. ModelRunner calls self.model.sample(...) ({{cite deepinfer/worker/model_runner.py:361-365}}).
  • Output buffers. The CUDA graph runner calls allocate_output(max_batch_size) ({{cite deepinfer/worker/cuda_graph_runner.py:96}}).

What it calls

  • Layers. One DeepseekDecoderLayer per main layer ({{cite deepinfer/model_executor/models/deepseek.py:92-103}}).
  • Topology. build_shared_layer_topology for cross-layer sharing ({{cite deepinfer/model_executor/models/deepseek.py:268-269}}).
  • Draft head. DFlash from mtp/dflash.py ({{cite deepinfer/model_executor/models/deepseek.py:300-306}}).
  • Engram. NgramHashMapping, EngramRuntime and the kernel tile_kernels.engram.engram_hash ({{cite deepinfer/model_executor/models/deepseek.py:83-90}}, {{cite deepinfer/model_executor/models/deepseek.py:180-188}}).
  • Sampler. Sampler(cfg.vocab_size) ({{cite deepinfer/model_executor/models/deepseek.py:296}}).
  • Loading. finalize_model_config, build_model_on_meta, load_hf_checkpoint and the HF coverage helpers ({{cite deepinfer/model_executor/models/deepseek.py:457-510}}).

Walk through the main methods

DeepseekForCausalLM.__init__: from containers to runtime

Shared topology (share-kv / share-index): built once at model level and passed explicitly to every layer. The layer map is normalized over all layers (main + NextN, that is, all modules except emb / lm_head). Remove emb and lm_head. NOTE: the number of MTP layers is decoupled from the number of predictions.
  1. Line 268: the container list has N + 2 + nextn modules. Without the embedding and the lm head, N + nextn layers remain.
  2. Line 276: load_nextn is DEEPINFER_USE_NEXTN_DECODE (default 5). It decides if DFlash is built (line 300).
  3. Line 277: the main head is module N + 1. Lines 280-286 give the inner model modules 0 … N: the embedding and the N blocks.
  4. Lines 290-294: the lm head reuses the HF head weight. It is not called in the forward.
  5. Lines 300-303: DFlash gets the embedding and the lm head of the main model.

The constructor ends with EPLB for all MoE layers (lines 310-317), torch.cuda.empty_cache() and allocate_userbuffer() (lines 320-321).

DeepseekModel.__init__

  1. Line 80: the embedding comes from module 0, a MultimodalEmbedding container.
  2. Lines 92-103: one DeepseekDecoderLayer per block. layer_idx runs from 0; the target layers of DFlash get a dflash_input_index.
  3. Line 107: HCHead exists only when hc_shifted is off.
  4. Line 110: output_norm is the norm of the HF GPTHead.
  5. Line 114: EngramRuntime gets the Engram modules of the Engram layers.

DeepseekModel.forward, part 1: before the loop

Runtime values held across layers (shared_hidden / pre_rope_kv / topk): pass the same reference layer by layer; each layer writes in place. DFlash target-layer features, and metadata with the same row layout (it can switch to compact at the YOCO compaction boundary). (assert message) dflash_cfg.dspark_target_layer_ids does not match the MTP head type.

The VL class passes hidden_states in every prefill, also a text-only one ({{cite deepinfer/model_executor/models/deepseek_vl.py:232-233}}). So with the registered VL class, line 162 runs only in decode. With context parallelism, line 170 reorders the tokens of a prefill into the mirror-CP layout. Lines 180-188 hash the n-grams of the batch once for all Engram layers.

DeepseekModel.forward, part 2: the loop and the end

  1. Lines 209-218: each layer gets its own KV cache view kv_caches[i], the metadata, the residual of the previous layer and the shared runtime.
  2. Line 223: DFlash writes its main cache from the features of the target layers. Translated comment (lines 221-222): "The target-layer features are consumed only here: write the DFlash main cache. In decode it is captured together with the main model's CUDA graph, which saves the CPU launch cost of each kernel. The padding rows of a CUDA graph land in state 0 of the placeholder, the dummy slot that the BlockManager never allocates."
  3. Lines 225-238: the last mHC post mix, then one mix of the hc_mult copies (shifted) or HCHead (not shifted).
  4. Line 239: the final RMSNorm.
  5. Lines 241-244: prefill with CP: all-gather and restore the token order.

The YOCO block in lines 191-207 is on {{link concepts/model-map}} (Step 3) and {{link concepts/yoco-swa-replay}}.

sample

The sampler gets the DFlash module and the lm head weight as embedding. It computes logits only for the rows that it samples. Then EPLB counts the step. The load-balance ratio is read later, in a post function (lines 406-409).

load_model

  1. Line 457: finalize_model_config adds parallel and runtime fields, for example the expert layout ({{cite deepinfer/model_executor/model_loader.py:109-125}}).
  2. Lines 459-460: one log line with the main KV format: "FP4" or "MXFP8".
  3. Lines 466-469: check the HF files, then build all containers on the meta device (no memory).
  4. Lines 474-498: give each parameter real memory: on the device, or on the CPU for Engram tables. Tied parameters share storage, "so MTP never allocates another vocabulary matrix" (lines 483-485). With skip_load, dummy weights are made.
  5. Lines 502-510: Engram tables are pre-allocated; then load_hf_checkpoint fills all weights.
  6. Lines 513-519: cls.from_model_cfg builds the runtime model and logs the memory before and after.

Take a made-up config with N = 8 main layers and num_nextn_predict_layers = 1. V41Builder makes 11 modules ({{cite deepinfer/model_executor/models/v4_modules/builder.py:105-125}}):

Index in model.module.moduleModuleUsed by

1 … 8MoeDecoderBlockHCDeepseekDecoderLayer 0 … 7 (lines 92-103)

Line 268 gives num_total_layers = 11 − 2 = 9: the 8 main layers and 1 draft layer. The sharing maps cover these 9 layers. num_moe_layers = 8 + the MoE layers of DFlash (line 310). The KV cache list has one entry per runtime layer, so the forward reads kv_caches[0] … kv_caches[7].

N = 8 and one draft layer are example values. The real values are in the checkpoint's config.json, not in the repo.
  • Every worker process builds its own model: the driver and each context-parallel follower. Followers get their inputs by broadcast (see {{link code/llm-engine}}, deep dive "Processes and threads").
  • The forward must not synchronize the CPU with the device: ModelRunner runs it inside forbid_cuda_sync() ({{cite deepinfer/worker/model_runner.py:320-329}}).
  • In decode, the graph runner captures this forward, and later replays it ({{cite deepinfer/worker/cuda_graph_runner.py:55-66}}). The DFlash cache update at line 223 is captured too (comment on line 221).
  • load_model runs once at start-up, under the default dtype of the model config and torch.device("cuda") ({{cite deepinfer/model_executor/model_loader.py:69-74}}).
  • KV cache. The forward does not know the cache layout. It passes kv_caches[i] to layer i. The cache engine decides which layers share a view ({{link concepts/cross-layer-kv-sharing}}).
  • Input metadata. The forward reads is_prompt, input_ids, ngram_token_ids and the CP fields. With YOCO compaction it swaps the metadata object at the boundary (lines 191-207).
  • EPLB. _init_eplb groups the MoE layers by (logical, physical, routed, extra experts, EP group, weight shapes and dtypes) and makes one ExpertLoadBalancer per group (lines 331-364). sample() calls expert_lb.step(is_prompt) each step. See {{link concepts/eplb}}.
  • Userbuffer. allocate_userbuffer sizes the CP all-gather buffer as the maximum over three needs: hidden × 2 bytes per token for the sampler, hc_mult × hidden × 2 with YOCO compact mode, and the per-layer need of the attention ({{cite deepinfer/model_executor/models/deepseek.py:415-436}}).
  • Sampler and DFlash. sample() hands the DFlash module to the sampler, which runs the drafts. See {{link concepts/speculative-decoding}}.

What does DeepseekForCausalLM.forward return, and where are the logits computed?

A CausalLMForwardOutput with bf16 hidden states [T, hidden] ({{cite deepinfer/model_executor/models/deepseek.py:246-248}}). The sampler computes logits in sample(), with lm_head.weight ({{cite deepinfer/model_executor/models/deepseek.py:392-400}}).

 You set DEEPINFER_USE_NEXTN_DECODE=0. Name two things that change in this file.

load_nextn is 0, so MTP_module is None and num_mtp_moe_layers is 0 ({{cite deepinfer/model_executor/models/deepseek.py:300-306}}). EPLB then covers only the N main MoE layers (line 310). The inner model also gets no DFlash target layers, so dflash_input is not allocated ({{cite deepinfer/model_executor/models/deepseek.py:72}}).

 Why does DeepseekModel.__init__ sometimes not make an HCHead?

With hc_shifted, each sub-layer applies the mix of the sub-layer before it, and the last mix is applied at the end of the model with mhc_pre_apply_mix ({{cite deepinfer/model_executor/models/deepseek.py:229-230}}). So no head is needed ({{cite deepinfer/model_executor/models/deepseek.py:107}}). The HF loader turns hc_shifted on by default ({{cite deepinfer/hugging_face/config.py:295}}).

 A config has 8 main layers and 1 draft layer. How many modules does the container list have, which index is the main head, and what is num_total_layers?

11 modules: embedding, 8 blocks, main head, 1 DFlash head. The main head is index N + 1 = 9 ({{cite deepinfer/model_executor/models/deepseek.py:277}}). num_total_layers = 11 − 2 = 9 ({{cite deepinfer/model_executor/models/deepseek.py:268}}). This is the deep dive "Worked example: the module list".
