Purpose

environ.py is the one place where DeepInfer reads its DEEPINFER_* {{term environment-variable | environment variables}}: it parses each one on first use and keeps the result.

Filedeepinfer/environ.py, 221 lines. No other deepinfer import, so any module can import it early.
Main classenvs ({{cite deepinfer/environ.py:97}}), with 59 class attributes in 16 groups. The descriptor class is EnvVar ({{cite deepinfer/environ.py:31}}).
Runs inEvery process, on the first read of each attribute. A spawned process reads its own copy of the environment again.
Called byAlmost every module, as envs.DEEPINFER_X. The package exports envs at the top level ({{cite deepinfer/__init__.py:6}}).
Callsos.getenv only.
Not in this fileFive DEEPINFER_* names that other code reads with os.getenv or C++ getenv, and the NCCL_* and visible-device variables. The page {{link reference/env-vars}} lists them all.

This page reads the mechanism. For the effect and the default of each variable, use {{link reference/env-vars}}.

Where it sits

Who calls it

  • Readers. Code reads a value as an attribute, for example envs.DEEPINFER_USE_NEXTN_DECODE in config.py ({{cite deepinfer/config.py:13}}).
  • rearm. EngineArgs.__post_init__ sets two variables with os.environ.setdefault and then calls environ.rearm for each ({{cite deepinfer/engine/arg_utils.py:51-60}}).
  • rearm_all. The test fixture in tests/conftest.py restores os.environ after each test and re-arms every descriptor ({{cite tests/conftest.py:21-26}}).
  • Writers. Three places assign a value directly to the class: the memory profile ({{cite deepinfer/worker/model_runner.py:510-512}}), the userbuffer setup ({{cite deepinfer/model_executor/parallel_utils/userbuffer.py:90}}) and the benchmark script ({{cite examples/benchmark.py:148}}).

What it calls

Only os.getenv(name), inside EnvVar.__get__ ({{cite deepinfer/environ.py:50}}). It does not import torch.

Walk through the main methods

EnvVar.__get__: parse once, then step aside

  1. Lines 40-42: when Python makes the class envs, each descriptor learns its own name and registers itself in _descriptors.
  2. Lines 45-48: a lock makes the first read safe with threads. If the class dict already holds a plain value, the descriptor returns it. (Normally Python does not call __get__ at all then, see line 56.)
  3. Line 50: parse the text from os.getenv.
  4. Lines 52-55: on a parse error, raise the same exception type with the variable name in front.
  5. Line 56: setattr(owner, name, value) replaces the descriptor in the class with the value. Later reads are plain attribute reads.

The page {{link reference/env-vars}} explains the descriptor protocol and each parse rule, with examples ("How DeepInfer reads a variable"). This page gives only the short version.

The groups and the derived variables

The largest number of speculative tokens; default 5. Set it to 0 explicitly to turn speculative decoding off.

Comments such as # -- MTP -- split the class into 16 groups. Three variables depend on others when they are read:

  • DEEPINFER_MAX_BACKTRACKING_TOKENS is at least DEEPINFER_USE_NEXTN_DECODE + 1 (line 132).
  • DEEPINFER_DFLASH_CONFIDENCE_HEAD_TEMPERATURE accepts one float or a list with exactly nextn items (lines 134-143).
  • DEEPINFER_ENGRAM_FORCE_GPU_STORAGE is always on when DEEPINFER_ACCELERATOR is "ascend" (line 147).

rearm: read the environment again

rearm puts the descriptor back into the class. The next read calls __get__ and parses the current os.environ. EngineArgs needs this: an import before LLM(...) may already have read DEEPINFER_ZERO_OVERHEAD_SCHEDULING as off.

Deep dive

  1. Cached after the first read. A change of os.environ after the first read has no effect until rearm ({{cite deepinfer/environ.py:56}}).
  2. Copied at import time. A default argument or a module constant keeps the value from the import. Example: SchedulerConfig ({{cite deepinfer/config.py:193-194}}). rearm does not help here. The {{link reference/env-vars#import-time-table | import-time table}} lists six such variables.
  3. Overwritten by code. A direct assignment such as envs.DEEPINFER_FORCE_IMBALANCE_RATIO = 0.0 replaces the descriptor with a plain value ({{cite deepinfer/worker/model_runner.py:512}}). Your exported value never takes effect after start-up.
  4. Another process. A spawned CP follower has its own envs class. It reads the environment that it got at its start, not later changes in the parent.

Worked example. A script runs import deepinfer, then print(envs.DEEPINFER_ZERO_OVERHEAD_SCHEDULING) (prints False, the default), then LLM(...). __post_init__ sets the variable to "1" and calls rearm. The next read returns True, so the engine runs with ZOS. Without line 55 of arg_utils.py, the engine would keep False.

You export DEEPINFER_ENFORCE_EAGER=off. Is eager mode on or off?

On. Only "0", "", "false" and "False" parse as False ({{cite deepinfer/environ.py:12-13}}).

 What does environ.rearm("DEEPINFER_USE_MULTIMODAL_POOL") do, and why does EngineArgs call it?

It puts the descriptor back into envs ({{cite deepinfer/environ.py:213-215}}), so the next read parses os.environ again. EngineArgs has just set the variable with setdefault, and an earlier read could have cached the old value ({{cite deepinfer/engine/arg_utils.py:56-60}}).

 In a running engine, you call os.environ["DEEPINFER_FORCE_IMBALANCE_RATIO"] = "2" and then environ.rearm("DEEPINFER_FORCE_IMBALANCE_RATIO"). Does the next read return 2.0? Why can it be different without the rearm?

Yes, after rearm the next read parses "2" and returns 2.0. Without it, the read returns 0.0: the memory profile assigned envs.DEEPINFER_FORCE_IMBALANCE_RATIO = 0.0, which put a plain value in the class ({{cite deepinfer/worker/model_runner.py:510-512}}). See the deep dive "Four ways a value can stay old".
