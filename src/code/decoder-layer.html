Purpose

decoder_layer.py joins the parts of one {{term decoder-layer}}: it calls the {{term mhc}} code, the attention, and the MoE in the right order, and it adds three optional hooks.

Filedeepinfer/model_executor/models/decoder_layer.py, 239 lines of Python. No "Derived from vLLM" header. Some comments are in Chinese.
Main classesDeepseekDecoderLayer ({{cite deepinfer/model_executor/models/decoder_layer.py:48}}) and DFlashDecoderLayer ({{cite deepinfer/model_executor/models/decoder_layer.py:178}}). Both inherit from HCLayerMixin.
Runs inEvery worker process. The forward launches device kernels on the current stream; in decode it runs inside the CUDA graph of the model.
Called byDeepseekModel (build and forward loop), DFlash (draft layers).
CallsHCLayerMixin (mHC), V4Attention / DFlashAttention, DeepseekMoE, Engram, YOCO helpers, dflash_input_store, the timers.
Not in this fileThe mHC math (v4_modules/hc.py), attention (attn.py), MoE (mlp.py), the weights (hc_blocks.py), the loop over layers (deepseek.py).

Where it sits

Who calls it

  • Build. DeepseekModel.__init__ makes one DeepseekDecoderLayer per main block, with layer_idx 0 … N−1 and an optional DFlash index ({{cite deepinfer/model_executor/models/deepseek.py:92-103}}). DFlash makes the DFlashDecoderLayer objects ({{cite deepinfer/model_executor/models/mtp/dflash.py:128-132}}).
  • Forward. The loop of DeepseekModel.forward calls each layer and keeps the returned residual for the next layer ({{cite deepinfer/model_executor/models/deepseek.py:209-218}}).
  • Drafts. DFlash.forward_drafts calls forward_drafts on each draft layer ({{cite deepinfer/model_executor/models/mtp/dflash.py:249-256}}).

What it calls

  • mHC. attn_norm_forward and ffn_norm_forward from HCLayerMixin ({{link code/v4-hc}}).
  • Attention. V4Attention ({{cite deepinfer/model_executor/models/decoder_layer.py:85}}) or DFlashAttention ({{cite deepinfer/model_executor/models/decoder_layer.py:190-195}}). See {{link code/v4-attn}}.
  • MoE. DeepseekMoE ({{cite deepinfer/model_executor/models/decoder_layer.py:40}}). See {{link code/v4-mlp}}.
  • Hooks. Engram ({{cite deepinfer/model_executor/models/decoder_layer.py:83}}), compact_yoco_boundary ({{cite deepinfer/model_executor/models/decoder_layer.py:137-139}}), dflash_input_store ({{cite deepinfer/model_executor/models/decoder_layer.py:95}}).

Walk through the main methods

_build_mlp_and_layernorms

Every block of this release is a MoeDecoderBlockHC, so every layer has a DeepseekMoE. For the main model, the type check in __init__ (line 57) fails first, with an AssertionError, so line 42 cannot run there. Only a DFlashDecoderLayer can reach the NotImplementedError. The two norms come from the block's norm1 and norm2. The loader sets fp8_attn and fp8_mlp for the released format ({{cite deepinfer/hugging_face/config.py:304-305}}), so both norms give FP8 output.

DeepseekDecoderLayer.__init__

(assert message) DFlash attention-input feature extraction supports only models with HC enabled. The MLP timer scales with the number of layers that actually run; with MTP off, or in a DFlash prefill, only the MLPs of the main model run. The shared hidden is captured and passed on only when a consumer exists (yoco_shared_hidden_required decides). Group the layers with the same structure; get_enable_timer_layer uses the groups to select the timer sample layers.
  1. Lines 57-58: the block must be a MoeDecoderBlockHC. HCLayerMixin.__init__ copies the mHC weights.
  2. Lines 64-67: a DFlash target layer needs mHC, and the DFlash config must take the attention input (dspark_target_attn_input, default True, {{cite deepinfer/hugging_face/config.py:183}}).
  3. Lines 70-73: timer scales. DEEPINFER_USE_NEXTN_DECODE (default 5) adds the draft layers to the MLP count.
  4. Line 76: every YOCO consumer layer gets the capture flag, but only when some consumer layer reads the shared hidden. At run time only the first of them captures it, because line 146 also checks that no shared hidden exists yet.
  5. Lines 80-83: an Engram layer gets an Engram module. The comment on line 82 says "HACK: currently only support hc_enabled".
  6. Lines 85 and 87: the attention, the MoE and the two norms.
  7. Line 90: register the layer in a timer group. The key is the module structure plus the attention config ({{cite deepinfer/model_executor/models/v4_modules/utils.py:123-127}}).

forward, part 1: setup

Engram is the trunk intervention hook after the hc post (see HCLayerMixin.attn_norm_forward).
  1. Line 107: the loop wraps the hidden states in Movable ({{cite deepinfer/model_executor/models/deepseek.py:209}}). move() takes the tensor and leaves the wrapper empty, so the caller no longer holds a reference ({{cite deepinfer/model_executor/utils.py:66-81}}).
  2. Lines 108-109: a layer called alone gets an empty CrossLayerRuntime.
  3. Lines 111-118: an Engram layer makes a closure. attn_norm_forward calls it on the trunk [T, hc_mult, H] after the post mix ({{cite deepinfer/model_executor/models/v4_modules/hc.py:225-226}}).
  4. Lines 120-133: the attention timer records in one sample layer per group: the second-last layer in prefill, the second layer in decode ({{cite deepinfer/model_executor/models/v4_modules/utils.py:139-143}}). The scale is the size of the group.

forward, part 2: the YOCO boundary and the attention input

(assert message) A YOCO layer cannot be an Engram layer. First consumer layer: the attn-norm bf16 hidden is the shared hidden. Write it in place into the cross-layer runtime, for this layer and the later consumer layers (held across layers). Under YOCO compaction this is the compact version (the boundary code above has swapped in the compact copy); the full version goes through consumer_full_hidden. TODO(YOCO): remove this clone (at the moment it prevents an in-place clear inside attention).
  1. Line 134: this block runs once per forward: in the first consumer layer of a prefill with DEEPINFER_YOCO_PREFILL_TRUNCATION_MODE=compact. The model sets consumer_full_metadata there ({{cite deepinfer/model_executor/models/deepseek.py:192-198}}).
  2. Lines 137-141: make compact copies of the hidden states and the lazy data. Then run attn_norm_forward on the full rows and keep only its BF16 output as consumer_full_hidden.
  3. Line 143: the mHC post of the previous MoE, the attention pre mix and the attention norm. See {{link code/v4-hc}}.
  4. Lines 144-145: a DFlash target layer stores the mean of its trunk streams in dflash_input. This runs after the attention mHC pre and norm (line 143) and before attention. residual.residual is the trunk after the post (and after the Engram hook), [1, T, hc_mult, H].
  5. Lines 146-152: the first YOCO consumer keeps a clone of the BF16 attention input as the shared hidden.

_store_dflash_input

n_embed is the last dimension of the trunk, H. The layer with DFlash index j writes into columns j·H … (j+1)·H − 1 of dflash_input [T, H × number of targets]. dflash_input_store computes the mean over the hc_mult streams and copies the result into that slice ({{cite deepinfer/model_executor/layers/tilelang_ops/dflash.py:134-143}}). The slice is a strided view, so the row stride must be a multiple of 4 ({{cite deepinfer/model_executor/layers/tilelang_ops/dflash.py:150}}).

forward, part 3: attention, then the MoE

  1. Line 153: wrap both inputs in Movable. V4Attention.forward moves them out at once ({{cite deepinfer/model_executor/models/v4_modules/attn.py:760}}), so attention can free them early.
  2. Line 154: only V4Attention gets the cross-layer runtime. In this class self_attn is always a V4Attention (line 85), so the condition is always true here.
  3. Lines 155-161: attention returns BF16 [T, H] ({{cite deepinfer/model_executor/models/v4_modules/attn.py:880}}).
  4. Line 162: the mHC post of attention, the MoE pre mix and the FFN norm. With mega-MoE and FP8, the norm writes into the MoE buffer.
  5. Lines 164-168: the MLP timer records only in layer 1.
  6. Lines 169-173: the MoE. DeepseekMoE.forward picks mega-MoE or the DeepEP path ({{cite deepinfer/model_executor/models/v4_modules/mlp.py:571-572}}).
  7. Line 175: return the MoE output and the lazy residual. The MoE output is not in the trunk yet: the next layer, or the end of the model, does that post mix.

DFlashDecoderLayer

In prefill_only mode the MLP and the layer norms are not loaded; only the attention parameters for main_k are needed. The DFlash MoE can have a different structure from the main model. attn_norm_forward / ffn_norm_forward (HCLayerMixin) depend on hc_enabled. Group the layers with the same structure; get_enable_timer_layer uses the groups to select the timer sample layers.

forward_drafts runs the same four calls as the main layer, with no hooks ({{cite deepinfer/model_executor/models/decoder_layer.py:231-239}}). The page {{link code/dflash}} explains the draft model.

"3 targets" is an example. The target list dspark_target_layer_ids comes from config.json ({{cite deepinfer/hugging_face/config.py:182}}).

Take H = 3, m = 2, two target layers 5 and 9, so dflash_input is [T, 6]. Layer 9 has index j = 1 ({{cite deepinfer/model_executor/models/deepseek.py:72-73}}).

  1. After the post of the previous MoE, the trunk of one token in layer 9 is [[1, 2, 3], [3, 0, −1]].
  2. _store_dflash_input selects columns 1·3 … 2·3 − 1, that is columns 3, 4, 5.
  3. The mean of the two streams is [2, 1, 1]. It goes into columns 3 to 5 of this token's row.
  4. After the loop, DFlash.update_main_cache reads the whole dflash_input ({{cite deepinfer/model_executor/models/deepseek.py:220-223}}).

Which four calls run in every DeepseekDecoderLayer.forward?

attn_norm_forward, self_attn, ffn_norm_forward, mlp ({{cite deepinfer/model_executor/models/decoder_layer.py:143}}, {{cite deepinfer/model_executor/models/decoder_layer.py:155-162}}, {{cite deepinfer/model_executor/models/decoder_layer.py:169-173}}).

 Is the MoE output of layer i in the trunk when forward returns?

No. The layer returns the MoE output and the lazy data ({{cite deepinfer/model_executor/models/decoder_layer.py:175}}). The post mix runs at the start of layer i + 1, in mega_mhc or in hc_post ({{cite deepinfer/model_executor/models/v4_modules/hc.py:195-202}}, {{cite deepinfer/model_executor/models/v4_modules/hc.py:220-222}}), or after the last layer ({{cite deepinfer/model_executor/models/deepseek.py:226-227}}).

 What exactly does a DFlash target layer store, and when in the layer?

The mean over the hc_mult streams of the trunk at the attention input: after the post of the previous MoE and after the Engram hook, before attention ({{cite deepinfer/model_executor/models/decoder_layer.py:143-145}}, {{cite deepinfer/model_executor/layers/tilelang_ops/dflash.py:134-143}}).

 With two DFlash target layers, H = 4096 and a decode step of 192 tokens, what is the shape of dflash_input, and which columns does the second target write?

[192, 8192] ({{cite deepinfer/model_executor/models/deepseek.py:74}}, {{cite deepinfer/model_executor/models/deepseek.py:174}}). The second target has index 1, so it writes columns 4096 to 8191 ({{cite deepinfer/model_executor/models/decoder_layer.py:95}}). See the deep dive "Worked example: one token through the DFlash store".
