Purpose

mla_attn.py allocates all weights of one attention layer, with the names, shapes and dtypes that the Hugging Face checkpoint uses. It runs nothing: attn.py, compress.py and index_attn.py own the forward.

Where it sits

Who calls it

  • MoeDecoderBlockHC.__init__ makes one LoraRopeCompressFlashMHAAutoRecomp per block, with the per-layer config and the two "source" flags ({{cite deepinfer/model_executor/models/v4_modules/hc_blocks.py:100-104}}).
  • V41Builder._build_block computes the flags from the shared topology. It merges the layer's attention config over the global config first ({{cite deepinfer/model_executor/models/v4_modules/builder.py:45-74}}).
  • The runtime reads the containers: V4Attention and DFlashAttention assert the type ({{cite deepinfer/model_executor/models/v4_modules/attn.py:236}}, {{cite deepinfer/model_executor/models/v4_modules/attn.py:894}}); Compressor reads SoftmaxAPEGatedColumnParallelLora ({{cite deepinfer/model_executor/models/v4_modules/compress.py:71}}); MQA reads MQAIndexer ({{cite deepinfer/model_executor/models/v4_modules/index_attn.py:71}}).
  • The HF loader maps checkpoint names onto these attribute names ({{cite deepinfer/hugging_face/names.py:43-57}}).

What it calls

  • ReplicatedLinear: a plain nn.Linear with a use_fp8_gemm flag ({{cite deepinfer/model_executor/models/v4_modules/linear.py:8-20}}). So each weight has shape [out_features, in_features].
  • DropoutAddRMSNorm: an RMSNorm container with no forward ({{cite deepinfer/model_executor/models/v4_modules/norm.py:13-34}}).
  • build_rotary_emb: a RoPE container with no parameters, "base" or "yarn" ({{cite deepinfer/model_executor/models/v4_modules/rope.py:42-53}}).

Walk through the main methods

ColumnParallelLora: the low-rank projection

  1. Lines 44-49: A maps in_features to rank + num_lora_rope_head × rope_head_dim. For Wkv this is kv_lora_rank + 1 × qk_rope_head_dim = 512.
  2. Lines 50-59: B exists only when out_features > 0. Wkv passes 0, so it has no B.

MQAIndexer: the indexer weights and its rules

  1. Line 111: topk_tokens = cfg.index_topk.
  2. Lines 119-123: asserts. RoPE on, no q norm, RoPE size 64, sparse_stage == 2, flat k_proj only.
  3. Lines 125-130: q_B reads the query latent (q_lora_rank) and makes n_head × head_dim values. FP8 GEMM.
  4. Lines 131-136: weights_proj reads the hidden state and makes one weight per index head. BF16.
  5. Lines 137-142: k_proj reads the 512-value compressed vector and makes head_dim values. BF16.
  6. Line 148: the indexer RoPE uses compress_rope_theta.

LoraRopeCompressFlashMHAAutoRecomp.__init__, part 1: Q, KV and output

  1. Lines 170-171: compression overlap and APE raise ValueError.
  2. Lines 175-176: one KV head, always.
  3. Lines 189-190: YOCO is on when n_prefill_layer < num_hidden_layers.
  4. Lines 192-196: a q LoRA rank, interleaved RoPE, no q norm weight, no attention bias, FP8 attention.

Then the weights (lines 198-246): Wq (low-rank, FP8, with an RMSNorm over q_lora_rank), an optional weightless q_norm, the grouped output Wv, and Wkv.

Wv is one matrix [o_groups × o_lora_rank, (kv_lora_rank + R) × heads_per_group]. Line 229 stores its group layout as einsum_info. The runtime uses it as [G, ro, heads_per_group × 512] in fp8_einsum ({{cite deepinfer/model_executor/models/v4_modules/attn.py:124}}).

__init__, part 2: compressor, indexer, sinks

  1. Line 250: sparse_stage is 0 (SWA-only layer) or 2 (compressed layer).
  2. Lines 252-269: only a layer with packed heads has a compressor slot. Only a KV-source layer fills it; other layers keep None and use the source's cache.
  3. Lines 271-273: only an index-source layer with sparse_stage == 2 and an attn_index config gets an MQAIndexer.
  4. Line 277: compressed layers use compress_rope_theta; SWA-only layers use rope_theta.
  5. Line 283: v_scaling_factor = 1; the runtime asserts it.
  6. Lines 287-292: one fp32 sink value per head.

runtime_attn_sink

The runtime shares the same storage as the container. It does not copy or rescale the values, and it asserts fp32.

Does mla_attn.py define a forward method?

No. It is a parameter container: it only allocates weights ({{cite deepinfer/model_executor/models/v4_modules/__init__.py:6-9}}). attn.py owns the forward.

 Why does Wkv have no B matrix?

It is built with out_features = 0 ({{cite deepinfer/model_executor/models/v4_modules/mla_attn.py:232-235}}), and B exists only for out_features > 0 ({{cite deepinfer/model_executor/models/v4_modules/mla_attn.py:50-59}}). The 512-value output of A is the stored key and value; no up-projection is needed.

 A C1 layer is a KV source. Which compressor weights does it have?

PackedWkv.A and PackedWkv.norm, but no Gate: the gate exists only when kv_compress_ratio != 1 ({{cite deepinfer/model_executor/models/v4_modules/mla_attn.py:86-95}}). The docstring says why: the single-token softmax of C1 is always 1.

 With 64 heads and o_groups = 8, what is the input size of one group in Wv?

(kv_lora_rank + R) × (H / G) = 512 × 8 = 4,096 values ({{cite deepinfer/model_executor/models/v4_modules/mla_attn.py:227}}). The runtime views the weight as [8, ro, 4096]. (64 and 8 are example values.)
