The idea

The tour {{link tours/life-of-a-request}} starts after the engine is ready. This tour covers the part before it. The call LLM(model=...) does a lot of work. It starts processes, connects the devices and loads the weights. Then it measures the free memory, makes the {{term kv-cache}} and records {{term cuda-graph | CUDA graphs}}. Only after all that can generate() run.

The order of this work is strict. The KV cache gets the memory that the weights and a test run leave free, so it comes after them. The CUDA graphs record kernels that read the KV cache, so they come after the cache. The device settings must be in the environment before Python imports torch, so they come first of all.

The tour uses the settings of examples/offline_inference.py with its defaults: --ep 8 --cp 1 on one host with 8 devices ({{cite examples/offline_inference.py:13-15}}). So there are 8 {{term data-parallelism | data-parallel}} (DP) ranks, and each one builds a full engine with max_num_seqs=4, max_model_len=32768 and gpu_memory_utilization=0.85 ({{cite examples/offline_inference.py:45-57}}). Where the library defaults give other numbers, the deep dives say so.

An everyday comparison. Think of a restaurant before it opens. The owner picks the staff and gives each cook a station (stops 1 to 8). The cooks bring in the food and set up the kitchen (stops 9 and 10). Then the owner measures the free space in the cold room and fills it with shelves (stops 11 and 12). The cooks practise each dish one time, so that later they can repeat it fast (stop 13). The comparison stops being true in one place. Here all 8 "restaurants" (DP ranks) must open at the same time, because they share one set of experts.

We are in examples/offline_inference.py. The script reads the parallel sizes from the command line. dp_size is ep // cp, so 8 ({{cite examples/offline_inference.py:24-29}}). The last line calls launch_dp(main, dp_size) ({{cite examples/offline_inference.py:112-113}}).

Set the single-host defaults of RANK/WORLD_SIZE, then start child processes with run_dp; when dp_size is None, use all GPUs of this node. Give main_fn to each global data-parallel rank that this node owns, by RANK/WORLD_SIZE. With dp_size == 1, run main_fn(dp_size, 0) in the current process.
  1. Lines 17-18: RANK is the index of this host and WORLD_SIZE the number of hosts. The defaults are one host.
  2. Lines 35-44: with more than one DP rank, the launcher starts one process per rank of this host with the {{term spawn}} start method. Each process runs main(dp_size, dp_rank).
  3. Lines 46-48: it waits for all processes. A process with a non-zero exit code gives RuntimeError.

More than one host. run_dp starts the ranks with dp_rank // (dp_size // num_nodes) == node_rank ({{cite examples/_launch.py:39-40}}). With 16 ranks on 2 hosts, host 0 starts ranks 0-7 and host 1 starts ranks 8-15. dp_size must be a multiple of the host count (line 33).

What spawn gives. The code does not say why it uses spawn. A spawned child gets a copy of the environment of the parent but no copy of its memory. The child imports torch only after it sets the visible devices (stop 2).

Who else starts processes. The engine starts more processes later: CP followers with spawn (stop 6) and a multimodal worker with fork (stop 5). The launcher does not know about them.

The world size. world_size = dp_size * cp_size and it must be a multiple of ep_size ({{cite examples/offline_inference.py:28-29}}). With --ep 8 --cp 2 the script makes 4 DP ranks with 2 devices each.

Each DP process runs main. It first writes {{term environment-variable | environment variables}} and only then imports deepinfer. Many settings are read only once, at the first read or at import. And the visible devices must be known before torch starts CUDA.

Order. The followers start first, and then the driver Worker is built. All of them meet in init_dist (stop 8), so this order does not matter for correctness. A follower that starts late only makes the others wait.

The init method. All ranks of all DP processes meet at one TCP address. get_distributed_init_method returns tcp://MASTER_ADDR:(MASTER_PORT − 50 + engine_group_rank), with defaults localhost and 23333 ({{cite deepinfer/utils.py:222-230}}). So the example uses tcp://localhost:23283. The comment says that two independent jobs on one host must use different MASTER_PORT values.

What can go wrong

If your script imports torch or deepinfer before it sets CUDA_VISIBLE_DEVICES (or ASCEND_RT_VISIBLE_DEVICES), the setting can have no effect. Follow the order of create_llm ({{cite examples/_config.py:104-110}}).
  • KeyError: 'CUDA_VISIBLE_DEVICES'. The engine and the Worker read this variable without a default ({{cite deepinfer/engine/llm_engine.py:188}}, {{cite deepinfer/worker/base.py:127}}). Set it, also on Ascend.
  • The ranks hang in stop 8. One DP process failed or did not start, or two jobs use the same MASTER_PORT ({{cite deepinfer/utils.py:222-230}}). The others wait up to the timeout of the default group, DEEPINFER_GLOO_TIMEOUT (4 hours by default).
  • ValueError: Unsupported HF ... The checkpoint is not a DeepSeek V4.1 checkpoint in the expected format ({{cite deepinfer/hugging_face/config.py:241-262}}).
  • "No available memory for the cache blocks" or "runtime max seq len ... is larger than ...". The weights and the test batch leave too little memory. Raise gpu_memory_utilization, or lower max_model_len, max_num_seqs or max_num_batched_tokens ({{cite deepinfer/engine/llm_engine.py:441-451}}).
  • Out of memory or "illegal memory access" in stop 13. The graphs did not fit in the memory that is left. Lower gpu_memory_utilization ({{cite deepinfer/entrypoints/llm.py:50-51}}).
  • RuntimeError: unknown GPU type at the very end: the device is not SM100 and not Ascend ({{cite deep_cluster/hardware/device.py:151-156}}).
  • A NUMA warning in the log. libnuma.so.1 is missing or the binding failed. Start-up continues, but host-to-device copies can be slower ({{cite deepinfer/worker/base.py:356-357}}).

Why it matters. Start-up decides the numbers that limit every later step. These are the number of blocks, the batch sizes that have a graph, and the ranks that talk to each other. When a step does something unexpected, read the start-up log first. It shows the block count, the graph sizes and the group layout.

Why does examples/_config.py import deepinfer inside create_llm and not at the top of the file?

The visible devices must be set before torch starts CUDA (or ACL on Ascend). create_llm first calls setup_cuda_visible_devices, then imports torch and deepinfer ({{cite examples/_config.py:104-110}}). The module docstring states the rule ({{cite examples/_config.py:1-7}}).
