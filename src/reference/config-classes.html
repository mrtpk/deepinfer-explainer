Also the derived values, the checks, and the fields that nothing reads. --- The engine reads all its settings from one {{term engine-args | EngineArgs}} object, which becomes four {{term engine-configs | config objects}} at start-up.

Use this page to look up one setting. The page {{link code/config}} explains the code of deepinfer/config.py. The page {{link reference/env-vars}} lists the DEEPINFER_* {{term environment-variable | environment variables}}, which are a second, separate way to set the engine.

From keyword arguments to config objects

  1. LLM(model, **kwargs) adds its own defaults and makes an EngineArgs ({{cite deepinfer/entrypoints/llm.py:67-81}}).
  2. EngineArgs.__post_init__ uses the model path as the tokenizer path if you give no tokenizer. It also sets two environment variables if they are not set ({{cite deepinfer/engine/arg_utils.py:48-60}}).
  3. LLMEngine.from_engine_args calls create_engine_configs() ({{cite deepinfer/engine/llm_engine.py:460-469}}). That method makes the four objects in this order: ModelConfig, CacheConfig, ParallelConfig, SchedulerConfig ({{cite deepinfer/engine/arg_utils.py:62-114}}).
  4. The engine gives the same four objects to the driver Worker. It gives copies to each {{term cp-follower | CP follower}} process as spawn arguments ({{cite deepinfer/engine/llm_engine.py:377-413}}).
  5. Some fields are empty at first. Other files fill them later, during start-up (the "Set later" rows below).
ObjectMain readers
ModelConfigtokenizer loader, model loader, Worker, ModelRunner. Four of its fields are also copied into model_cfg.gpt, which the model layers read ({{cite deepinfer/config.py:82-94}}).
CacheConfigWorker (memory profile), CacheEngine, the two BlockManager objects, the statistics logger.
ParallelConfigWorker (ranks and process groups), ModelRunner, the TCP address of the {{term rendezvous}}.
SchedulerConfigThe C++ {{term scheduler}}: its constructor reads nine attributes from the Python object ({{cite csrc/engine/scheduler.hpp:94-108}}). Also ModelRunner.

LLM-only arguments. decode_sequence (default True) is not an engine setting. LLM keeps it and uses it to decode the output text ({{cite deepinfer/entrypoints/llm.py:64}}, {{cite deepinfer/entrypoints/llm.py:82}}). All other LLM keyword arguments go to EngineArgs through **kwargs. An unknown name raises TypeError from the dataclass constructor. LLM also sets TOKENIZERS_PARALLELISM=false if it is not set ({{cite deepinfer/entrypoints/llm.py:69}}).

Side effects of __post_init__. It sets DEEPINFER_ZERO_OVERHEAD_SCHEDULING to 1 for NORMAL and COMPLETION engines, and DEEPINFER_USE_MULTIMODAL_POOL to 1 except for COMPLETION. It sets each one only if the variable is not set, and then calls environ.rearm ({{cite deepinfer/engine/arg_utils.py:51-60}}, {{cite deepinfer/engine/engine_type.py:15-17}}). So ZOS is on when ModelConfig computes runtime_max_model_len.

get_vocab_size() returns model_cfg.gpt.vocab_size, a value from the checkpoint, not from the repository ({{cite deepinfer/config.py:121-122}}).

Fields copied into the model config. _load_model_cfg writes max_num_seqs, max_num_batched_tokens, runtime_max_model_len and engine_type into model_cfg.gpt ({{cite deepinfer/config.py:82-94}}). The model layers get only model_cfg.gpt, so they read these copies.

Copies for CP followers. A CP follower gets ModelConfig as a spawn argument, so Python pickles it. __getstate__ leaves out model_cfg and keeps the four copied values. __setstate__ loads config.json again in the new process and writes the four values back:

model_cfg cannot be pickled. So pass only the necessary runtime scalars; the worker process loads model_cfg again in __setstate__ and then fills them back in.

The default values of prefill_attempt_interval and prefill_any_attempt_interval are function default arguments ({{cite deepinfer/config.py:193-194}}). Python computes them once, when it imports deepinfer.config. create_engine_configs does not pass them ({{cite deepinfer/engine/arg_utils.py:107-113}}). So set the two variables before you import deepinfer. See {{link reference/env-vars#import-time-table | the import-time table}}.

Where the docstrings and the code disagree

  • max_model_len. The docstring says: "If None, will be derived from the model" ({{cite deepinfer/config.py:39-40}}). The code uses 4096 and does not read the model ({{cite deepinfer/config.py:69}}). The checkpoint value max_position_embeddings is parsed, but ModelConfig does not use it ({{cite deepinfer/hugging_face/config.py:277}}).
  • gpu_memory_utilization. The error text says "must be less than 1.0", but the test is > 1.0, so 1.0 passes ({{cite deepinfer/config.py:146-147}}). The LLM docstring says "between 0 and 1" ({{cite deepinfer/entrypoints/llm.py:44-48}}). No check refuses 0 or a negative value; then the memory profile finds no room, and start-up stops with "No available memory for the cache blocks" ({{cite deepinfer/engine/llm_engine.py:441-444}}).
  • stop_preempted_request. Three defaults exist: SchedulerConfig False ({{cite deepinfer/config.py:191}}), EngineArgs True ({{cite deepinfer/engine/arg_utils.py:40}}), LLM False ({{cite deepinfer/entrypoints/llm.py:68}}). The EngineArgs value always reaches SchedulerConfig ({{cite deepinfer/engine/arg_utils.py:111}}).

Fields that nothing reads

A search of deepinfer/, csrc/ and examples/ finds no reader for these fields. They are stored and then not used in this release.

  • EngineArgs.offline_inference: stored in LLMEngine.offline_inference only ({{cite deepinfer/engine/llm_engine.py:195}}).
  • ModelConfig.ignore_len ({{cite deepinfer/config.py:73}}) and ModelConfig.served_model_name ({{cite deepinfer/config.py:74}}).
  • SchedulerConfig.driver_gpu_id: the C++ constructor does not read it ({{cite deepinfer/engine/llm_engine.py:253}}, {{cite csrc/engine/scheduler.hpp:94-108}}).
  • CacheConfig.bytes_per_block appears only in a log line ({{cite deepinfer/engine/llm_engine.py:262-264}}).
