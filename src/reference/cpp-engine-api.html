Use this page to find a name fast. For the rules that apply to many names (memory that a call borrows, calls that release the {{term gil | GIL}}, loose types), read {{link code/engine-pyi}}. This page does not repeat them.

The module and its three submodules

  • One module, three parts. csrc/pybind.cpp makes the {{term pybind11}} module and adds the submodules cuda_utils, engine and graph_timer ({{cite csrc/pybind.cpp:7-17}}). The stub of the package lists the same three ({{cite deepinfer/_C/__init__.pyi:1-5}}).
  • One build per platform. setup.py compiles the same engine sources on both platforms. It adds cuda_utils.cpp and graph_timer_cuda.cpp on NVIDIA, and asc_utils.cpp and graph_timer_asc.cpp on Ascend ({{cite setup.py:22-34}}, {{cite setup.py:43-47}}, {{cite setup.py:61-65}}).
  • Where the file is. The compiled .so is in deepinfer/_so/<accelerator>-<arch>/. The package adds that folder to its search path at import ({{cite deepinfer/__init__.py:28-32}}).
  • The stubs. The .pyi files are {{term type-stub | type stubs}} that make stubgen generates with pybind11_stubgen ({{cite Makefile:27-28}}, {{cite scripts/gen_stub.sh:11-14}}). Python never imports them. The "Stub" column below gives the line in the stub.

Submodule graph_timer (3 names)

Low-level handles for the {{term graph-timer}}, which measures regions inside a replayed {{term cuda-graph}}. The binding is {{cite csrc/graph_timer/pybind.cpp:5-29}}. The Python side is CUDAGraphTimer in {{cite deepinfer/timer.py:78-217}}. CudaGraphRunner wraps each captured graph in a GraphHandle and registers it ({{cite deepinfer/worker/cuda_graph_runner.py:130-136}}).

CUDAGraphTimer.supported() returns PLATFORM.is_gpu ({{cite deepinfer/timer.py:94-98}}). On Ascend, every method of the three classes throws "NPU graph timer primitives are not implemented yet" ({{cite csrc/graph_timer/graph_timer_asc.cpp:7}}). So the Python code makes no handle on Ascend.
