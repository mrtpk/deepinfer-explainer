DeepSeek V4.1 in DeepInfer keeps this skeleton but uses MLA attention, MoE layers and mHC residual paths. --- A transformer turns token ids into vectors and changes them in a stack of identical layers. Then it turns each vector into one score per vocabulary token.

The idea

Three parts

Almost every LLM is a {{term transformer}}. It has three parts:

  1. The embedding. The {{term embedding}} is a table with one row per token id. The model looks up the row of each input token. Each row is a vector of d numbers, where d is the hidden size (often a few thousand). This vector is the {{term hidden-state}} of the token.
  2. A stack of N layers. Each {{term decoder-layer}} reads the hidden states of all tokens and writes new ones of the same shape. N is often between 30 and 100.
  3. The output head. A final norm, then the {{term lm-head | LM head}}: a matrix that turns each hidden state into one score per vocabulary token. These scores are the {{term logits}}.

So a text of T tokens is a matrix of shape [T, d] inside the model. Every layer keeps this shape. Only the content changes: each layer adds information to each token's vector.

Inside one layer

A decoder layer has two blocks:

  • {{term attention | Attention}}. Tokens exchange information. Each token looks at the earlier tokens and copies a weighted mix of their information. This is the only place where tokens see each other. The page {{link learn/attention}} explains it step by step.
  • Feed-forward network ({{term ffn | FFN}}). Each token alone goes through two or three large matrix multiplies. Most of the weights of a model are here. In an {{term moe | MoE}} model, this block has many "experts", and a router selects a few of them for each token ({{link learn/moe}}).

Two more parts keep the stack stable:

  • Normalization. Before each block, a {{term rmsnorm | RMSNorm}} rescales the vector of each token to a standard size.
  • The residual stream. A block does not replace its input. It adds its result to the input: x = x + block(norm(x)). The hidden state that flows through all layers is the {{term residual-stream | residual stream}}.

Where the order of the tokens comes from

Attention by itself does not know which token comes first. A transformer adds position information. Most modern LLMs, also DeepSeek, use {{term rope | RoPE}}: it turns the query and key vectors by an angle that depends on the position. The attention scores then depend on the distance between two tokens.

An everyday comparison

Think of a folder that goes along an assembly line, one folder per token. At each station, a worker reads the folder and adds a note. Some stations let the worker look into the folders of earlier tokens (attention). Other stations work on one folder alone (FFN). Nothing is removed; notes only accumulate. At the end, a clerk reads each folder and writes a guess for the next token.

The comparison stops here. The "notes" are numbers, not words, and nobody designed what each station does. Training found the numbers. Also, the real model sends all folders through a station at the same time, as one matrix.

Step 3: the three changes of DeepSeek V4.1

  • MLA attention. All query heads share one key/value entry per token. The start-up code requires exactly one KV head ({{cite deepinfer/hugging_face/config.py:53-58}}). See {{link concepts/mla-attention}}.
  • MoE feed-forward. Every layer is an MoE block. The decoder layer asserts this type; another block type stops with AssertionError ({{cite deepinfer/model_executor/models/decoder_layer.py:57}}, {{cite deepinfer/model_executor/models/decoder_layer.py:38-42}}). See {{link concepts/moe-routing}}.
  • mHC residual. The residual stream has hc_mult parallel paths, with shape [n, hc_mult, hidden_size] ({{cite deepinfer/model_executor/models/v4_modules/hc.py:58}}). See {{link concepts/mhc-residual}}.

Deep dive

Worked example. A step with 3 sequences: one prefill of 1,000 tokens, two prefills of 12 tokens. Then T = 1,024. The embedding gives [1024, d]. The layers keep [1024, hc_mult, d]. The sampler selects 3 rows, one per sequence, and computes logits of shape [3, V].

RMSNorm. DeepInfer's class documents the formula ({{cite deepinfer/model_executor/layers/layernorm.py:15-18}}):

RMSNorm(x) = w ⊙ x / sqrt(mean(x²) + eps)

Worked example with x = (3, 4), w = (1, 1), eps ≈ 0:

  1. mean(x²) = (9 + 16) / 2 = 12.5.
  2. sqrt(12.5) = 3.536.
  3. x / 3.536 = (0.849, 1.131). The root mean square of the result is 1.

The value of eps comes from rms_norm_eps in the checkpoint config ({{cite deepinfer/hugging_face/config.py:281}}).

Pre-norm residual. A standard pre-norm layer computes:

h   = x + Attention(RMSNorm(x))
out = h + FFN(RMSNorm(h))

The input x reaches the output unchanged, plus two additions. This direct path lets training send its signal through many layers. It also means that a layer can learn to change only a little.

mHC in DeepInfer. mHC widens the residual stream to hc_mult paths. Before each block, learned weights mix the paths into one block input. After the block, the output goes back into the paths. At the end of the model, the paths are mixed back into one hidden state ({{cite deepinfer/model_executor/models/v4_modules/hc.py:57-68}}). The details are on {{link concepts/mhc-residual}}.

A standard FFN with the {{term swiglu | SwiGLU}} activation has three matrices. For one token vector x of size d, with an inner size dff:

FFN(x) = W2 · ( SiLU(W1 · x) ⊙ (W3 · x) )        W1, W3: [d_ff, d]   W2: [d, d_ff]
SiLU(z) = z · sigmoid(z)

DeepInfer requires this activation: the checkpoint must say hidden_act: silu, and the config maps it to swiglu ({{cite deepinfer/hugging_face/config.py:53-58}}, {{cite deepinfer/hugging_face/config.py:278}}).

Weight count per layer (standard dense layer, illustrative numbers):

BlockWeightsd = 4,096, dff = 11,008
Attention (Q, K, V, output; full multi-head)4 · d²67.1 million
FFN (SwiGLU)3 · d · dff135.3 million
Two RMSNorm weights2 · d8,192

So in this example the FFN holds about two thirds of the layer. An MoE layer replaces the one FFN with many expert FFNs. Each token uses only a few of them, so the model can be very large but the work per token stays small.

The numbers are a generic example, not DeepSeek V4.1. MLA attention uses low-rank projections, so its weight count is different. DeepInfer reads all sizes from the checkpoint config ({{cite deepinfer/hugging_face/config.py:271-300}}).

The config loader accepts only the variant that the run-time code supports:

  1. SwiGLU (hidden_act = silu), no attention bias, attention dropout 0.
  2. num_key_value_heads = 1: one KV head, the MLA design.
  3. BF16 parameters in the checkpoint.

Other start-up facts that a reader of the model code meets:

  • Head size. The KV entry has kv_lora_rank + qk_rope_head_dim numbers, and the config sets kv_lora_rank = head_dim − qk_rope_head_dim ({{cite deepinfer/hugging_face/config.py:287-289}}). The cache code asserts that the sum is the 512 elements of the KV cache format ({{cite deepinfer/worker/cache_engine.py:46-56}}, {{cite deepinfer/model_executor/layers/tilelang_ops/cache_common.py:109-111}}). So head_dim is 512 (inferred).
  • Head count. The attention kernels accept 64 or 128 query heads. Another count up to 128 is padded with zeros to the next allowed count; more than 128 raises ValueError ({{cite deepinfer/model_executor/layers/attention_backend.py:5-23}}).
  • One architecture. The registry maps DeepseekV41ForCausalLM to the vision-language class DeepseekVLForCausalLM ({{cite deepinfer/model_executor/models/__init__.py:14-17}}). The text model is inside it; see {{link concepts/vision-encoder}}.
  • Extra parts. Some layers also have {{link concepts/engram | Engram}} memory ({{cite deepinfer/model_executor/models/decoder_layer.py:80-83}}). A draft module (DFlash) shares the embedding and the LM head ({{cite deepinfer/model_executor/models/deepseek.py:300-302}}).

What can go wrong

  • Another model. A checkpoint with several KV heads, attention bias or a non-BF16 dtype stops at start-up with ValueError ({{cite deepinfer/hugging_face/config.py:53-60}}).
  • Too many heads. More than 128 query heads raise ValueError in the attention backend ({{cite deepinfer/model_executor/layers/attention_backend.py:15-16}}).
  • A dense layer. The decoder layer accepts only MoE blocks. Another block type fails the assert in DeepseekDecoderLayer.__init__ ({{cite deepinfer/model_executor/models/decoder_layer.py:57}}). The helper that builds the MLP also raises NotImplementedError for other types ({{cite deepinfer/model_executor/models/decoder_layer.py:38-42}}).
  • Logits from the model. Code that expects the forward pass to return logits gets hidden states. Call the sampler path, or multiply by the LM head yourself ({{cite deepinfer/model_executor/models/deepseek.py:246-248}}).

Why it matters. All model pages of this site use this skeleton. A page can talk about MLA, MoE, mHC, Engram or YOCO. For each one, ask two questions: which part of the skeleton does it change, and does the shape [T, d] stay the same?

A step has 500 tokens and the hidden size is d. What is the shape of the hidden states between two decoder layers, in a plain transformer?

[500, d]. Every layer keeps this shape. Only the LM head changes it, to [rows, V].

 In which block do tokens exchange information?

In attention. The FFN works on each token alone.

 Compute RMSNorm of x = (1, 1, 1, 1) with weights of 1 and eps ≈ 0. Then compute it for x = (2, 2, 2, 2).

Both give (1, 1, 1, 1). mean(x²) is 1 and 4, the roots are 1 and 2, and x divided by the root is 1 in both cases. RMSNorm removes the overall size of the vector.

 Why does DeepseekModel.forward in DeepInfer return hidden states and not logits? Give the reason from the code and a number.

The sampler needs logits only for the rows that it samples: in a prefill step, the last token of each sequence ({{cite csrc/engine/prepare_sample.cpp:197}}). It gathers those rows first, then multiplies by the LM head weight ({{cite deepinfer/model_executor/layers/sampler.py:140-142}}, {{cite deepinfer/model_executor/models/deepseek.py:392-394}}). Take a prefill of 1,024 tokens and V = 129,280 (inferred). Logits for all rows would need 1,024 × 129,280 × 4 bytes ≈ 530 MB. One row needs about 517 KB.
