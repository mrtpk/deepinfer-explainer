## 8. How the supervisor works

Supervisor + subagents. At most ~6-7 subagents at the same time. Writer → separate fact checker → commit
per batch. `progress.md` is updated after every event. The target repo is never changed. No push without
a user request. Open questions go to `progress.md` "Questions for the user".

## 9. Definition of done

- All planned pages exist (or are deferred by the user) and `python3 build.py` has 0 errors.
- Every concept and tour page has a diagram, code excerpts, a deep dive and "Check yourself".
- Every batch is fact-checked; the FINAL-PASS TODO list is empty.
- Site check at 1280 and 390 px: no overflow, no JS errors, no broken links; every visual works.
- A beginner can follow Home → Basics → Tour 1 with no dead end.

## 10. Risks

| Risk | What we do |
|---|---|
| Wrong explanations | Writers read the code; separate fact check per batch; citations always |
| Pages differ in style | One template, STYLE.md, Phase 1 samples given to every writer |
| Out-of-scope code | Explain the interface only, and say so on the page |
| Too large to finish | Priority: Basics → Tour 1 → core concepts → code map → reference |
