## Version
- DeepInfer commit 9bd9cf243fc53ef9afbf8f04d391d989117d6ab9 (2026-10-21). Repo has 4 commits. Derived from vLLM.
- vendor/ submodules (DeepEP, DeepEP-Ascend, DeepGEMM, DeepGEMM-Ascend, DeepSelect, FlashMLA) are NOT checked out. `tilelang` and `tile-kernels` come from pip.

## Platform
- `get_platform()` (platform.py ~223) picks PlatformNPU if `deep_cluster.hardware.accelerator_kind() == "ascend"`, else PlatformGPU (also for "cpu").
- `DEEPINFER_ACCELERATOR` default "nvidia" (environ.py ~101); used for the `_so/<accelerator>-<arch>/` tag. Ascend users must export it.
- Kernel dispatcher is `layers/tilelang_ops/ops.py` (NOT `__init__.py`, which is empty). cuda/ has 43 `*_tl` factories, asc/ 42; only `detect_outlier_and_abort_tl` is CUDA-only.
- One deployment = one hardware type (NCCL or HCCL). Not AFD. E/P/D disaggregation is not in this release.

## Engine and API
- Tokenization happens in `LLM._add_request` (entrypoints/llm.py ~156). BOS id 0, EOS id 1.
- Vocab size 129280 is NOT in the repo: `vocab_size` comes from the checkpoint config.json (config.py ~121). It is only INFERRED from the first image-token id 129280 hard-coded in tokenizer.py ~48-56. Always mark it "inferred".
- Engine and driver worker share one process; `_init_workers` spawns processes only for CP ranks 1..cp-1. DP ranks are separate processes started by `examples/_launch.py`.
- ZOS: `environ.py` default off, but `EngineArgs` turns it on for the NORMAL engine (arg_utils.py ~51-55). With ZOS, `step()` returns the outputs of the PREVIOUS decode step as pointers into a C++ RequestOutput pool (size 10000), released at the next `pre_sampler_sync`; callers must clone. `LLM` calls `flush_inflight_reqs()` at the end.
- A bad prompt token id: `add_request` returns None with an info log (no exception).
- llm_engine.py ~800-858: empty hooks for PD split / KV saving; unused in this release.
- The only registered architecture maps to `DeepseekVLForCausalLM` (models/__init__.py ~15-17). So every NORMAL engine has a `MultimodalProcessor` (llm_engine.py ~210), and every request (also text-only) waits until the multimodal worker marks it schedulable in `fetch()`, which runs after `schedule()` in each step.
- `DeepseekModel.forward` is the INNER model; the top-level is `DeepseekForCausalLM.forward` (deepseek.py ~374). In a VL prefill the VL class passes its own hidden states.
- Sampler arrays (temperature, top-p, top-k, seed) have one entry per sequence, not per row.
- When `DEEPINFER_ENABLE_MTP_VARLEN` is on (the README calls this feature DSpark), the worker also waits on `d2h_evt` (worker.py ~146-152, ~218-234), not only `sample_end_evt`.
- `_preempt` only frees blocks (scheduler.hpp ~766-790). Clones come only from forked sequences. The `deepinfer` package never calls `fork_seq`, but `examples/benchmark.py` ~337-347 does (it also calls try_allocate_seq, sets chunk checkpoints and decode_step = 0).

## Scheduler and KV cache
- Block size fixed at 128 tokens (model_metadata_utils.py ~133-135).
- `ca_cache` (main compressed KV) and `ica_cache` (indexer keys) share one uint8 paged buffer `gpu_blocks [num_gpu_blocks, bytes_per_block]`; each block row holds all layers.
- `swa_cache` is NOT paged: a per-sequence ring of 134 tokens (128 window + 6 backtracking) × 528 B per layer, in a separate state buffer `gpu_states`. `ca_state` is float32 state for ratio-2 layers. `ica_state` exists only for indexers without `use_kproj` (cache_engine.py ~123-127); the HF loader always sets `use_kproj=True` (config.py ~122, asserted in mla_attn.py ~272), so in practice `ica_state` is None. State slots have a second BlockManager. Block 0 and slot 0 are never used.
- 1 KV head; one 512-value entry per GROUP of tokens, where the group size is the layer's compress ratio from the checkpoint (config.py ~148-152; e.g. 1 or 2 — do not claim a fixed list): 528 B (fp8) / 288 B (fp4). The classic `2 × heads × head_dim` formula does not apply.
- Free list is FIFO. Prefill only when cache usage ≤ 90%.
- Decode preemption picks the running sequence with the MOST output tokens; the comment at scheduler.hpp ~557 says "shortest" (comment is wrong). No swap to CPU: stop or recompute. `EngineArgs` default `stop_preempted_request=True`; offline `LLM` sets False (recompute).
- `_init_cache`: the docstring says minimum, but the code takes the MEAN block count over ranks, rounded down to even, after reserving 2 × the state buffer (worker/base.py ~264-266).

## Decoding
- The model forward returns hidden states; the sampler computes fp32 logits only for the rows it samples.
- After prefill the draft list holds 5 placeholder ids (vocab_size − 1); a decode step sends 1 + 5 = 6 tokens per sequence (default `DEEPINFER_USE_NEXTN_DECODE` = 5).
- C++ also reads `DEEPINFER_USE_NEXTN_DECODE` with getenv.

## Env vars
- 59 variables in deepinfer/environ.py. Bool parsing: only `0`, empty, `false`, `False` are false (`=off` turns a feature ON). Empty value for an int var raises ValueError.
- 6 variables are read at import time; `SchedulerConfig` reads the prefill-interval vars as default arguments.
- `examples/README.md:63` says extra experts default 32; code default is 0 (32 comes from the example scripts).
- On Ascend, `DEEPINFER_ENGRAM_FORCE_GPU_STORAGE` is always on. `CUDA_VISIBLE_DEVICES` must be set (KeyError otherwise).

## Added after B1 (2026-10-21)
- Sampling order in the fused sampler: temperature → top-p on the full softmax → top-k (layers/tilelang_ops/fused_sample.py ~121-150, 209-211). Returned logprobs are after temperature/top-p/top-k (~52).
- "A decode step sends 1 + 5 tokens" holds while DEEPINFER_ENABLE_MTP_VARLEN is off (default off: environ.py ~131; mtp_varlen.hpp ~153-157). With it on, the verification length varies.
- A NORMAL engine tries prefill only at attempt points (every 70 / 100 decode steps), so a new request can wait up to 69 decode steps (scheduler.hpp ~308-319).
- With `prompt_token_ids`, DeepInfer does not add BOS (llm.py ~153-156).
- head_dim 512 is INFERRED (hugging_face/config.py ~287-289 + assert in cache_engine.py ~46-56).
- Decode attention passes `causal=False`; the index lists act as the mask (attention_backend.py ~133).
- The checkpoint must have 1 KV head, SwiGLU and BF16 (hugging_face/config.py ~53-60).

## Added after B9 (2026-10-21)
- Rejection test is not exact: residual is `max(q − α·p, 0)` with `α = exp(−5e-5)` (tilelang_ops/common.py ~3-19, 53); each token's probability goes up by at most a factor (1+ε) and down by at most ≈5e-5 absolute (common.py ~3-19); the distribution test checks only the upper bound.
- `DEEPINFER_DECODE_TOKEN_BLACKLIST` also applies to prefill rows (sampler.py ~167-171).
- Under ZOS the CPU picks the total verification budget (total_q) from accept rates two rounds older than the step being scheduled, one round older than the GPU's (mtp_varlen.hpp ~203-204); the GPU splits it with the newest confidences. Without CUDA graphs, DSpark falls back to 1 + 5 tokens.
- A rejected draft is never undone: caches are indexed by position and the next step overwrites the same positions. The SWA ring has 134 = 128 + 6 slots, enough for this.

## Added after B5a (2026-10-21)
- The HF loader defaults `use_fp4_sparse_kv=True` (hugging_face/config.py ~303): the main KV entry is 288 B (FP4) unless config.json says otherwise; 528 B is the FP8 option.
- `qk_rope_head_dim` must be 64 when indexer layers exist (mla_attn.py ~121, config.py ~127), so `kv_lora_rank` is 448 (512 − 64).
- config.py ~159 docstring says the first ratio-1 layer is on the prefill side; yoco.py ~21 and attn.py ~247 make it the first YOCO consumer. Describe the code.
- NOT in the repo (mark as example values): number of layers, hidden size, heads, q_lora_rank, o_lora_rank, o_groups, sliding_window, compress_ratios, index_topk, index_n_heads, index_head_dim, hc_mult, expert counts, vocab size, nextn, sharing lists. Docs only: "first 20 stored layers", "20 decoder layers" (doc/inference_deployment_qa.md ~163, 187).

## Added after B7 (2026-10-21)
- `DEEPINFER_FORCE_IMBALANCE_RATIO` from the environment never takes effect: the memory profile sets it to 1.8 and then 0.0 (model_runner.py ~509-512).
- EPLB rearrangement is off by default (interval 0). Counting and `moe_lb` still run when EP > 1.
- With the released checkpoint format, mma_type is always `fp8xfp4`, so Ascend always uses mega-MoE, and GPU uses it whenever the EP group fits in the NVLink domain.
- No group-limited routing. The policy can put two copies of one expert on one rank. The EPLB window is not cleared after a rearrangement.
- Order in the code: the shared expert is launched before combine; combine uses an event captured BEFORE the shared expert, and `limit_num_sms` keeps SMs free for communication (mlp.py ~601-603). Whether the combine transfer overlaps the shared expert on the device is decided inside DeepEP: do not claim either "they overlap" or "they do not overlap".
- NOT in the repo: expert count, top-k, routed_scaling_factor, hidden/intermediate sizes, the exact sqrtsoftplus/noaux_tc formulas (inside kernels), how the kernel picks one copy of a replicated expert.

## Added after B2 (2026-10-21)
- No TP group and no PP group exist. Groups: world, local, dp, cp, ep, ep_in_dp, enp (Engram), plus gloo copies of dp, cp, ep_in_dp (parallel_state.py ~51-68). `ReplicatedLinear` is the only dense linear class; `ParallelRoutedLinear` holds the local experts and splits by expert, not inside a matrix (v4_modules/linear.py ~23-34); `VocabParallelEmbedding` keeps the full table on every rank; `model_parallel_size` equals the CP size (config.py ~171).
- doc/inference_deployment_qa.md ~53 says TP and CP are not used in production "for now", but the code and examples support CP.
- `is_within_nvl_domain` (defined at parallel_state.py ~130-134, called in mlp.py ~184-188) always returns True on NPU.
- The loader accepts only quant fp8, FP4 experts, block [32, 32], UE8M0 scales and activation_scheme "dynamic" (hugging_face/config.py ~254-262), so fp8_attn, fp8_mlp, mxfp8 and mxfp4 are always True.
- Every decoder layer is an MoE block (decoder_layer.py ~38-42).
- Global rank = engine_rank × cp_size + cp_rank (worker/base.py ~329).
- Prefill attempt points: every 70 decode steps (ALL vote) or 100 (ANY vote); step 0 counts as an ALL point.

## Added after B3a (2026-10-21)
- After a slot frees, a waiting request starts only at the next prefill attempt point, not at once.
- An aborted request that is already running gets no output with finish reason "abort" (derived from the code, not run).
- Some Scheduler members are written but never read, incl. `truncate_len`: DEEPINFER_YOCO_PREFILL_KEEP_TOKENS reaches the scheduler but the scheduler does not use it. SampledInfo.update and from_reqcnt are unused.
- A finished sequence still holds a max_num_seqs slot during a prefill step (late release).

## Added after the B1 fact check (2026-10-21)
- Only the NON-fused decode attention call passes `causal=False`. On GPU with 64 or 128 heads, sparse layers and layers without a compressed cache use a fused kernel with no causal argument (attention_backend.py ~107-121, attn.py ~87-92).
- A non-MoE block fails the assert at decoder_layer.py ~57 (AssertionError) before any NotImplementedError.
- Token-id range limit is `vocab_size + 5`, because `LLM` always passes multimodal data (llm.py ~158-159, multimodal_tokens.py ~28).
- Random-sampling tags: case 1 = new sample after a rejected draft, case 2 = accept test (fused_sample.py ~239, 245); draft proposals use tag "mtp" with seed offset 1000000007 (dflash.py ~329).
- Engram compressed token ids apply only when tokenizer compression is on (arg_utils.py ~89-90).

## Added after the B5a fact check (2026-10-21)
- The VL class computes the embeddings in every prefill (also text-only), so with that class the inner embedding line runs only in decode (deepseek_vl.py ~232-233).
- Compressed cache is FP4 by default; the window (SWA) cache is FP8 (config.py ~303, cache_common.py ~109-128).
- YOCO prefill truncation is OFF by default (environ.py ~188); consumer layers skip prefill work only when it is on.
- Decode `kv_ca_index` is the indexer top-k output and holds physical slots (index_attn.py ~506-514).
- In C2 decode, `pre_rope_kv` has one row per query token, with zero rows where no entry ends (tilelang_ops/compress.py ~93-101).

- Post-processing is deferred one step only for ZOS decode steps; prefill steps and runs without ZOS post-process at once (worker.py ~182-187).
- With more than one DP rank the ALL vote can fail, so a new request can wait up to 100 decode steps (the ANY point).

## Added after the B9 and B3a fact checks (2026-10-21)
- SWA window: the oldest query of a step (at P) needs keys back to P−127 (the window includes itself; prepare_tensor_input_v4.cpp ~644-649). Rejected keys are never read: a query reads only keys up to its own position, and the step that first queries a position rewrites it first.
- `accept_probs` is an estimate; the α penalty makes it slightly lower than Σmin(p,q).
- In the GPU DSpark split a new sequence gets rate 0 and ranks last; it can still get drafts if the budget is large (schedule_mtp_varlen.py ~57-98).
- Top-p keeps the shortest prefix with sum GREATER than p (fused_sample.py ~139).
- QA-doc speculative numbers are benchmark figures, not production.
- Preempted requests with structured output stop when `structured_output.status != 0` (scheduler.hpp ~770-771), not always.
- YOCO keep tokens: `truncate_len` is set only in compact mode; the FlopsEstimator still gets the value (llm_engine.py ~318-322).
- EOS id 1 source: tokenizer.py ~38/121 (release mode). The scheduler's "unset" token limit is 2**30.
- `free_seq_nolock` also frees the state slot and the MTP slot (scheduler.hpp ~738-745).
- Possible block leak (unconfirmed): a chunked/recomputed sequence aborted in `waiting` leaves via `ignored_seqs` (scheduler.hpp ~363-367, 569-577); no free of its blocks was found. Pages must call this an open question.
- With ZOS (default), the decode slot mapping is computed on the device by `prepare_v4_decode_metadata` (model_metadata_utils.py ~143, prepare_tensor_input_zos.py ~336-367), not in C++.
- One shared/default SamplingParams in LLM.generate gives every request the same seq_seed (deepcopy does not re-run the constructor).

## Added after the B7 fact check (2026-10-21)
- examples/benchmark.py ALWAYS sets 32 extra experts (~161-162), also with EPLB off; offline_inference.py only with EPLB on. The EPLB window of 3 is always set (_config.py ~80).
- TopKGate always makes `bias_vl` (moe.py ~63-64), so the text-bias fallback at mlp.py ~236 never happens.
- FP8 scales for 32 × 32 blocks (config.py ~258).
- EPLB weight moves use torch.distributed point-to-point (NCCL on GPU, HCCL on Ascend). P2P receive buffers are made at every rearrangement (shuffle.py ~82).
- moe_lb = sum of the maxima / sum of the means (stats_logger.py ~238-241); "slowest rank / mean" is the doc's wording (qa.md ~99).
