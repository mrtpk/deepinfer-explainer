Vision encoder (VL)

IntermediateDeepInfer conceptsabout 10 min read + 6 min deep dives

Code version: DeepInfer @ 9bd9cf2 · 2026-10-21

Before you read

This page uses ideas from these pages:

  • Tokens and tokenizers Beginner
  • Prefill and decode Beginner
  • Model map: DeepSeek-V4.1-Flash in DeepInfer Intermediate
  • The scheduler Intermediate

In one sentence

A worker process prepares each image. In the prefill, a ViT and a projector turn its pixels into vectors at the image tokens of the prompt.

The idea#

A language model reads only vectors, one per token. To read an image, the model needs vectors for the image too. A vision encoder makes them. DeepInfer's vision encoder is a ViT: it cuts the image into patches of 14 × 14 pixels and runs 32 transformer blocks over the patches. A projector then joins small blocks of patch vectors and maps them to the hidden size of the language model.

The prompt needs room for these vectors. So the engine replaces each image placeholder in the prompt with many image tokens, one position per image vector plus a few marker positions. In the prefill, the model puts the image vectors into exactly these positions. After that, the image is part of the KV cache like any text, and decode never looks at the pixels again.

Image work is slow on the CPU. So a separate process, the MultimodalProcessor worker, decodes and resizes the image while the engine continues. A request can run only after the worker has answered.

An everyday comparison. Think of a translator who reads a letter with a photo in it. An assistant first scans the photo and writes a short description card. The translator leaves a gap of the right size in the text and puts the card into the gap. The comparison stops here. The "card" is a list of numbers that the model learned to read, not words. Also, the gap size depends only on the image size.

One machine, not E/P/D

In this release the vision encoder runs inside the prefill forward of each engine. The docs describe separate vision-encoder, prefill and decode instances (doc/inference_deployment_qa.md:31, doc/inference_deployment_qa.md:61-63). The README lists "VE/Prefill/Decode disaggregation" as not included in this release (README.md:38-41). See Is it AFD?.

In the code#

Step 1: the request brings image bytes and sizes#

The caller passes one dict per prompt to LLM.generate(..., multi_modal_data=...) (deepinfer/entrypoints/llm.py:96, deepinfer/entrypoints/llm.py:135-141). The image is not part of SamplingParams. The example scripts build the dict from examples/images/:

The prompt text contains one placeholder token per image, <image> or <｜deepseek_image｜> (deepinfer/multimodal_tokens.py:14). At start-up, the processor finds its id in the tokenizer and asserts that config.json has the same image_token_id (deepinfer/ve/multimodal_processor.py:68-86). A text-only prompt still gets a dict with empty image lists, because the engine has a MultimodalProcessor (deepinfer/entrypoints/llm.py:158-159).

Step 2: each placeholder becomes many image tokens#

add_request calls overwrite_prompt before it makes the sequence (deepinfer/engine/llm_engine.py:547-551). For each placeholder, line 145 computes the token count from the image size alone, with no image decode. The first new id is vocab_size + 2 (IMAGE) and all others are vocab_size + 1 (IMAGE_PAD) (deepinfer/ve/multimodal_processor.py:89-91, deepinfer/multimodal_tokens.py:17-28). The id range check then allows the 5 ids above vocab_size (deepinfer/engine/llm_engine.py:581).

Step 3: the worker process prepares the image#

The engine forks one worker process at start-up (deepinfer/ve/multimodal_processor.py:93-103, deepinfer/engine/llm_engine.py:213-219). _enqueue adds the sequence to the scheduler and puts the dict on the input queue (deepinfer/engine/llm_engine.py:620-625). The sequence starts with schedulable = False, because it has a multimodal dict (csrc/engine/pybind_sequence.cpp:35).

Line 201 runs DeepseekVLForCausalLM.multi_modal_mapper. It decodes and resizes the image and makes the token types and patch positions (see models/deepseek_vl.py: the vision-language model class). With the multimodal pool on, lines 205-211 copy every non-empty tensor into shared memory and send only handles. If you do not set the variable, EngineArgs turns the pool on for every engine type except COMPLETION (deepinfer/engine/arg_utils.py:56-60).

Step 4: fetch() makes the request schedulable#

step() calls fetch() after schedule() (deepinfer/engine/llm_engine.py:939-945). So a request can join a prefill at the earliest in the next step. A failed image gives None (line 290); the engine aborts that request.

Every request waits for the worker

The only registered architecture is DeepseekVLForCausalLM (deepinfer/model_executor/models/__init__.py:15-17). So every NORMAL engine has a MultimodalProcessor, and every request, also a text-only one, waits for one round trip through the worker process. The Tour: Life of a request tour shows what this means for the first prefill step.

Step 5: the scheduler keeps each image in one chunk#

With chunked prefill, a chunk can end anywhere. If it ends inside an image, the code moves the end. For the first sequence of the batch, it grows the chunk to the image end if the token budget allows. Else it shrinks the chunk to the image start (csrc/engine/scheduler.hpp:487-493). This is why the first id of an image is different (IMAGE, not IMAGE_PAD): two images that touch can still be cut between them.

Then prepare_input_metadata_vl cuts the image data of each sequence to the token range of the chunk (deepinfer/ve/prepare_tensor_input_vl.py:77-138). It runs only for prefill batches (deepinfer/model_executor/model_metadata_utils.py:182-187).

Step 6: the prefill forward puts the image vectors into the prompt#

In every prefill, also a text-only one, the VL class computes the input embeddings itself. Decode uses the normal embedding of DeepseekModel. get_input_embeddings embeds the ids and, when the batch has image bytes, calls the vision-language tuner (deepinfer/model_executor/models/deepseek_vl.py:194-224):

  1. rgb_pad_to_patches turns the raw RGB bytes into normalized bf16 patches on the device.
  2. _encode_images runs the ViT, joins blocks of patch vectors (batch_downsample) and runs the projector (deepinfer/model_executor/models/vision_encoder/vl_aligner.py:47-77).
  3. _merge_image_embeds writes the i-th image vector into the i-th position of type IMAGE. Positions of type IMAGE_START, IMAGE_NEW_LINE and IMAGE_END get three learned vectors (deepinfer/model_executor/models/vision_encoder/vl_aligner.py:31-45, deepinfer/model_executor/models/vision_encoder/vl_aligner.py:79-94).

The batch also gets images_seq_mask, true at every image position (deepinfer/model_executor/models/deepseek_vl.py:179). The MoE gate then uses a separate correction bias for image tokens (deepinfer/model_executor/models/v4_modules/mlp.py:373-390), and Engram uses the mask too (deepinfer/model_executor/models/deepseek.py:180-186).

Deep dive#

Deep dive

Worked example: how many tokens does one image take?

The geometry code is in ve/processor/image_processor.py. Its inputs come from config.json: patch_size, downsample_ratio, max_image_tokens, min_pixels, max_wh_ratio (deepinfer/hugging_face/processor.py:25-36). The repo does not contain these values. The example below uses patch 14 (the ViT constant, deepinfer/model_executor/models/vision_encoder/vit.py:27) and ratio 3, the values that a code comment names (deepinfer/ve/prepare_tensor_input_vl.py:155). It assumes max_image_tokens ≥ 206, min_pixels ≤ 307200, and max_wh_ratio null or at least 4/3 (deepinfer/ve/processor/image_processor.py:166-173).

  1. Round each side up to a multiple of 14: 640 → 644, 480 → 490 (deepinfer/ve/processor/image_processor.py:178-179).
  2. Patch grid: n_vit_w = 644 / 14 = 46, n_vit_h = 490 / 14 = 35, so 1610 patches (deepinfer/ve/processor/image_processor.py:87-92).
  3. LLM grid: n_llm_w = ceil(46 / 3) = 16, n_llm_h = ceil(35 / 3) = 12, so 192 image vectors.
  4. Token count: n_llm_h × (n_llm_w + 1) + 2 = 12 × 17 + 2 = 206. Each row of the grid ends with a NEW_LINE token, and START and END frame the image (deepinfer/ve/processor/image_processor.py:76-78).
  5. If the count is above max_image_tokens, solve_resize_ratio computes a smaller size with about the same aspect ratio in one pass. Then an assert checks that the new count fits (deepinfer/ve/processor/image_processor.py:95-127, deepinfer/ve/processor/image_processor.py:140-152).

The comment explains the NEW_LINE tokens: the ViT features have 2-D information, but the LLM uses 1-D RoPE (deepinfer/ve/processor/image_processor.py:175-177).

Deep dive

Inside the ViT and the projector

  • Constants in vit.py fix the ViT structure: patch 14, width 1024, 32 blocks and 16 heads. The MLP ratio is 2.7, rounded up to a multiple of 128 (deepinfer/model_executor/models/vision_encoder/vit.py:26-32). The comment says it is the only vision encoder in use for V4.1.
  • Attention is not causal. cu_seqlens_vit splits the batch so that patches see only patches of the same image (deepinfer/model_executor/models/vision_encoder/vit.py:107-122).
  • Positions use a 2-D RoPE table. Each patch gathers the cos and sin of its row and of its column (deepinfer/model_executor/models/vision_encoder/vit.py:196-203).
  • On Ascend, an import hook replaces _flash_attn_fwd with a function that calls npu_fusion_attention (deepinfer/npu_ops/__init__.py:3-12, deepinfer/npu_ops/vit_attn.py:9-20). That kernel needs the segment ends as a host list. That is why the batch also carries vit_attn_cu_seqlens on NPU (deepinfer/ve/prepare_tensor_input_vl.py:131-133). See Hardware platforms: NVIDIA and Ascend.
  • The projector type must be downsample_mlp_gelu (deepinfer/model_executor/models/vision_encoder/mlp_projector.py:14). The HF loader sets depth 2 (deepinfer/hugging_face/config.py:225-233).
Deep dive

Chunks, cached prefixes and the image slices

_chunk_mm_metadata works on one sequence and one chunk [seqlen_k − seqlen_q, seqlen_k) (deepinfer/ve/prepare_tensor_input_vl.py:17-18, deepinfer/ve/prepare_tensor_input_vl.py:31-74):

  1. Slice the per-token tensors mm_token_type and images_seq_mask to the chunk.
  2. Find the images that overlap the chunk with two binary searches over the image start and end positions.
  3. No overlap: set every image key to None. The chunk is then text-only for the vision encoder.
  4. Else slice the per-image tensors, the raw bytes (with cu_raw_bytes) and the patch positions (with cu_image_patch_lens).

Because the scheduler never ends a chunk inside an image, an overlapping image is always inside the chunk. A chunk end that falls on the first token of an image is allowed; that image then goes to the next chunk.

Cached images. The mapper can replace a prefix of images that the KV cache already holds with plain text of the same length (deepinfer/model_executor/models/deepseek_vl.py:41-72). It reads _num_cached_tokens from the dict. In this release, _enqueue calls add(request_id, multi_modal_data) without num_cached_tokens, so the value is always 0 (deepinfer/engine/llm_engine.py:625, deepinfer/ve/multimodal_processor.py:248-255).

Deep dive

Memory and lifetime of the image data

  • The pool is DEEPINFER_MULTIMODAL_POOL_SIZE_GB (default 8) of shared host memory per rank, pinned for fast copies to the device (deepinfer/environ.py:207-210, deepinfer/shared_memory.py:360-363). The log line says how much memory all ranks of the node keep (deepinfer/ve/multimodal_processor.py:49-56).
  • When a prefill has read all tokens of a sequence, defer_expiring_pool_handles takes the pool blocks and records an event. The engine frees them in pre_sampler_sync of the same step, after the event (deepinfer/ve/schema.py:48-77, deepinfer/engine/llm_engine.py:118-119, deepinfer/engine/llm_engine.py:830-831).
  • An aborted request frees its blocks at once (deepinfer/engine/llm_engine.py:651-655, deepinfer/ve/schema.py:32-45).
  • The output queue holds at most DEEPINFER_MULTI_MODAL_BUFFER_SIZE (default 512) results. A full queue blocks the worker (deepinfer/ve/multimodal_processor.py:96).

Deep dive

Examples and the VL regression test

examples/images/ holds two pictures, carrots.jpeg and ribs.jpeg. The offline samples are two text-only prompts, one with one image, one with three images, and one 4-shot prompt with five images (examples/README.md:27-29, examples/_prompts.py:67-99). The README asks you to measure the PPL baselines again on NVIDIA and Ascend after a change to the images or questions.

The tests that cover the vision path:

  • tests/models/test_offline_inference.py: the offline regression with these five samples, compared to the PPL baselines in offline_decode_ppl.json (tests/models/test_offline_inference.py:19).
  • tests/models/test_ve_batch_invariant.py: runs only the image encoding and checks that each image gives bit-identical vectors in any batch (tests/models/test_ve_batch_invariant.py:1-13).
  • tests/engine/test_mm_overwrite_prompt.py and tests/ve/test_chunk_mm_metadata.py: the placeholder expansion and the chunk slicing.

What can go wrong#

  • More placeholders than images. The engine logs an error and keeps the extra placeholders as plain tokens (deepinfer/ve/multimodal_processor.py:118-124).
  • Wrong image_sizes. The token count comes from the declared size. If the real image has another size, the worker prints a warning and resizes it to the planned size (deepinfer/ve/processor/image_processor.py:292-299).
  • A broken image. The mapper raises in the worker, the worker sends None, and the engine aborts the request with an error log (deepinfer/ve/multimodal_processor.py:213-217, deepinfer/engine/llm_engine.py:942-945). With image_bytes=None, the request starts as FINISHED_VE_FAILED (deepinfer/engine/llm_engine.py:548-549, deepinfer/engine/llm_engine.py:603-604).
  • A hung worker. After DEEPINFER_MULTI_MODAL_WORKER_TIMEOUT seconds with no result, the engine process calls os.abort() (deepinfer/ve/multimodal_processor.py:264-275).
  • A tokenizer without a known image token. Start-up fails with AssertionError (deepinfer/ve/multimodal_processor.py:70-71).
  • An image longer than the token budget. The scheduler never cuts an image. If an image starts at the chunk start and has more tokens than max_num_batched_tokens, the shrink step gives a chunk of 0 tokens. With no other sequence in the batch, the TORCH_CHECK fails (csrc/engine/scheduler.hpp:488-501). This case needs chunked prefill: without it, max_num_batched_tokens must be at least max_model_len (deepinfer/config.py:209-212). This site derived this case from the code and did not run it. max_image_tokens limits the size of one image.

Why it matters. The image path changes the timing of every request, not only of image requests. Also, an image always enters the KV cache in one chunk, so chunks can be shorter than the token budget.

Check yourself#

  1. 1
    Does the decode step run the ViT?
    easy
    Show answer

    No. DeepseekVLForCausalLM.forward calls get_input_embeddings only when is_prompt is true (deepinfer/model_executor/models/deepseek_vl.py:232-233). After the prefill, the image is in the KV cache.

  2. 2
    Is E/P/D (separate vision-encoder machines) part of this release?
    easy
    Show answer

    No. The README lists "VE/Prefill/Decode disaggregation" under "not included in this release" (README.md:38-41). The vision encoder runs inside each engine's prefill.

  3. 3
    Why is the first id of an image vocab_size + 2 and the rest vocab_size + 1?
    medium
    Show answer

    The scheduler must find image boundaries in the id list. A chunk boundary can be just before an IMAGE id, but not just before an IMAGE_PAD id that follows one (csrc/engine/scheduler.hpp:214-230). The different first id marks where one image ends and the next one starts. The comment says the first token must be IMAGE to support chunked prefill (deepinfer/ve/multimodal_processor.py:89).

  4. 4
    With patch 14 and downsample ratio 3, how many prompt positions does a 640 × 480 image take, and how many of them get ViT vectors?
    hard
    Show answer

    The grid is 46 × 35 patches. Rounded up by 3, the LLM grid is 16 × 12 = 192 vectors. The positions are 12 × (16 + 1) + 2 = 206: 192 IMAGE, 12 NEW_LINE, one START and one END (deepinfer/ve/processor/image_processor.py:76-92, deepinfer/ve/processor/image_processor.py:232-235). Only the 192 IMAGE positions get ViT vectors; the 14 others get learned vectors.

  5. 5
    A text-only request arrives at an idle engine. Why can it not run its prefill in the same step in which it was added?
    hard
    Show answer

    It has a multimodal dict with empty image lists (not None), so it starts with schedulable = False (deepinfer/entrypoints/llm.py:158-159, csrc/engine/pybind_sequence.cpp:35). Only fetch() sets it, and fetch() runs after schedule() in each step (deepinfer/engine/llm_engine.py:885, deepinfer/engine/llm_engine.py:939-941). So the earliest prefill is in a later step, after the worker has answered.
