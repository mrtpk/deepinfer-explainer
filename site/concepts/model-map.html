Model map: DeepSeek-V4.1-Flash in DeepInfer

IntermediateDeepInfer conceptsabout 10 min read + 8 min deep dives

Code version: DeepInfer @ 9bd9cf2 · 2026-10-21

Before you read

This page uses ideas from these pages:

  • Inside a transformer Beginner
  • Attention, step by step Beginner
  • Mixture of Experts (MoE) Beginner

In one sentence

DeepInfer runs one model, DeepSeek-V4.1-Flash: an embedding, N decoder layers of attention and MoE with mHC mixing, and a final norm.

The idea#

DeepSeek-V4.1-Flash is a LLM with the usual transformer plan (see Inside a transformer). The embedding turns each token id into a hidden state. Then N decoder layers change the hidden states one after the other. A final norm ends the forward. The lm head turns the last hidden state into logits. In DeepInfer the sampler applies the lm head, not the forward.

Each decoder layer has two sub-layers:

  1. Attention. The token looks at earlier tokens. V4.1 uses MLA attention: one 512-value vector per token is both key and value. A layer can read keys from two sources. The first source is a sliding window of recent tokens. The second source is compressed keys: one per token or per 2 tokens. In sparse layers, an indexer selects only some of the compressed keys.
  2. MoE. A MoE block sends each token to a few experts. See MoE routing: the gate, top-k and the shared expert and Mega-MoE: the whole MoE layer in one call.

Between the sub-layers, V4.1 does not use a plain residual sum. It keeps hc_mult parallel copies of the residual stream and mixes them before and after each sub-layer. This is mHC.

Some features change the plan:

  • Layer kinds. The config gives each layer a compress ratio: 0 (sliding window only), 1 (C1) or 2 (C2).
  • YOCO. The layers from the first C1 layer to the end are "consumer" layers. Their compressed KV comes from one shared hidden state. When YOCO prefill truncation is on (default off), a long prefill computes only the last tokens in these layers.
  • Cross-layer sharing. A layer can reuse the compressed KV, the index keys or the top-k list of an earlier layer.
  • Optional parts. A DFlash draft head for speculative decoding, Engram n-gram memory in some layers, and the vision encoder for images.

An everyday comparison. Think of an assembly line with N stations. Each product (a token) passes every station in the same order. Each station has two machines: one compares the product with earlier products (attention), one sends it to a few specialists (MoE). The comparison stops here: in a real line, products do not look at each other. Also, here the product travels with several copies of itself (mHC), and a station can borrow a machine setting from an earlier station (sharing).

In the code#

Step 1: from config.json to the layer list#

The model loader reads the Hugging Face config.json. load_hf_model_config checks the architecture and the number formats, then builds the inference config gpt (deepinfer/hugging_face/config.py:237-311). The per-layer list comes from the config key compress_ratios:

  1. Line 152: ratio 0 gives a sliding-window spec; ratio 1 or 2 gives a compressed spec with an indexer config.
  2. Line 153: the lm head takes one entry, with no attention.
  3. Line 154: one spec for each DFlash layer.
  4. Line 161: n_prefill_layer is the index of the first ratio-1 layer. It is the first YOCO consumer layer (deep dive "YOCO producer and consumer layers").

V41Builder then makes the parameter containers in this order: the embedding, the N blocks, the main head, and the DFlash heads (deepinfer/model_executor/models/v4_modules/builder.py:105-125).

Step 2: three model classes#

The only registered architecture is DeepseekV41ForCausalLM. It maps to DeepseekVLForCausalLM (deepinfer/model_executor/models/__init__.py:15-17). The classes nest like this:

  • DeepseekVLForCausalLM (deepseek_vl.py) adds the vision path. In every prefill (also text-only) it computes the input embeddings itself, adds image features when the batch has images, and passes them on (deepinfer/model_executor/models/deepseek_vl.py:226-234).
  • DeepseekForCausalLM (deepseek.py) holds the inner model, the lm head, the sampler, the DFlash module and the expert load balancer (deepinfer/model_executor/models/deepseek.py:251-321).
  • DeepseekModel (deepseek.py) holds the embedding, the N layers and the final norm (deepinfer/model_executor/models/deepseek.py:59-116), and runs the forward (deepinfer/model_executor/models/deepseek.py:154-248).

Step 3: the forward loop#

Without input hidden states, the forward starts with the embedding. One CrossLayerRuntime object goes through all layers. A source layer writes shared values into it, and later layers read them (deepinfer/model_executor/models/v4_modules/cross_layer.py:276-308). Then the loop runs the layers:

Lines 191-207 run only in a prefill with YOCO truncation, at the first consumer layer. Lines 210-218 call one layer with its own slice of the KV cache, kv_caches[i]. Each layer returns the new hidden states and the residual data for mHC.

Step 4: one decoder layer#

DeepseekDecoderLayer.forward is short. Without the timers and the YOCO boundary, it is four calls:

  1. Line 143: attn_norm_forward finishes the mHC post mix of the previous sub-layer, mixes the copies into one attention input, and normalizes it. It returns FP8 values and a BF16 copy.
  2. Lines 155-161: V4Attention (MLA attention: one latent vector per token).
  3. Line 162: ffn_norm_forward does the same mHC work around the MoE input.
  4. Lines 169-173: DeepseekMoE (MoE routing: the gate, top-k and the shared expert).

The page models/decoder_layer.py: one decoder layer reads the file line by line, and the tour Tour: Inside one decoder layer follows one token through it.

Step 5: the end of the forward#

The last layer leaves the residual stream as hc_mult copies. Line 227 does the last mHC post mix. With hc_shifted (the HF default is True, deepinfer/hugging_face/config.py:295), line 230 mixes the copies into one. Without it, the HCHead does this (line 238). Line 239 is the final RMSNorm. The forward returns these hidden states. The sampler applies lm_head.weight later, only to the rows that it samples (deepinfer/model_executor/models/deepseek.py:391-400).

Step 6: where each piece lives#

The file v4_modules/__init__.py sorts the model files into four roles: parameter containers, runtime adapters, tensor operators, and topology (deepinfer/model_executor/models/v4_modules/__init__.py:6-20). This table maps each part of the model to its concept page and its files:

Deep dive

DeepseekModel.forward, line by line

  1. Lines 161-162. The text path embeds the ids. The VL class passes its own hidden states in every prefill, also a text-only one (deepinfer/model_executor/models/deepseek_vl.py:232-233). So with the VL class, these lines run only in decode.
  2. Line 166. One CrossLayerRuntime per forward. Translated comment: "Runtime values held across layers (shared_hidden / pre_rope_kv / topk): pass the same reference layer by layer; each layer writes in place."
  3. Lines 168-170. Prefill with context parallelism: reorder the tokens into the mirror-CP layout (see Context parallelism (mirror CP)).
  4. Lines 173-174. DFlash on: allocate dflash_input [T, hidden × number of target layers]. The assert says the target layer list and the MTP head type must match.
  5. Lines 180-188. Engram on: hash the n-grams of the batch once; fetch returns one hook per Engram layer.

Then the loop (lines 190-218, Step 3 above), and the end:

  1. Lines 220-223. DFlash writes its main cache from dflash_input. Translated comment: "the target-layer features are consumed only here; in decode this is captured in the main model's CUDA graph."
  2. Lines 225-239. Final mHC mix and output_norm (Step 5 above).
  3. Lines 241-244. Prefill with CP: all-gather the hidden states and put them back in the original token order.
  4. Line 246. Return CausalLMForwardOutput(hidden_states=...).

Deep dive

YOCO producer and consumer layers

YOCO splits the main layers into two halves:

The HF loader sets n_prefill_layer to the index of the first layer with ratio 1 (deepinfer/hugging_face/config.py:158-161). By line 21, that layer is the first consumer. V4Attention agrees: is_first_yoco_consumer_layer is true when layer_idx == n_prefill_layer (deepinfer/model_executor/models/v4_modules/attn.py:247).

The docstring and the code do not agree

The docstring of _n_prefill_layer says: "it and everything before it form the prefill side, the layers after it are yoco consumer layers" (deepinfer/hugging_face/config.py:159). The code treats that layer as a consumer. This site describes the code.

What changes in a consumer layer. In a KV-source consumer layer, the compressed KV is projected from the shared hidden state, not from the layer's own hidden state (deepinfer/model_executor/models/v4_modules/attn.py:345-352). The shared hidden state is the attention-norm output of the first consumer layer (deepinfer/model_executor/models/decoder_layer.py:146-152). The deployment notes describe the same design: "the decoder layers' block KV cache is projected from the last encoder layer's hidden state" (doc/inference_deployment_qa.md:187).

With DEEPINFER_YOCO_PREFILL_TRUNCATION_MODE set to mask or compact (default off, deepinfer/environ.py:188), a prefill keeps only the last DEEPINFER_YOCO_PREFILL_KEEP_TOKENS query tokens in the consumer layers. The README uses 140 (README.md:25). The page YOCO and SWA bounded replay explains this.

Deep dive

Cross-layer sharing maps, with a worked example

The config lists the source layers. _source_map maps every layer from the first source onward to the nearest source at or before it:

Worked example. kv_source_layer_ids = [2, 5] and N = 8 give {2: 2, 3: 2, 4: 2, 5: 5, 6: 5, 7: 5}. Layers 0 and 1 are not in the map, so they use their own KV. Layers 3 and 4 reuse the compressed KV of layer 2; the cache engine gives them the same ca_cache view (deepinfer/worker/cache_engine.py:448-449).

SharedLayerTopology checks the maps at start-up: segments must be contiguous, index-topk segments must lie inside index-K segments, and those inside KV segments (deepinfer/model_executor/models/v4_modules/cross_layer.py:36-47). Share-KV must not cross the YOCO boundary (deepinfer/model_executor/models/v4_modules/cross_layer.py:114-116). The page Cross-layer KV sharing explains the maps.

Deep dive

The optional parts: DFlash, Engram, VL

DFlash draft head. DeepseekForCausalLM builds DFlash when DEEPINFER_USE_NEXTN_DECODE is not 0 (default 5) (deepinfer/model_executor/models/deepseek.py:276, deepinfer/model_executor/models/deepseek.py:300-306). The DFlash layers come after the lm head in the module list (deepinfer/model_executor/models/mtp/dflash.py:92-95). In the main forward, the layers in dspark_target_layer_ids write a feature row into dflash_input (deepinfer/model_executor/models/decoder_layer.py:144-145). After the loop, update_main_cache turns these features into the DFlash KV. The sampler then runs the drafts. See Speculative decoding.

Engram. The layers in engram_layer_ids get an Engram module (deepinfer/model_executor/models/decoder_layer.py:80-83). It works as a hook inside the attention norm step: after the mHC post mix, it changes the residual stream (deepinfer/model_executor/models/decoder_layer.py:111-118). Engram tables can live in CPU memory: DEEPINFER_ENGRAM_FORCE_GPU_STORAGE moves them to the device, and it is always on with DEEPINFER_ACCELERATOR=ascend (deepinfer/environ.py:147, deepinfer/model_executor/models/deepseek.py:473-477). See Engram n-gram memory.

Vision. In a prefill with images, get_input_embeddings embeds the ids and lets the vision-language tuner put image features into the image-token rows (deepinfer/model_executor/models/deepseek_vl.py:194-224). Decode never runs the vision encoder. See Vision encoder (VL).

EPLB. The constructor puts the MoE layers of the main model and of DFlash into groups with the same weight layout. It makes one expert load balancer per group (deepinfer/model_executor/models/deepseek.py:310-317, deepinfer/model_executor/models/deepseek.py:331-364). See Expert load balancing (EPLB).

What can go wrong#

  • Wrong checkpoint. The loader accepts one architecture name, model_type == "deepseek_v41", BF16 parameters, FP8 weights with 32 × 32 blocks and FP4 experts. Anything else raises ValueError (deepinfer/hugging_face/config.py:241-262).
  • No vision config. Only multimodal HF models are supported; the loader asserts vl_aligner (deepinfer/model_config_loader.py:21-22).
  • Unsupported ratio. A compress ratio other than 0, 1 or 2 raises ValueError (deepinfer/model_executor/model_metadata_utils.py:52-53).
  • No C1 layer. _n_prefill_layer uses next(...) with no default, so a config without a ratio-1 layer raises StopIteration (deepinfer/hugging_face/config.py:160-161).
  • Bad sharing maps. SharedLayerTopology asserts at start-up. A consumer layer without layer_info_shared_cfg fails on purpose: without the check, it would silently read a cache that nobody writes (deepinfer/model_executor/models/v4_modules/cross_layer.py:106-112).
  • YOCO truncation on a model without consumers. With the mode not off, ModelMetadata asserts that YOCO is on and that the keep-token count is above 0 (deepinfer/model_executor/model_metadata_utils.py:90-92).
  • DFlash and the drafts disagree. The forward asserts that a DFlash module exists exactly when target layers are set (deepinfer/model_executor/models/deepseek.py:173).

Why it matters. The model map tells you which page to read for a question. A question about memory leads to the layer kinds and the caches. A question about speed in long prompts leads to the indexer and YOCO. A question about a wrong output leads to the config checks above.

Check yourself#

  1. 1
    Which two sub-layers does each decoder layer run, and in which order?
    easy
    Show answer

    Attention (V4Attention), then MoE (DeepseekMoE). mHC mixing and a norm come before each one (deepinfer/model_executor/models/decoder_layer.py:143-173).

  2. 2
    Does DeepseekForCausalLM.forward return logits?
    easy
    Show answer

    No. It returns hidden states in CausalLMForwardOutput (deepinfer/model_executor/models/deepseek.py:246-248). The sampler applies lm_head.weight in sample() (deepinfer/model_executor/models/deepseek.py:392-400).

  3. 3
    The config has compress_ratios = [0, 0, 2, 2, 1, 2, 1, 2] for 8 main layers (no draft layers). What is n_prefill_layer, and which layers are YOCO consumers?
    medium
    Show answer

    The first ratio-1 layer is layer 4, so n_prefill_layer = 4 (deepinfer/hugging_face/config.py:158-161). Consumers are layers 4 to 7: n_prefill_layer ≤ i < N (deepinfer/model_executor/models/v4_modules/yoco.py:19-21). Layer 4 itself is the first consumer, although the docstring says otherwise.

  4. 4
    Which file allocates the attention weights, and which file runs the attention? Why are they separate?
    medium
    Show answer

    mla_attn.py allocates them (a parameter container); attn.py runs the forward (a runtime adapter). Containers keep the Hugging Face names, shapes and dtypes for loading; runtime files convert them to the layout that the kernels need (deepinfer/model_executor/models/v4_modules/__init__.py:6-15).

  5. 5
    With kv_source_layer_ids = [1, 4] and N = 6, which layers have their own compressed KV cache? Which layers write to the cache of layer 1?
    hard
    Show answer

    _source_map gives {1: 1, 2: 1, 3: 1, 4: 4, 5: 4} (deepinfer/hugging_face/config.py:62-65). Layer 0 is not in the map, so it is its own source. Own caches: layers 1 and 4, and also layer 0 if layer 0 is a compressed layer (a ratio-0 layer has no compressed cache). Layers 2 and 3 get the ca_cache view of layer 1 (deepinfer/worker/cache_engine.py:448-449), but only the source layer 1 writes it: a consumer has no PackedWkv (deepinfer/model_executor/models/v4_modules/mla_attn.py:252-269). This is in the deep dive "Cross-layer sharing maps".

Related pages

  • MLA attention: one latent vector per tokenIn DeepInfer's MLA, all query heads of a layer read one 512-value vector per token. This vector is the key and also the value, so the KV cache keeps one small entry per token.
  • Sparse attention with an indexerIn a sparse layer, a small indexer scores all compressed keys for each query and keeps the best index_topk. The main attention then reads only those keys plus the sliding window.
  • Sliding-window attentionEvery attention layer of DeepSeek-V4.1-Flash reads the most recent tokens (a window of 128 in the docs) from a ring of 134 slots per sequence and layer. This page shows the ring, the decode and prefill index paths, and how the window joins the compressed keys.
  • KV compression (C1 and C2)A compressed layer stores one 512-value cache entry per token (C1) or per 2 tokens (C2). C2 mixes the two tokens with a learned softmax gate and keeps the score and latent of the most recent tokens in a small fp32 state ring. Entries are FP4 (288 B) by default, or FP8 (528 B).
  • Cross-layer KV sharingA layer can reuse the compressed KV, the indexer keys or the top-k list of an earlier source layer. SharedLayerTopology turns three lists of source layers from config.json into checked segment maps; the cache engine then allocates the compressed-KV and index-K caches only for source layers.
  • YOCO and SWA bounded replayYOCO splits the main layers into producer and consumer layers. Consumer layers project their compressed KV from one shared hidden state. With the optional prefill truncation (README feature "Decoder SWA bounded replay"), a prefill computes the consumer layers only for the last KEEP_TOKENS prompt tokens (140 in the README), with the window cut at that range. Only their compressed KV still covers every token.
  • mHC residual mixingDeepSeek-V4.1 keeps the residual stream as hc_mult parallel streams. Before each sub-layer, learned weights mix the streams into one input. After it, the output goes back into all streams. The model ends with one fold.
  • MoE routing: the gate, top-k and the shared expertIn each MoE layer, a gate scores every expert for every token. DeepInfer sends each token to its top-k routed experts and to one shared expert, and maps each choice to a physical expert slot.
  • Mega-MoE: the whole MoE layer in one callInside one NVLink domain, DeepInfer replaces dispatch, the expert GEMMs, the shared expert and combine with one DeepGEMM mega-MoE call that works on a symmetric buffer. The choice is fixed per layer at start-up.
  • Engram n-gram memoryEngram gives some decoder layers a large learned table. Each token hashes its last few tokens (its n-grams) to rows of that table, and the layer adds those rows to its hidden states. The table is split across the ranks of the enp group.
  • Vision encoder (VL)DeepInfer reads images in the prefill of the same engine. A worker process prepares each image, the scheduler keeps whole images in one chunk, and a ViT plus a projector turn the pixels into vectors at the image-token positions of the prompt.
  • models/deepseek.py: the DeepSeek-V4.1 modeldeepseek.py holds DeepseekModel (embedding, N decoder layers, final mix and norm) and DeepseekForCausalLM (lm head, sampler, DFlash, EPLB, weight loading). The forward returns hidden states.
  • models/decoder_layer.py: one decoder layerdecoder_layer.py holds DeepseekDecoderLayer (one main-model layer: mHC, attention, mHC, MoE, plus the Engram, YOCO and DFlash hooks) and DFlashDecoderLayer (one draft-model layer).
  • Tour: Inside one decoder layerFollow 192 tokens of one decode step through one decoder layer, in 10 stops: inputs, hooks, mHC post and pre, the DFlash copy, attention, mHC again, the gate, the experts, and the way out. Shapes at every stop.
