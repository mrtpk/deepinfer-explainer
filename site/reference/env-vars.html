Environment variables

IntermediateReferenceabout 31 min read + 11 min deep dives

Code version: DeepInfer @ 9bd9cf2 · 2026-10-21

In one sentence

DeepInfer reads each DEEPINFER_* setting from the process environment one time, on first use, through the class envs in deepinfer/environ.py.

Use this page in two ways. To learn the mechanism, read the first four sections. To look up one variable, go to All DEEPINFER variables, or search for its name. The variable tables are made by the script tools/gen_env_vars.py from environ.py. The "What it does" text is written by hand from the code that reads each variable.

What an environment variable is#

An environment variable is a named text value that a process gets from its parent when it starts. In a shell, you set one for all later commands with export, or for one command only:

export DEEPINFER_ACCELERATOR=nvidia          # for this shell and all programs it starts
DEEPINFER_ENFORCE_EAGER=1 python3 examples/offline_inference.py   # for one command only

In Python, the process environment is the dict os.environ. os.getenv("NAME") returns the text, or None when the variable is not set. A child process gets a copy of the environment of its parent. A change in the parent after the child starts does not reach the child.

Environment variables are always text. A program must parse the text into a number, a flag or a path. DeepInfer does this in one place, deepinfer/environ.py. The file defines one class, envs, with one attribute for each variable:

Other code reads a value as envs.DEEPINFER_NCCL_NUM_SMS, for example in deepinfer/platform.py:81. The package exports envs at the top level, so from deepinfer import envs works (deepinfer/__init__.py:6).

59 variables in 16 groups

environ.py declares 59 variables. Comments such as # -- MTP -- put them in 16 groups. This page uses the same groups. Five more DEEPINFER_* names are read directly with os.getenv or std::getenv, outside environ.py. They are in a separate table.

How DeepInfer reads a variable#

The EnvVar descriptor#

Each attribute of envs is an EnvVar object. EnvVar is a descriptor: a Python object in a class that controls what an attribute read returns. When code reads envs.X and X is still a descriptor, Python calls X.__get__. This is the whole mechanism:

  1. Class definition (lines 40-42). Python calls __set_name__ for each attribute when it makes the class envs. The descriptor remembers its name, for example "DEEPINFER_NCCL_NUM_SMS". It also adds itself to the module dict _descriptors.
  2. First read (lines 49-50). envs.DEEPINFER_NCCL_NUM_SMS calls __get__. It reads os.getenv(self.name) and gives the text to its parse function init.
  3. Cache (line 56). setattr(owner, self.name, value) puts the parsed value, for example the int 32, into the class. The descriptor is now gone from the class dict.
  4. Later reads. The attribute is now a plain int. Python returns it directly and does not call any function. So a later change of os.environ has no effect on envs.

So a read after the first one costs the same as a normal class attribute. And the code never parses a variable that no code reads, so a bad value in it gives no error.

Simplified

"The first read caches the value" is true for each process. DeepInfer starts its extra workers with SpawnProcess (deepinfer/engine/llm_engine.py:389-395, deepinfer/logger.py:169-170). A spawned process is a new Python interpreter, so it has its own envs class and reads the environment again. It reads the environment that it got from its parent at start.

Four variables use their own parse function. DEEPINFER_GLOO_TIMEOUT makes a timedelta. DEEPINFER_MAX_BACKTRACKING_TOKENS and DEEPINFER_ENGRAM_FORCE_GPU_STORAGE read another variable. DEEPINFER_DFLASH_CONFIDENCE_HEAD_TEMPERATURE accepts a comma-separated list (deepinfer/environ.py:110, deepinfer/environ.py:132-147). The deep dive Derived variables reads them.

Errors name the variable. If the parse fails, lines 51-55 raise the same exception type again, with the variable name in front. For example, DEEPINFER_NCCL_NUM_SMS=abc gives ValueError: DEEPINFER_NCCL_NUM_SMS: invalid literal for int() with base 10: 'abc'. If the exception type cannot take one text argument, the original exception is raised.

When DeepInfer reads a variable#

A value is fixed at the first read in each process. So the important question is: when is the first read? There are three cases.

  1. At import time. Some code reads envs.X at the top level of a module, in a class body, or in the default value of a function argument. Python runs this code at import time. The import-time table lists every such read.
  2. At first use. Most reads are inside functions. The first call fixes the value, for example when the engine builds its config or a worker builds the model.
  3. In C++. Two variables are read by the C++ extension with std::getenv, separately from envs: DEEPINFER_USE_NEXTN_DECODE (csrc/engine/utils.hpp:36-40) and DEEPINFER_CPP_LOG_LEVEL (csrc/utils/log.hpp:19-31).

Set variables before you import deepinfer#

Set the environment first, then import

Set all DEEPINFER_* variables and the visible-device variables before import deepinfer and before import torch. A value that you set later can be ignored without an error.

The example scripts follow this rule. The module docstring of examples/_config.py says so:

create_llm sets the environment, then the visible devices, and only then imports torch and DeepInfer:

There are three reasons for this order:

  • import deepinfer reads DEEPINFER_ACCELERATOR. The package calls _so_platform_tag() at module level to find its compiled extension folder (deepinfer/__init__.py:15, deepinfer/__init__.py:30-32).
  • Device runtimes read the visible devices once. After CUDA or the Ascend runtime starts, a new CUDA_VISIBLE_DEVICES or ASCEND_RT_VISIBLE_DEVICES has no effect. For this reason, import deepinfer sets PYTORCH_NVML_BASED_CUDA_CHECK=1 (deepinfer/__init__.py:37-39), and PLATFORM is made only on first use (deepinfer/__init__.py:58-59).
  • Some modules read variables at import time (next table).

Variables read at import time#

The script found these reads with Python's ast module: each envs.X outside a function body. The table also lists DEEPINFER_ACCELERATOR. A function reads it, but deepinfer/__init__.py calls that function at module level (deepinfer/__init__.py:30). For these variables, the value at the time of the module import counts. A later rearm does not change values that the module already copied, for example the default argument prefill_attempt_interval of SchedulerConfig.__init__.

Values that the code changes at run time#

Some code changes a value after start-up. It uses one of three methods.

1. os.environ.setdefault plus rearm. EngineArgs chooses a default that depends on the engine type. Then it calls environ.rearm, which puts the descriptor back, so the next read parses the new text:

So DEEPINFER_ZERO_OVERHEAD_SCHEDULING is False in environ.py, but it is on for NORMAL and COMPLETION engines (deepinfer/engine/engine_type.py:15-17). DEEPINFER_USE_MULTIMODAL_POOL is on for all engines except COMPLETION. Your own exported value wins, because setdefault does not overwrite.

2. Direct assignment to envs. envs.X = value replaces the class attribute. The profile run sets DEEPINFER_FORCE_IMBALANCE_RATIO to 1.8 and then back to 0.0 (deepinfer/worker/model_runner.py:509-512). The EP buffer writes the calculated SM count into DEEPINFER_USERBUFFER_COMM_SMS (deepinfer/model_executor/parallel_utils/userbuffer.py:86-90). These assignments do not change os.environ, so child processes and C++ do not see them.

3. Tests. pytest runs many tests in one process. Without help, the first test that reads a variable fixes it for all later tests. An autouse fixture in tests/conftest.py restores os.environ after each test and calls rearm_all():

Some tests change envs directly with the pytest monkeypatch fixture. A comment in tests/worker/test_state_cache_ops.py explains a trap: monkeypatch.setattr first reads the old value, and that read replaces the descriptor. So the undo restores a plain value, not the descriptor. The test depends on rearm_all() in the autouse fixture, which runs after the undo (tests/worker/test_state_cache_ops.py:93-97). The same test must also clear an lru_cache that keeps old results (tests/worker/test_state_cache_ops.py:102-103, deepinfer/worker/cache_engine.py:130-138).

DEEPINFER_YOCO_PREFILL_TRUNCATION_MODE=compact

DEEPINFER_BATCH_INVARIANT=1 DEEPINFER_ENABLE_MTP_VARLEN=0   # and a fixed seq_seed in SamplingParams

Source: README.md:28. The README does not give the reason for MTP_VARLEN=0. The code shows one batch dependency. One variable end to end: DEEPINFER_USE_NEXTN_DECODE

This variable sets the maximum number of draft tokens for each request in one decode step. A draft token is a guess for a later token. The model checks all guesses in one step (speculative decoding, see Speculative decoding). We follow the value 3 from the shell to every place that uses it. The example uses max_num_seqs = 4, max_model_len = 32768 and ZOS on.

Deep dive

EnvVar.__get__ in detail: lock, cache check and errors

  1. Line 45. Each descriptor has its own threading.Lock (line 38). Two threads that read the same variable at the same time parse it only once.
  2. Lines 46-48. The thread that waited for the lock looks in owner.__dict__. If the first thread already stored the value, the entry is not the descriptor any more, and line 48 returns the stored value. Normal reads after the first one do not reach this code, because the class attribute is no longer a descriptor.
  3. Line 50. os.getenv returns None when the variable is not set. The parse function uses the default only for None. An empty text is a value: DEEPINFER_NCCL_NUM_SMS= calls int("") and raises ValueError.
  4. Lines 51-55. The error message gets the variable name in front. raise ... from e keeps the original traceback. If the exception class cannot take one text argument, the original exception is raised again.
  5. Line 56. setattr on the class stores the value for all readers in this process.

Why a non-data descriptor. EnvVar has __get__ but no __set__. So envs.X = 5 replaces the class attribute and does not call the descriptor. The code uses this for run-time changes (see Values that the code changes at run time). __slots__ on line 34 keeps each descriptor small: it has only name, init and lock.

Class, not instance. Nobody makes an instance of envs. All reads use the class, so instance is always None and owner is envs.

Deep dive

Derived variables: values that read other variables

Four definitions use their own parse function. Three of them read another variable, so the order of the first reads matters.

  • DEEPINFER_MAX_BACKTRACKING_TOKENS is max(_int(v), DEEPINFER_USE_NEXTN_DECODE + 1). Unset, with the default 5 draft tokens, it is max(0, 6) = 6. The value 1 that examples/benchmark.py sets is raised to 6 too (examples/benchmark.py:164). A comment in the YOCO script says the same (examples/yoco/yoco_equiv.py:473). So this variable can only make the rollback space larger.
  • DEEPINFER_DFLASH_CONFIDENCE_HEAD_TEMPERATURE is a decorated function, not an assignment. Without a comma, the result is one float. With commas, it is a tuple, and its length must equal DEEPINFER_USE_NEXTN_DECODE. With 5 draft tokens, "1.0,1.0,0.9" raises ValueError: DEEPINFER_DFLASH_CONFIDENCE_HEAD_TEMPERATURE: has 3 elements ('1.0,1.0,0.9') but DEEPINFER_USE_NEXTN_DECODE=5. ConfidenceHead makes one temperature for each draft step and clamps each value to at least SAMPLING_EPS (deepinfer/model_executor/models/mtp/dflash.py:62-64).
  • DEEPINFER_ENGRAM_FORCE_GPU_STORAGE is _bool(v) or DEEPINFER_ACCELERATOR == "ascend". So on an Ascend build you cannot turn it off: Engram tables always go to device memory. On NVIDIA it is off by default, and the Engram parameters stay in CPU memory (deepinfer/model_executor/models/deepseek.py:473-477).
  • DEEPINFER_GLOO_TIMEOUT parses a float number of seconds and makes timedelta(seconds=...). The default 14400 seconds is 4 hours (deepinfer/environ.py:110).

Deep dive

Prefill vote points with real numbers (70 and 100)

In a NORMAL engine with data parallelism, all DP ranks must do the same kind of step: all prefill or all decode. The C++ scheduler counts decode steps in decode_step. A prefill step sets it back to 0. At some steps the ranks vote with an all-reduce:

  1. Line 308: an ANY point is each multiple of prefill_any_attempt_interval (default 100), but not step 0.
  2. Line 309: an ALL point is each multiple of prefill_attempt_interval (default 70), and also step 0.
  3. Line 313: a rank "wants" prefill if its KV cache usage is at or below a watermark and a prefill request waits.
  4. Line 316: at an ANY point, one rank that wants prefill is enough. When a step is both an ANY and an ALL point, the ANY rule applies (csrc/engine/scheduler.hpp:303).
  5. Line 318: at an ALL point, every rank must want prefill.

Use the defaults, with no prefill in between. Then the ranks vote at these decode steps: 0 (ALL), 70 (ALL), 100 (ANY), 140 (ALL), 200 (ANY), 210 (ALL), 280 (ALL), 300 (ANY) ... 700 (ANY, also an ALL point). So if only one rank has a request in its queue, that request waits at most 100 decode steps.

Set the interval variables before deepinfer.config is imported

Both values are default arguments of SchedulerConfig.__init__ (deepinfer/config.py:193-194). Python computes them when it imports deepinfer.config. A value that you set after that import has no effect, and rearm does not help. Both must be at least 1 (deepinfer/config.py:213-216, csrc/engine/scheduler.hpp:105-108).

Deep dive

CUDA graph batch sizes with real numbers

A CUDA graph records the kernels of one decode step for one batch size. The engine pads each batch to the next captured size. build_graph_batch_sizes chooses the sizes:

  • Offline example: max_num_seqs = 4 (examples/offline_inference.py:54) and 5 draft tokens give a maximum of 4 * 6 = 24. With the default interval 8: [1, 2, 4, 8, 16, 24].
  • Benchmark: it sets the interval to 32 (examples/benchmark.py:169). Assume a maximum of 384, for example 64 sequences with 5 draft tokens. Then the 17 sizes are 1, 2, 4, 8, 16, 32, 64, ..., 352, 384.
  • DFlash graphs use DEEPINFER_DFLASH_CUDAGRAPH_BATCH_SIZE_INTERVAL with the maximum max_num_seqs (deepinfer/worker/dflash_cuda_graph_runner.py:36).

A smaller interval makes more graphs. Each graph costs capture time and memory, but it gives less padding. DEEPINFER_ENFORCE_EAGER=1 makes no graphs. The PROMPT engine never uses graphs (deepinfer/worker/model_runner.py:73).

Deep dive

EPLB variables together, with real numbers

Five variables control expert load balancing (EPLB). The example scripts set them as a group (examples/_config.py:77-83):

DEEPINFER_OVERRIDE_NUM_EXTRA_EXPERTS=32           # setdefault, if set_override_experts
DEEPINFER_EXPERT_COUNT_WINDOW_SIZE=3              # always
DEEPINFER_EXPERT_REARRANGEMENT_STEP_INTERVAL=30   # only with EPLB on
DEEPINFER_REARRANGE_AFTER_PREFILL_IN_NORMAL_ENGINE=1   # only with EPLB on
  1. Redundant experts. resolve_num_extra_experts adds padding so that routed plus extra experts divide by the EP size (deepinfer/model_executor/eplb/__init__.py:21-28). Assume 256 routed experts (a number for this example only), 32 extra and EP size 24: -(256 + 32) % 24 = 0, so 32 stays. With EP size 20: -(288) % 20 = 12, so the loader uses 44 and logs a warning (deepinfer/model_executor/model_loader.py:95-99).
  2. Window. The balancer keeps a ring of the last 3 steps of token counts, as an int tensor [window, num_moe_layers, num_local_physical_experts] (deepinfer/model_executor/eplb/__init__.py:113-119). The default 100 needs more memory, which is why the examples use 3.
  3. Interval. With interval 30, the step counter starts at 30 - max(1, 30 // 4) = 23. So the first rearrangement comes after 7 steps, then one every 30 steps (deepinfer/model_executor/eplb/__init__.py:121-123, deepinfer/model_executor/eplb/__init__.py:161-165). The window (3) must be between 1 and the interval (30), or the constructor raises ValueError (deepinfer/model_executor/eplb/__init__.py:106-111).
  4. After prefill. In a NORMAL engine, a prefill step sets the counter to interval - 1. The next decode step reaches the interval and rearranges (deepinfer/model_executor/eplb/__init__.py:156-159).
  5. Statistics. Independent of rearrangement, every 128 steps (DEEPINFER_MOE_LB_STAT_INTERVAL) the EP ranks all-gather an int64 tensor [ep_size, 128, num_moe_layers] and compute mean and maximum tokens per rank (deepinfer/model_executor/eplb/__init__.py:181-193).

With an EP size of 1, step() returns at once, and none of this runs (deepinfer/model_executor/eplb/__init__.py:133-134). See Expert load balancing (EPLB).

Deep dive

Automatic SM count for DeepEP (DEEPINFER_USERBUFFER_COMM_SMS=0)

With the default 0, the code asks DeepEP for a theoretical SM count. It keeps min(32, device_sms // 4) SMs free for compute, and takes the smaller value. For example, on a device with 148 SMs, compute_num_sms = min(32, 37) = 32, so DeepEP gets at most 116 SMs. Line 90 writes the result into envs. Later dispatch and combine calls read it from there (deepinfer/model_executor/models/v4_modules/mlp.py:471, deepinfer/model_executor/models/v4_modules/mlp.py:504). Only envs changes, not os.environ.

The shared-expert MLP runs inside limit_num_sms(envs.DEEPINFER_USERBUFFER_COMM_SMS, enabled=PLATFORM.is_gpu) while combine runs (deepinfer/model_executor/models/v4_modules/mlp.py:600-603). This site does not explain the inside of DeepEP.

What can go wrong#

"off" means on

A bool variable is False only for 0, an empty text, false and False (deepinfer/environ.py:12-13). DEEPINFER_BATCH_INVARIANT=off or =no turns the feature on. Use 0 and 1.

  • The value is set too late. After the first read, a process ignores changes to os.environ (deepinfer/environ.py:56). For import-time reads, the module import is the first read. No error tells you this. Set variables before import deepinfer.
  • Empty text for a number. export DEEPINFER_NCCL_NUM_SMS= gives ValueError, not the default, because only an unset variable uses the default (deepinfer/environ.py:16-17). Use unset to go back to the default.
  • Wrong case for a choice. DEEPINFER_YOCO_PREFILL_TRUNCATION_MODE=Compact raises ValueError: ... 'Compact', must be one of ('off', 'mask', 'compact') (deepinfer/environ.py:90-91).
  • YOCO keep tokens too small. With truncation on, KEEP_TOKENS must be above 0 and at least window_size + DEEPINFER_MAX_BACKTRACKING_TOKENS. Otherwise an AssertionError stops start-up (deepinfer/model_executor/model_metadata_utils.py:92, deepinfer/worker/model_runner.py:110-113).
  • Temperature list with the wrong length. The list for DEEPINFER_DFLASH_CONFIDENCE_HEAD_TEMPERATURE must have DEEPINFER_USE_NEXTN_DECODE values (deepinfer/environ.py:140-141).
  • EPLB window larger than the interval. With rearrangement on, DEEPINFER_EXPERT_COUNT_WINDOW_SIZE must be from 1 to the interval. The default window 100 with an interval of 30 raises ValueError (deepinfer/model_executor/eplb/__init__.py:106-111).
  • A change in Python only. envs.X = value does not change os.environ. The C++ scheduler reads DEEPINFER_USE_NEXTN_DECODE from the environment (csrc/engine/scheduler.hpp:118). Spawned workers also read the environment. Change the environment, not envs, if other processes or C++ must see the value.
  • CUDA_VISIBLE_DEVICES not set. The engine reads it with os.environ[...] and stops with KeyError (deepinfer/engine/llm_engine.py:188). The example scripts set it for you (examples/_config.py:55-63).
  • Cached results in tests. get_inference_compress_block_size has an lru_cache. After you change DEEPINFER_MAX_BACKTRACKING_TOKENS, call clear_compress_block_size_cache() (deepinfer/worker/cache_engine.py:130-138).
  • Docs and code differ. examples/README.md says that DEEPINFER_OVERRIDE_NUM_EXTRA_EXPERTS defaults to 32 (examples/README.md:63). The default in environ.py is 0 (deepinfer/environ.py:114). The value 32 comes from the example scripts, only when the caller passes set_override_experts=True (examples/_config.py:77-79). benchmark.py always passes True (examples/benchmark.py:161). offline_inference.py passes True only with EPLB on (examples/offline_inference.py:35-40). In your own code, the default is 0 redundant experts.

Why it matters. A wrong variable rarely gives an error. It changes speed, memory or results without a message. When a run behaves in an unexpected way, print the values that the process really uses: {k: getattr(envs, k) for k in environ._descriptors}. This forces the first read of every variable in that process, so do it after the start-up code has set the environment.

Check yourself#

  1. 1
    You run DEEPINFER_ENFORCE_EAGER=false python3 my_script.py. Does DeepInfer capture CUDA graphs? And with DEEPINFER_ENFORCE_EAGER=no?
    easy
    Show answer

    Assume a NORMAL engine (the PROMPT engine never captures graphs). With false: yes, it captures graphs. "false" is one of the four false texts. With no: no graphs. _bool treats every other text as true, so eager mode is on (deepinfer/environ.py:12-13, deepinfer/worker/model_runner.py:73).

  2. 2
    What is the default of DEEPINFER_ZERO_OVERHEAD_SCHEDULING in environ.py? Is ZOS on when you make an LLM with the default engine type and you set nothing?
    easy
    Show answer

    The default in environ.py is False (deepinfer/environ.py:179). But EngineArgs.__post_init__ calls os.environ.setdefault("DEEPINFER_ZERO_OVERHEAD_SCHEDULING", "1") for NORMAL and COMPLETION engines and then rearm (deepinfer/engine/arg_utils.py:51-55). The default engine type is NORMAL (deepinfer/engine/arg_utils.py:41), so ZOS is on.

  3. 3
    A script imports deepinfer.config, then sets os.environ["DEEPINFER_PREFILL_ATTEMPT_INTERVAL"] = "10" and calls environ.rearm("DEEPINFER_PREFILL_ATTEMPT_INTERVAL"). Which interval does a new SchedulerConfig get?
    medium
    Show answer

    Still 70. The value is a default argument of SchedulerConfig.__init__ (deepinfer/config.py:193). Python computed it when it imported deepinfer.config. rearm puts the descriptor back into envs, but the function keeps its own copy of 70. Pass prefill_attempt_interval=10 explicitly, or set the variable before the import.

  4. 4
    You set nothing, and the model uses the default 5 draft tokens. What is envs.DEEPINFER_MAX_BACKTRACKING_TOKENS? Then you export DEEPINFER_USE_NEXTN_DECODE=0 and DEEPINFER_MAX_BACKTRACKING_TOKENS=1. What is it now, and which state ring gets smaller?
    hard
    Show answer

    With nothing set: max(0, 5 + 1) = 6 (deepinfer/environ.py:132). In the second case: max(1, 0 + 1) = 1. The sliding-window block becomes window_size + 1 instead of window_size + 6 (deepinfer/worker/cache_engine.py:93). The compression ring becomes compress_ratio + 0 instead of compress_ratio + 5 (deepinfer/worker/cache_engine.py:133). The C++ scheduler also reads 0 from the environment and makes no drafts (csrc/engine/scheduler.hpp:118).
