C++ engine API (deepinfer._C)

IntermediateReferenceabout 8 min read

Code version: DeepInfer @ 9bd9cf2 · 2026-10-21

In one sentence

The compiled extension module deepinfer._C gives Python 40 names in three submodules; this page lists each one with the page that explains it.

Use this page to find a name fast. For the rules that apply to many names (memory that a call borrows, calls that release the GIL, loose types), read deepinfer/_C/engine.pyi: the C++ engine API, as seen from Python. This page does not repeat them.

The module and its three submodules#

  • One module, three parts. csrc/pybind.cpp makes the pybind11 module and adds the submodules cuda_utils, engine and graph_timer (csrc/pybind.cpp:7-17). The stub of the package lists the same three (deepinfer/_C/__init__.pyi:1-5).
  • One build per platform. setup.py compiles the same engine sources on both platforms. It adds cuda_utils.cpp and graph_timer_cuda.cpp on NVIDIA, and asc_utils.cpp and graph_timer_asc.cpp on Ascend (setup.py:22-34, setup.py:43-47, setup.py:61-65).
  • Where the file is. The compiled .so is in deepinfer/_so/<accelerator>-<arch>/. The package adds that folder to its search path at import (deepinfer/__init__.py:28-32).
  • The stubs. The .pyi files are type stubs that make stubgen generates with pybind11_stubgen (Makefile:27-28, scripts/gen_stub.sh:11-14). Python never imports them. The "Stub" column below gives the line in the stub.

Submodule engine (34 names)#

The stub lists the names in __all__ (deepinfer/_C/engine.pyi:8): 19 classes, 2 enums, 12 functions and 1 constant. The groups are the same as on the engine.pyi page, which also gives the binding and the C++ line of each name.

Submodule graph_timer (3 names)#

Low-level handles for the graph timer, which measures regions inside a replayed CUDA graph. The binding is csrc/graph_timer/pybind.cpp:5-29. The Python side is CUDAGraphTimer in deepinfer/timer.py:78-217. CudaGraphRunner wraps each captured graph in a GraphHandle and registers it (deepinfer/worker/cuda_graph_runner.py:130-136).

Related pages

  • deepinfer/_C/engine.pyi: the C++ engine API, as seen from Pythonengine.pyi is the generated type stub of deepinfer._C.engine. This page maps its 34 names in five groups to the Python files that use them and to the C++ files that bind and implement them, with the rules for borrowed memory and the GIL.
  • The Python and C++ boundaryDeepInfer runs the scheduler and the step bookkeeping in C++. One pybind11 module, deepinfer._C, connects that code to Python. This page explains the build, the three submodules, the GIL and lock rules, and the memory that crosses the boundary.
  • csrc/engine/scheduler.hpp: the C++ Schedulerscheduler.hpp holds the C++ Scheduler: the waiting and running queues, the choice between prefill and decode, block allocation, preemption, and the bookkeeping after each step. It also defines SchedulerOutputs and three free functions.
  • csrc/engine/outputs.hpp: RequestOutput and its pooloutputs.hpp defines RequestOutput (one new token of one request), a fixed pool of 10000 of them, and build_request_outputs, which turns one engine step into output handles. pybind_output.cpp binds them, with clone and raw-pointer accessors.
  • worker/cache_engine.py: CacheEngine and the cache layoutCacheEngine allocates two raw uint8 device buffers - gpu_blocks for the paged KV cache and gpu_states for the per-sequence state slots - and KVCacheManager cuts them into one KVCache view object per attention layer.
  • CUDA graphsAt start-up DeepInfer records the decode forward pass once for each of a list of batch sizes. Each decode step then pads its rows to the next recorded size and replays the recording with one call.
