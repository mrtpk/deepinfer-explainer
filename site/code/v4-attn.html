v4_modules/attn.py: the MLA attention runtime

AdvancedCode mapabout 9 min read + 4 min deep dives

Code version: DeepInfer @ 9bd9cf2 · 2026-10-21

Before you read

This page uses ideas from these pages:

  • MLA attention: one latent vector per token Advanced
  • Sparse attention with an indexer Advanced

Purpose#

attn.py runs one attention layer: it makes Q and the KV vectors, writes them to the caches, gets the key list, calls FlashMLA, and projects the result back to the hidden size.

Filedeepinfer/model_executor/models/v4_modules/attn.py, 1,008 lines. Role 2 "runtime adapter" (deepinfer/model_executor/models/v4_modules/__init__.py:10-15).
Main classesV4AttentionBase (deepinfer/model_executor/models/v4_modules/attn.py:65), V4Attention (deepinfer/model_executor/models/v4_modules/attn.py:228), DFlashAttention (deepinfer/model_executor/models/v4_modules/attn.py:883).
Runs inEvery worker process, once per layer per step. All work is device kernels; decode runs inside a CUDA graph.
Called byDeepseekDecoderLayer and DFlashDecoderLayer in decoder_layer.py.
CallsFlashMLA wrappers in layers/attention_backend.py, deep_gemm.fp8_einsum, TileLang interface kernels, Compressor (compress.py), MQA (index_attn.py), userbuffer for context parallelism.
Not in this fileThe HF-shaped weights (mla_attn.py), the compression math (compress.py), the top-k selection (index_attn.py), the kernel insides (vendor libraries).

The module docstring sums it up: V4AttentionBase holds the shared projection, norm and RoPE plumbing; V4Attention adds compressed KV, sparse index, sliding window, YOCO and cross-layer paths; DFlashAttention serves the draft model (deepinfer/model_executor/models/v4_modules/attn.py:1-7).

Where it sits#

Who calls it#

  • DeepseekDecoderLayer.__init__ makes one V4Attention per main layer (deepinfer/model_executor/models/decoder_layer.py:85). Its forward calls it with the FP8 and BF16 hidden states and the cross-layer runtime (deepinfer/model_executor/models/decoder_layer.py:154-161).
  • DFlashDecoderLayer makes a DFlashAttention and calls update_main_cache and forward_drafts (deepinfer/model_executor/models/decoder_layer.py:190-195, deepinfer/model_executor/models/decoder_layer.py:216-236).
  • DeepseekForCausalLM.allocate_userbuffer asks each layer for get_max_ag_bytes_per_token() (deepinfer/model_executor/models/deepseek.py:429-430).

What it calls#

  • Attention kernels: prefill_attn_varlen_sparse and decode_mla_mqa_sparse (deepinfer/model_executor/models/v4_modules/attn.py:20-23), which call FlashMLA. The fused FlashMLA module fused_norm_rope_attn_rope_cast also permutes weights at start-up (deepinfer/model_executor/models/v4_modules/attn.py:14).
  • GEMMs: ReplicatedLinear for the projections; deep_gemm.fp8_einsum for the grouped Wv (deepinfer/model_executor/models/v4_modules/attn.py:215-221).
  • TileLang interface kernels: fused_norm_rope_hadamard_cast_store_kvcache, gather, kv_index_cat, load_paged_kv_cache, store_kv_cache (deepinfer/model_executor/models/v4_modules/attn.py:29-39). None of the calls here passes Hadamard arguments.
  • Sub-modules: Compressor (deepinfer/model_executor/models/v4_modules/attn.py:346) and MQA (deepinfer/model_executor/models/v4_modules/attn.py:355-362).

Walk through the main methods#

V4AttentionBase.__init__: the flags#

  1. Line 85: a layer is sparse when its config has index_topk above 0.
  2. Line 86: has_packed_kv: the layer has compressed KV (ratio 1 or 2).
  3. Lines 87-92: the fused FlashMLA path. The comment says it is "disabled in dense packed-KV decoding".
  4. Lines 93-96: a layer needs the sliding window, or compressed KV, or both. A sparse layer needs the window.

_init_compressor_and_indexer: who owns what#

  1. Only a KV-source layer has a Compressor (line 346). In a YOCO consumer, its weights go into a separate projection of the shared hidden state (lines 349-350).
  2. Only a layer with its own indexer has an MQA (line 355). Its weights_proj joins the projection of the current hidden state (line 364).
  3. Lines 368-371: the joined projection gives fp32 output for C2 and bf16 for C1. The Compressor asserts these dtypes (deepinfer/model_executor/models/v4_modules/compress.py:89-95).

forward, part 1: inputs and projections#

  1. Lines 764-765: compute_attn_info expands compact index fields of the metadata into the index lists that the kernels need. It does nothing when they exist already.
  2. Line 768: one GEMM for the compressor input and the indexer weights.
  3. Lines 769-780: YOCO paths: in compact prefill, the full-context KV is written first (line 774); else a YOCO KV source projects the shared hidden state (line 780).
  4. Line 785: with CP, the all-gather of the compressor input starts now and overlaps with the Q projection.
  5. Lines 787-799: Q, the SWA vector, its FP8 store or cast, and the query up-projection.
  6. Lines 802-809: store the compressed KV and get the compressed-key list (next method).

_compute_kv_ca_index: three sources of the key list#

  1. Lines 553-567: the layer has its own indexer: call MQA, which returns [T, index_topk].
  2. Lines 568-578: a sparse layer that shares the indexer of an earlier layer reuses cross_layer_runtime.topk_indices.
  3. Line 580: a dense compressed layer reads all its compressed keys: input_metadata.kv_ca_index[ratio].
  4. Lines 583-584: without a local indexer, the compressed KV is stored late, to overlap with the CP all-gather. With an indexer it was stored earlier (line 546), because the indexer needs pre_rope_kv.

forward, part 2: the prefill buffer#

  1. Lines 814-818: the buffer sizes. total_k_swa = number of sequences × window (deepinfer/model_executor/input_metadata/input_metadata.py:272-273).
  2. Lines 825-830: copy the current SWA vectors into the middle part (with CP: gather them into it).
  3. Lines 834-842: load the compressed KV from ca_cache as BF16 into the last part. A share-KV consumer skips the load and reuses the buffer of its source.
  4. Lines 847-855: load the SWA history into the first part, then store the new SWA vectors. The comment explains the order: the store slots can overlap the loaded range.

forward, part 3: kernel and output#

_prefill_attention joins the SWA index and the compressed-key list with kv_index_cat and calls prefill_attn_varlen_sparse (deepinfer/model_executor/models/v4_modules/attn.py:603-625). _decode_attention passes swa_cache and ca_cache with their index lists to decode_mla_mqa_sparse (deepinfer/model_executor/models/v4_modules/attn.py:640-669). The page MLA attention: one latent vector per token reads these calls in detail.

DFlashAttention.forward_drafts#

The draft attention has no compressed KV and no indexer. It writes the draft keys into its own swa_cache slots. The comment says they "live for one decode step and are overwritten by the next step" (line 975). Then it calls the decode kernel with dflash_kv_index and the scheduler metadata key "DFlash". See models/mtp/dflash.py: the DFlash draft model.

Deep dive

Worked example: the size of the prefill buffer

A prefill step with two sequences in a C2 layer. The window is 128 (the value in the deployment notes, doc/inference_deployment_qa.md:191; the code reads it from the config).

  • Sequence A: a new prompt of 1,000 tokens.
  • Sequence B: a later chunk of 300 tokens, after 2,048 cached tokens.
  1. total_k_swa_cached = 2 × 128 = 256 rows. A has no history, so its rows are zeros (src_block_id = −1 zero-fills, deepinfer/model_executor/input_metadata/input_metadata.py:268-271).
  2. total_k_swa_cur = 1,000 + 300 = 1,300 rows.
  3. total_k_compressed["2"] ≈ 1,000 / 2 + 2,348 / 2 = 500 + 1,174 = 1,674 rows. The new entries are stored before the load, so the load includes them. The real value can be a little larger: it includes padding (deepinfer/model_executor/input_metadata/input_metadata.py:278-279).
  4. total_kv ≈ 256 + 1,300 + 1,674 = 3,230 rows. In BF16: 3,230 × 512 × 2 B ≈ 3.3 MB.

A query of B reads its row of kv_index: 128 window positions, then up to topk positions in the compressed part. kv_index_cat adds total_k_swa_cached + total_k_swa_cur = 1,556 to each compressed index (deepinfer/model_executor/layers/tilelang_ops/kv_index_cat.py:24).

Deep dive

Context parallelism in this file

  • CP is used only in prefill: use_cp = is_prompt and CP size > 1 (deepinfer/model_executor/models/v4_modules/attn.py:766).
  • Each rank projects its own tokens. The compressor input and the SWA vectors are all-gathered through userbuffer.cp, so each rank has the full sequence for the cache store (deepinfer/model_executor/models/v4_modules/attn.py:785, deepinfer/model_executor/models/v4_modules/attn.py:450).
  • gather(..., mirror_cp_reverse_index) puts the gathered rows back in sequence order (deepinfer/model_executor/models/v4_modules/attn.py:828).
  • Decode asserts that CP is off (line 422).
  • get_max_ag_bytes_per_token sizes the shared buffer: 512 × 4 B for the SWA vector, plus the projected KV width (2 B per value for C1, 4 B for C2), plus the indexer's estimate (deepinfer/model_executor/models/v4_modules/attn.py:375-384).

See Context parallelism (mirror CP).

Check yourself#

  1. 1
    Which two FlashMLA wrappers does V4Attention call, and when?
    easy
    Show answer

    prefill_attn_varlen_sparse in prefill and decode_mla_mqa_sparse in decode (deepinfer/model_executor/models/v4_modules/attn.py:859-877).

  2. 2
    A sparse layer shares the indexer of an earlier layer. Which code path gives it its key list?
    medium
    Show answer

    has_local_index is false and is_sparse is true, so _compute_kv_ca_index takes cross_layer_runtime.topk_indices, written by the index source (deepinfer/model_executor/models/v4_modules/attn.py:568-570, deepinfer/model_executor/models/v4_modules/attn.py:585-586).

  3. 3
    In prefill, why does the code store the new SWA vectors only after it loads the SWA history?
    medium
    Show answer

    The store slots of the ring can overlap the range that the load reads. A store first would overwrite history that the prefill still needs (deepinfer/model_executor/models/v4_modules/attn.py:854-855).

  4. 4
    Two sequences in a C2 prefill: 1,000 new tokens, and 300 new tokens after 2,048 cached ones. Window 128. About how many rows does the buffer kv have, and what offset does kv_index_cat add to a compressed index?
    hard
    Show answer

    256 SWA history rows + 1,300 current rows + about 1,674 compressed rows ≈ 3,230. The offset is 256 + 1,300 = 1,556 (deepinfer/model_executor/models/v4_modules/attn.py:814-818, deepinfer/model_executor/layers/tilelang_ops/kv_index_cat.py:24). This is the deep dive "Worked example: the size of the prefill buffer".

Related pages

  • MLA attention: one latent vector per tokenIn DeepInfer's MLA, all query heads of a layer read one 512-value vector per token. This vector is the key and also the value, so the KV cache keeps one small entry per token.
  • Sparse attention with an indexerIn a sparse layer, a small indexer scores all compressed keys for each query and keeps the best index_topk. The main attention then reads only those keys plus the sliding window.
  • Sliding-window attentionEvery attention layer of DeepSeek-V4.1-Flash reads the most recent tokens (a window of 128 in the docs) from a ring of 134 slots per sequence and layer. This page shows the ring, the decode and prefill index paths, and how the window joins the compressed keys.
  • KV compression (C1 and C2)A compressed layer stores one 512-value cache entry per token (C1) or per 2 tokens (C2). C2 mixes the two tokens with a learned softmax gate and keeps the score and latent of the most recent tokens in a small fp32 state ring. Entries are FP4 (288 B) by default, or FP8 (528 B).
  • Cross-layer KV sharingA layer can reuse the compressed KV, the indexer keys or the top-k list of an earlier source layer. SharedLayerTopology turns three lists of source layers from config.json into checked segment maps; the cache engine then allocates the compressed-KV and index-K caches only for source layers.
  • YOCO and SWA bounded replayYOCO splits the main layers into producer and consumer layers. Consumer layers project their compressed KV from one shared hidden state. With the optional prefill truncation (README feature "Decoder SWA bounded replay"), a prefill computes the consumer layers only for the last KEEP_TOKENS prompt tokens (140 in the README), with the window cut at that range. Only their compressed KV still covers every token.
  • v4_modules/mla_attn.py: the attention weight containersmla_attn.py allocates the weights of one attention layer with their Hugging Face names and shapes: the low-rank Q and KV projections, the compressor, the indexer, the grouped output projection and the attention sinks. It has no forward.
  • v4_modules/index_attn.py: the sparse-attention indexerindex_attn.py holds the class MQA. It stores the FP4 index keys, scores every compressed key for each query with DeepGEMM, and selects the top-k keys with DeepSelect, in prefill and in decode, with optional candidate blocks.
  • v4_modules/compress.py: the KV compressorcompress.py holds two small runtime classes. Compressor turns the projected KV of a C1 or C2 layer into compressed entries, stores them in ca_cache and returns the pre-RoPE vector for the indexer. KProject is the indexer's key projection of that vector.
  • models/decoder_layer.py: one decoder layerdecoder_layer.py holds DeepseekDecoderLayer (one main-model layer: mHC, attention, mHC, MoE, plus the Engram, YOCO and DFlash hooks) and DFlashDecoderLayer (one draft-model layer).
