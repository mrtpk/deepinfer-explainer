v4_modules/cross_layer.py: sharing topology and the cross-layer runtime

AdvancedCode mapabout 6 min read + 4 min deep dives

Code version: DeepInfer @ 9bd9cf2 · 2026-10-21

Before you read

This page uses ideas from these pages:

  • Cross-layer KV sharing Advanced
  • Sparse attention with an indexer Advanced

Purpose#

cross_layer.py decides, once at start-up, which layer is the source of each shared value, and carries those values from layer to layer during a forward.

Filedeepinfer/model_executor/models/v4_modules/cross_layer.py, 383 lines. Role 4 "topology and assembly" (deepinfer/model_executor/models/v4_modules/__init__.py:16-20).
Main classesSharedLayerTopology (deepinfer/model_executor/models/v4_modules/cross_layer.py:22), CrossLayerRuntime (deepinfer/model_executor/models/v4_modules/cross_layer.py:276-277), SharedLayerMetadata (deepinfer/model_executor/models/v4_modules/cross_layer.py:354-355).
Runs inEvery worker process. The topology is plain Python at start-up. The runtime is one Python object per forward; its fields hold device tensors.
Called byV41Builder, DeepseekForCausalLM.__init__, ModelMetadata, DeepseekModel.forward; read by V4Attention, MQA, DeepseekDecoderLayer, yoco.py; C++ FlopsEstimator.
CallsOnly iter_runtime_attn_modules and AttrDict. No kernels.
Not in this fileThe source-id lists to maps conversion (hugging_face/config.py), the cache aliasing (worker/cache_engine.py), the reads and writes of the runtime values (attn.py, index_attn.py, yoco.py).

The module docstring names the three parts (deepinfer/model_executor/models/v4_modules/cross_layer.py:1-8). The concept is on Cross-layer KV sharing.

Where it sits#

Who calls it#

  • The builder makes a topology to decide which containers get PackedWkv and an indexer (deepinfer/model_executor/models/v4_modules/builder.py:100-106, deepinfer/model_executor/models/v4_modules/builder.py:63-73).
  • DeepseekForCausalLM.__init__ makes it again for the runtime modules and passes it to every layer (deepinfer/model_executor/models/deepseek.py:266-269, deepinfer/model_executor/models/decoder_layer.py:85).
  • ModelMetadata calls build_shared_layer_metadata (deepinfer/model_executor/model_metadata_utils.py:75). The C++ FlopsEstimator reads the flag lists from it (csrc/engine/flops_estimator.hpp:158-171).
  • DeepseekModel.forward makes one CrossLayerRuntime per forward (deepinfer/model_executor/models/deepseek.py:165-166). A decoder layer called without one makes its own (deepinfer/model_executor/models/decoder_layer.py:108-109).

What it calls#

iter_runtime_attn_modules walks the attention list and skips the lm-head entry, so main and draft layers get one runtime number each (deepinfer/model_executor/layer_utils.py:6-16). Nothing else: this file has no tensor work.

Walk through the main methods#

_process_cfg: one shared config#

  1. Lines 66-69: every runtime layer that carries layer_info_shared_cfg joins the list. The HF loader gives it to every compressed layer (deepinfer/hugging_face/config.py:129).
  2. Line 71: at least one layer must carry it. build_shared_layer_topology checks this first and returns None instead (deepinfer/model_executor/models/v4_modules/cross_layer.py:346-351).
  3. Lines 74-75: all copies must be equal; the first one is the canonical config.

_build_layer_map: dense maps#

  1. Lines 145-146: without its own map, index K follows the top-k map. (The HF loader always writes an index-K map, by default equal to the KV map: deepinfer/hugging_face/config.py:74.)
  2. Lines 148-150: every id must be a valid layer.
  3. Line 151: a layer that is not in the map is its own source.
  4. Lines 152-154: the draft (MTP) layers must not share.

_validate: the checks#

  1. Lines 97-113: for each map, check the segments, then check each consumer: it carries the config, and it matches its source.
  2. Lines 114-116: the first YOCO consumer layer is a KV source (see YOCO and SWA bounded replay).
  3. Lines 117-118: the nesting check and the candidate checks.

All checks are assert statements, so a bad config stops the start-up with an AssertionError and a message that names the layer.

CrossLayerRuntime: the per-forward values#

The docstring explains why one slot per value is enough: the segments are contiguous and the layers run in order, so the value in the slot always comes from the nearest source (deepinfer/model_executor/models/v4_modules/cross_layer.py:284-287). The object is not returned through the layer outputs; the same reference goes to every layer (deepinfer/model_executor/models/v4_modules/cross_layer.py:281-282).

Worked example: the maps of the figure

Made-up config: 8 main layers, 1 draft layer, so num_layers = 9 and n_main_layer = 8. Source lists: KV [1, 3, 5, 6], index [1, 2, 3, 5, 6], no index-K list.

  1. The HF loader makes layer_kv_map = {1: 1, 2: 1, 3: 3, 4: 3, 5: 5, 6: 6, 7: 6}, the same map for index K (line 74 of config.py), and layer_index_module_map = {1: 1, 2: 2, 3: 3, 4: 3, 5: 5, 6: 6, 7: 6} (deepinfer/hugging_face/config.py:62-75).
  2. _build_layer_map gives layer_kv_map = [0, 1, 1, 3, 3, 5, 6, 6, 8]. Layer 0 and the draft layer 8 point to themselves.
  3. _validate_segmented_map walks the list: 0 is a source, 1 is a source, 2 → 1 equals the last source, and so on. Pass.
  4. Refinement, top-k inside index K: for layer 2, ik[ix[2]] = ik[2] = 1 and ik[2] = 1. Pass. Index K inside KV: the maps are equal. Pass.
  5. YOCO: the ratios are [0, 2, 2, 2, 2, 1, 2, 2], so n_prefill_layer = 5 and layer_kv_map[5] = 5. Pass.
  6. build_shared_layer_metadata gives is_kv_source_list = [T, T, F, T, F, T, T, F, T] and the same for index K; is_index_source_list differs only at layer 2 (T).

Deep dive

Three topologies from one config

The same config is turned into a topology at three places: in the builder (containers), in DeepseekForCausalLM.__init__ (runtime modules) and in each ModelMetadata (flag lists). The cache engine does not use the class at all: it reads the raw maps from each layer's layer_info_shared_cfg (deepinfer/worker/cache_engine.py:141-162). The code keeps these in agreement by convention, and the comment on lines 106-109 explains the one case that would break it: a consumer without the shared config.

The layer count also differs in form: the builder passes num_hidden_layers + nextn (deepinfer/model_executor/models/v4_modules/builder.py:102); the model counts its modules minus the embedding and the lm head (deepinfer/model_executor/models/deepseek.py:267-269). Both give the number of main plus draft layers.

Check yourself#

  1. 1
    How many CrossLayerRuntime objects does one forward of the main model use?
    easy
    Show answer

    One. DeepseekModel.forward makes it and passes the same reference to every layer (deepinfer/model_executor/models/deepseek.py:165-166, deepinfer/model_executor/models/v4_modules/cross_layer.py:281-282).

  2. 2
    A layer is missing from layer_kv_map in the config. What does SharedLayerTopology make of it?
    medium
    Show answer

    A KV source: raw.get(layer_id, layer_id) (deepinfer/model_executor/models/v4_modules/cross_layer.py:151). If the layer sits between a source and its consumers, the segment check then fails (deepinfer/model_executor/models/v4_modules/cross_layer.py:44-47).

  3. 3
    Why does a single slot per value work in CrossLayerRuntime?
    medium
    Show answer

    The maps are contiguous segments and the layers run in order of their id. So when a consumer runs, the last value written is the one of its nearest source (deepinfer/model_executor/models/v4_modules/cross_layer.py:284-287, deepinfer/model_executor/models/v4_modules/cross_layer.py:169-179).

  4. 4
    In the worked example, what are is_kv_source_list and is_index_source_list, and why does layer 2 differ?
    hard
    Show answer

    is_kv_source_list = [T, T, F, T, F, T, T, F, T]; is_index_source_list is the same except T at layer 2 (deepinfer/model_executor/models/v4_modules/cross_layer.py:370-374). Layer 2 is in index_source_layer_ids but not in kv_source_layer_ids, so it runs its own indexer on the KV and index keys of layer 1. See the deep dive "Worked example".

Related pages

  • Cross-layer KV sharingA layer can reuse the compressed KV, the indexer keys or the top-k list of an earlier source layer. SharedLayerTopology turns three lists of source layers from config.json into checked segment maps; the cache engine then allocates the compressed-KV and index-K caches only for source layers.
  • YOCO and SWA bounded replayYOCO splits the main layers into producer and consumer layers. Consumer layers project their compressed KV from one shared hidden state. With the optional prefill truncation (README feature "Decoder SWA bounded replay"), a prefill computes the consumer layers only for the last KEEP_TOKENS prompt tokens (140 in the README), with the window cut at that range. Only their compressed KV still covers every token.
  • KV compression (C1 and C2)A compressed layer stores one 512-value cache entry per token (C1) or per 2 tokens (C2). C2 mixes the two tokens with a learned softmax gate and keeps the score and latent of the most recent tokens in a small fp32 state ring. Entries are FP4 (288 B) by default, or FP8 (528 B).
  • v4_modules/attn.py: the MLA attention runtimeattn.py turns the MLA weight container into runtime weights and runs one attention layer per call: projections, sliding-window and compressed KV stores, the indexer, the FlashMLA kernel and the output projection. It also holds the DFlash draft attention.
  • v4_modules/index_attn.py: the sparse-attention indexerindex_attn.py holds the class MQA. It stores the FP4 index keys, scores every compressed key for each query with DeepGEMM, and selects the top-k keys with DeepSelect, in prefill and in decode, with optional candidate blocks.
  • models/deepseek.py: the DeepSeek-V4.1 modeldeepseek.py holds DeepseekModel (embedding, N decoder layers, final mix and norm) and DeepseekForCausalLM (lm head, sampler, DFlash, EPLB, weight loading). The forward returns hidden states.
  • worker/cache_engine.py: CacheEngine and the cache layoutCacheEngine allocates two raw uint8 device buffers - gpu_blocks for the paged KV cache and gpu_states for the per-sequence state slots - and KVCacheManager cuts them into one KVCache view object per attention layer.
