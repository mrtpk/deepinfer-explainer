deepinfer/sampling_params.py: SamplingParams

BeginnerCode mapabout 7 min read + 3 min deep dives

Code version: DeepInfer @ 9bd9cf2 · 2026-10-21

Before you read

This page uses ideas from these pages:

  • Sampling: temperature, top-k, top-p Beginner
  • deepinfer/entrypoints/llm.py: the offline LLM class Beginner

Purpose#

SamplingParams holds the settings of one request: how to choose each token, when to stop, and which extra values to return.

Filedeepinfer/sampling_params.py, 119 lines. The header says "Derived from vLLM; modified by DeepSeek." (deepinfer/sampling_params.py:2)
Main classSamplingParams (deepinfer/sampling_params.py:13). The constant SAMPLING_EPS = 1e-5 (deepinfer/sampling_params.py:10).
Runs inThe engine process, in Python, once per request. It imports torch only for the int32 limit (deepinfer/sampling_params.py:8).
Called byUser scripts, LLM.generate (default object), LLMEngine.add_request (from a dict), and two dummy runs in the model runner.
CallsOnly random.getrandbits and torch.iinfo.
Not in this fileAny sampling. The C++ code reads the values; the sampler uses them.

Where it sits#

Who calls it#

  • User scripts make one object per request, or one for all. Example: the eval script sets temperature, top-p, max_tokens and a fixed seq_seed per sample (eval/run_eval.py:225-234).
  • LLM.generate makes SamplingParams() when you pass none (deepinfer/entrypoints/llm.py:125-127). _add_request deep-copies the object for each request (deepinfer/entrypoints/llm.py:151).
  • LLMEngine.add_request also accepts a dict. It drops keys with the value None and calls the constructor (deepinfer/engine/llm_engine.py:521-526).
  • The model runner uses SamplingParams(temperature=0.0) for placeholder metadata and SamplingParams(top_p=0.99, top_logprobs=20) in the profile run (deepinfer/worker/model_runner.py:396, deepinfer/worker/model_runner.py:484).

Who reads the values#

  • The C++ Sequence constructor copies 9 values into SamplingScalars and 2 into StoppingCriteria (csrc/engine/sequence.hpp:280-281).
  • LLMEngine.add_request reads golden_token_ids, so_args and prompt_logprobs in Python (deepinfer/engine/llm_engine.py:529-537, deepinfer/engine/llm_engine.py:562, deepinfer/engine/llm_engine.py:607).

Order of the work in __init__#

  1. Line 63: drop logprobs.
  2. Lines 65-73: store the values; a max_tokens of 0 becomes 1.
  3. Line 74: make the seed (see below).
  4. Line 75: _verify_args() checks the ranges. It runs before the temperature clamp, so it sees the values that you gave.
  5. Lines 76-79: a temperature below SAMPLING_EPS becomes 1e-5, and top_p = 1.0, top_k = -1.
  6. Lines 80-83: store the four fields that have no check.

Temperature 0 is not exact greedy decoding

The engine has no separate greedy path. Temperature 0 becomes 1e-5. The sampler still makes a seeded draw from a very sharp distribution (see The sampler). Your top_p and top_k are replaced, but they must still pass the checks: SamplingParams(temperature=0, top_k=0) raises.

_make_seed: the seed rules#

  1. Line 88: no seed gives 64 random bits from Python's random module. So two runs give different tokens, unless you pass a seed or seed the random module.
  2. Line 90: an int is masked to 64 bits. A negative seed is valid: -1 becomes 18,446,744,073,709,551,615. True is an int in Python, so it gives seed 1.
  3. Line 91: any other type raises TypeError() with an empty message. A NumPy integer is not a Python int, so np.int64(7) raises too.

Because of the mask, the range check on seq_seed at lines 104-105 can never fail.

so_args: the grammar dict#

The docstring describes the keys in Chinese (deepinfer/sampling_params.py:39-43). Translated and split into a list:

  • "schema_type" and "schema": the grammar.
  • Optional "trigger_token_ids" (one list[int]): the token sequence that turns the grammar on. Before the full sequence appears, the output is free.
  • Optional "bound_token_id": a non-negative integer; 0 is valid. Missing or None means no bound. A list is not valid. It needs a non-empty trigger_token_ids.
  • When the bound is active, free tokens are no longer allowed. The output first follows the trigger sequence token by token, then enters the grammar.

The class does not check the dict. The grammar builder checks it in build(), and then compiles the grammar on a thread pool (deepinfer/structure_output/so_matcher_builder.py:58-95):

  • "serialized" raises ValueError (offline use needs schema_type and schema). "bound_token_ids" (plural) raises ValueError (deepinfer/structure_output/so_matcher_builder.py:60-63).
  • A bad trigger or bound does not raise: the builder returns an aborted matcher (deepinfer/structure_output/so_matcher_builder.py:71-76). When the request goes into the queue, it gets the status FINISHED_SO_FAILED (deepinfer/engine/llm_engine.py:620-623), and the scheduler ends it without a prefill (csrc/engine/scheduler.hpp:363-367).

The page Structured outputs explains the grammar matcher. examples/benchmark.py shows a regex example: {"schema_type": "regex", "schema": r"Hello, my name is [a-z]+"} (examples/benchmark.py:280).

What the engine changes after the constructor#

  1. Line 527: eos_id always becomes the tokenizer's EOS id. The docstring calls the field a "HACK" with default 0 "only for warm up phase" (deepinfer/sampling_params.py:36-38). So a value that you set has no effect through add_request.
  2. Lines 529-537: with DEEPINFER_YOCO_PREFILL_TRUNCATION_MODE not off, prompt_logprobs becomes False, with a warning in the log.

The engine changes the object that it gets. LLM passes a deep copy, so your object stays as it was. A direct caller of LLMEngine.add_request sees its own object change.

__repr__#

The text form shows 9 of the 13 fields (deepinfer/sampling_params.py:107-119). It leaves out first_n_token_no_eos, eos_id and golden_token_ids. logprobs is not stored, so it cannot show.

Deep dive#

The sections below give the full detail. Open them one at a time, or use Open all deep dives at the top of the page.

Deep dive

How the values reach the sampler, step by step

  1. Once, in the Sequence constructor. C++ reads attributes by name from the Python object: and max_tokens and ignore_eos into StoppingCriteria (csrc/engine/sequence.hpp:181-190). The Python object stays in the sequence as generation.params, but C++ never reads these numbers from it again.
  2. Each step, in the metadata. Each SequenceMetadata copies the SamplingScalars struct (csrc/engine/sequence.hpp:380).
  3. Each step, in prepare_sampler_inputs. The function fills one entry per sequence in pinned CPU tensors: temperatures and top_ps as float32, top_ks as int32, seq_seeds as uint64 (csrc/engine/prepare_sample.cpp:82-88, csrc/engine/prepare_sample.cpp:157-161). max_top_logprobs is the largest top_logprobs of the batch (line 157).
  4. EOS rules. In a prefill, a sequence with first_n_token_no_eos == 1 in its last prompt chunk adds a row and its eos_id to the suppression list (csrc/engine/prepare_sample.cpp:20-22, csrc/engine/prepare_sample.cpp:192-195). In a decode with drafts, stop_token_ids[i] = [eos_id, -1], or [-1, -1] with ignore_eos (csrc/engine/prepare_sample.cpp:217-219).
  5. Prompt logprobs. With prompt_logprobs, the prompt rows get the same temperature, top-p and top-k (csrc/engine/prepare_sample.cpp:181-189).
  6. To the device. All arrays go to the device with non_blocking=True (csrc/engine/prepare_sample.cpp:257-264).
  7. Stop check. After the step, the scheduler stops a sequence on EOS (unless ignore_eos), at max_model_len, or at max_tokens output tokens (csrc/engine/scheduler.hpp:1035-1052).

Worked example. R1 has temperature=0.6, top_p=0.95, seq_seed=7. R2 has temperature=0 and no seed. In one decode step: temperatures = [0.6, 1e-5], top_ps = [0.95, 1.0], top_ks = [-1, -1], seq_seeds = [7, <64 random bits>]. Note that 0.6 as float32 is 0.60000002384.

Deep dive

Where max_tokens matters besides the stop

  • Memory reserve. add_sequence reserves room in the token vector for max_tokens more tokens (csrc/engine/sequence.hpp:286-289, csrc/engine/scheduler.hpp:135-141). It also reserves the block table for (len + max_tokens) / 128 + 1 blocks (csrc/engine/scheduler.hpp:189-192). These are host-memory reserves, not KV blocks.
  • Batch planning. The default of 16 tokens is short. Benchmarks set max_tokens=1 for prefill-only requests (examples/benchmark.py:283).
  • The other limit. max_model_len also stops a sequence, with the same reason "length" (csrc/engine/scheduler.hpp:1043-1045, csrc/engine/sequence.hpp:49-50).

Check yourself#

  1. 1
    What are the defaults of temperature, top_p, top_k and max_tokens?
    easy
    Show answer

    1.0, 1.0, -1 (off) and 16 (deepinfer/sampling_params.py:49-53).

  2. 2
    You write SamplingParams(temperature=0, top_p=0.5, top_k=40). Which values does the sampler get?
    medium
    Show answer

    Temperature 1e-5, top-p 1.0, top-k -1. The checks pass first (0 ≥ 0, 0.5 in range, 40 in range), then lines 76-79 replace the three values (deepinfer/sampling_params.py:75-79).

  3. 3
    You set eos_id=42 and call LLM.generate. Which EOS id does the request use?
    medium
    Show answer

    The tokenizer's EOS id. add_request sets sampling_params.eos_id = self.eos_id for every request (deepinfer/engine/llm_engine.py:527, deepinfer/engine/llm_engine.py:225).

  4. 4
    After add_request, a script sets seq.sampling_params.temperature = 2.0. Does the next step sample with temperature 2.0?
    hard
    Show answer

    No. The C++ Sequence copied the value into SamplingScalars in its constructor (csrc/engine/sequence.hpp:280, csrc/engine/sequence.hpp:105). SequenceMetadata and prepare_sampler_inputs read that copy (csrc/engine/sequence.hpp:380, csrc/engine/prepare_sample.cpp:158). This is the deep dive "How the values reach the sampler".

Related pages

  • The samplerThe sampler turns the hidden states of the rows that need a token into float32 logits, applies temperature, top-p and top-k, and draws one token per request with a seeded hash. In decode steps it also verifies the draft tokens.
  • deepinfer/entrypoints/llm.py: the offline LLM classLLM is DeepInfer's offline Python API. It makes one LLMEngine, adds every prompt as a request, calls step() until no data-parallel rank has work, clones the outputs, and returns token lists or decoded text.
  • engine/llm_engine.py: the LLMEngine classLLMEngine starts the workers, sizes the KV cache, owns the C++ scheduler, and runs one engine step each time LLM calls step().
  • engine/prepare_sample.cpp: the sampler inputsprepare_sampler_inputs reads the scheduled sequences once and builds the arrays that the sampler needs: which model-output rows to sample, per-sequence temperature, top-p, top-k and seed, and the draft-token bookkeeping of speculative decoding.
  • csrc/engine/sequence.hpp: Sequence and SequenceMetadatasequence.hpp defines the C++ Sequence (one record per request, owned by the scheduler) and SequenceMetadata (a per-step view of one scheduled sequence that the worker reads). It also defines the status enum, the finish reasons and the image token offsets.
  • Structured outputsA structured-output request carries a grammar (regex, JSON schema or EBNF). DeepInfer compiles it with xgrammar on a pinned CPU thread pool, then masks every token that the grammar does not allow, also on each draft row.
  • Determinism and batch invarianceFloating-point sums depend on their order, and many kernels choose the order from the batch. DEEPINFER_BATCH_INVARIANT=1 (NVIDIA only) fixes this. Deterministic sampling also needs DEEPINFER_ENABLE_MTP_VARLEN=0 and a fixed seq_seed.
