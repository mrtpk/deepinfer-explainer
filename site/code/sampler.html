layers/sampler.py: the Sampler class

Purpose#

Sampler turns the hidden states of one engine step into new tokens: one per request in prefill, and an accepted draft prefix plus one token per request in decode.

Filesdeepinfer/model_executor/layers/sampler.py, 683 lines; the header says "Derived from vLLM; modified by DeepSeek." (deepinfer/model_executor/layers/sampler.py:2). deepinfer/model_executor/layers/sampler_utils.py, 196 lines, with no origin note.
Main classSampler(nn.Module) (deepinfer/model_executor/layers/sampler.py:59). It has no weights. The LM head weight comes in as an argument.
Runs inThe driver worker process of each data-parallel rank, on the main CUDA stream. The structured-output mask copy uses a second stream. Follower ranks of context parallelism also call it, but only for the collective parts.
Called byDeepseekForCausalLM.sample (deepinfer/model_executor/models/deepseek.py:383-400), which ModelRunner.execute_sample calls (deepinfer/worker/model_runner.py:337-367).
CallsTileLang kernels in tilelang_ops/ (fused_sample, gather, verification kernels), topk from DeepSelect, the xgrammar mask helpers, and DFlash.decode_forward.
Not in this fileThe per-sequence input arrays (C++ prepare_sampler_inputs), the kernel code, the draft model, and the update of the sequences (C++ process_outputs).

The class docstring is in Chinese. It lists the core flow (translated): take the hidden states that need sampling, compute the logits, apply the logits processors, temperature and top-k/top-p, sample the output token, and optionally predict draft tokens with the nextn module for the next decode step (deepinfer/model_executor/layers/sampler.py:60-67).

Where it sits#

Who calls it#

  • ModelRunner.execute_sample builds SamplerInputs and calls model.sample inside forbid_cuda_sync() (deepinfer/worker/model_runner.py:348-365).
  • DeepseekForCausalLM.sample calls the sampler with the DFlash module, the LM head weight as embedding, and the KV caches for DFlash (deepinfer/model_executor/models/deepseek.py:391-399).
  • Worker.execute_model_step calls execute_sample after the forward pass and before pre_sampler_sync (deepinfer/worker/worker.py:154-164).

What it calls#

  • Kernels and wrappers in tilelang_ops/: gather, prepare_verification_metadata, get_accept_result, finalize_verification, map_lookup, apply_token_bitmask_by_step_inplace, get_sum_smaller_probs (deepinfer/model_executor/layers/sampler.py:24-32). Through sampler_utils: fused_sample, expand_sampling_params, remap_draft_topk (deepinfer/model_executor/layers/sampler_utils.py:6-8).
  • Vendor code: topk from deep_select.interface (deepinfer/model_executor/layers/sampler.py:12), and the BF16 GEMM bf16_gemm_nt (deepinfer/model_executor/layers/sampler_utils.py:6).
  • Structured outputs: XGrammarUtils and allocate_vocab_mask (deepinfer/model_executor/layers/sampler.py:49).
  • The draft model: mtp_module.decode_forward (deepinfer/model_executor/layers/sampler.py:237-251). See models/mtp/dflash.py: the DFlash draft model.

Walk through the main methods#

__init__: settings from the environment#

  1. Line 99: force_topk from DEEPINFER_SAMPLER_FORCE_TOPK (0 = off).
  2. Line 104: need_sum_smaller_probs from DEEPINFER_COMPUTE_SUM_SMALLER_PROBS.
  3. Line 105: max_MTP_value from DEEPINFER_USE_NEXTN_DECODE (default 5).
  4. Lines 108-112: the blacklist string becomes an int64 tensor on the device. A bad string raises ValueError, so the model does not load.

forward, part 1: rows, logits and the follower path#

  1. Line 124: hidden_states.move() takes the tensor out of its Movable wrapper, so the caller no longer holds it.
  2. Lines 131-133: prompt logprobs need their own rows, gathered before the main gather.
  3. Lines 137-138: only the driver has sampler_inputs.driver. It starts the structured-output mask work on the CPU now, while the device works.
  4. Lines 141-142: gather the selected rows and make float32 logits. Line 143 frees the hidden states.
  5. Lines 145-161: a follower rank runs only the parts that contain collectives, then returns an empty SamplerOutput.

forward, part 2: the prefill path#

  1. Line 164: wait for the event of the mask copy stream.
  2. Line 169: the blacklist applies to both paths, because it runs before line 171.
  3. Lines 184-185: EOS suppression, one element per listed row.
  4. Line 190: _prefill_golden_gen samples one token per request.
  5. Line 193: sampler_epilogue() starts the copies to the CPU.

Lines 195-211 copy the prompt logprobs to the CPU and add a post function that splits them per request. Translated comment at line 206: "With values=None, requests that asked for prompt logprobs get an empty list; the others get None."

forward, part 3: the decode path#

  1. Lines 225-233: _verification returns 8 values. The DFlash pool is passed in, because the verification reads the drafts of the previous step from it.
  2. Line 235: golden_tokens is the new token of each request (residual sample or bonus token).
  3. Lines 236-251: if the step has drafts, DFlash makes the next drafts. It starts after last_valid_offset accepted drafts.
  4. Lines 252-254: a request that emitted a stop token gets zero confidence for its next drafts.

Lines 258-299 start the CPU copies, keep device copies for ZOS, and build the SamplerOutput. The counters num_generated_tokens and num_verified_tokens are filled later by _decode_post_func, when the CPU values are ready (deepinfer/model_executor/layers/sampler.py:293-298).

_verification: sample, verify, finalize#

The page Speculative decoding reads lines 423-491 line by line. The second half collects the extra outputs and packs the results:

  1. Lines 494-499: the logprob of each row's token. With force top-k, the lookup is by key in token_index.
  2. Lines 501-509: sum_smaller_probs, only if the environment variable asks for it. With force top-k, the token first becomes a column index.
  3. Lines 511-515: the top logprobs of every row.
  4. Lines 519-536: finalize_verification makes the request results. The confidence inputs are passed only if the pool has confidences.

Without drafts (nextn = 0), lines 567-583 return the fresh samples directly, and last_valid_offset is all zeros.

_prefill_golden_gen and _update_golden_tokens#

  1. Lines 603-607: process_sampling without draft arguments: temperature, top-p, top-k, log-softmax and a draw.
  2. Line 614: golden override and token logprobs.
  3. Lines 668-677: with golden tokens, the sample first becomes a vocabulary id (force top-k), then torch.where puts the golden token where it is not -1. The logprob lookup then uses the final id.
  4. Lines 678-681: without golden tokens, the code reads the logprob by column first, then maps the column to a vocabulary id.

process_sampling (sampler_utils.py)#

  1. Lines 162-163: with row_to_req, the per-sequence parameters become per-row parameters. The sample position of row j gets j × 10000019 added.
  2. Lines 166-167: force top-k. sorted=False: the kernel does not need sorted input.
  3. Lines 172-180: the draft logprobs move into the target's top-k space.
  4. Lines 185-194: one kernel launch. It returns five tensors; the last three are None without drafts.

compute_prompt_logprobs (sampler_utils.py)#

Every context-parallel rank must call it with the same number of rows, so the chunk borders match (docstring, lines 89-92). Only rank 0 allocates the result. In each chunk, get_logits runs on all ranks; the rest runs on rank 0 only (deepinfer/model_executor/layers/sampler_utils.py:62-64).

Deep dive

Streams, events and the no-sync rule

  • Main stream. All sampler kernels and the DFlash pass run on the current stream. A note in the docstring says that the MTP info pool has a read-after-write dependency across steps: the verification of step N reads what the DFlash graph wrote in step N−1, and the shared stream keeps the order (deepinfer/model_executor/layers/sampler.py:85).
  • Mask copy stream. _get_so_mask records an event on the main stream, makes the copy stream wait for it, copies the pinned masks, and records so_mask_ready. Then record_stream tells the allocator that the main stream uses these tensors (deepinfer/model_executor/layers/sampler.py:391-407).
  • No CPU wait. All copies to the CPU are non_blocking. The worker reads the values after sample_end_evt in a later call (deepinfer/worker/worker.py:167-168). The function execute_sample must not contain a CUDA synchronize (deepinfer/worker/model_runner.py:344-347).
Deep dive

Worked example: one decode call with numbers

Two requests, nextn = 5, force top-k 4096, no grammar, no golden tokens. Request 0 has seqlen_q = 6, request 1 has seqlen_q = 4 (DSpark cut it). Request 1 has top_logprobs = 4, request 0 has 0.

  1. total_q = R = 10. logits float32 [10, V]: with the inferred V = 129280, 5.17 MB.
  2. prepare_verification_metadata: row_to_req = [0×6, 1×4], is_verify false at rows 5 and 9.
  3. process_sampling: topk gives values [10, 4096] and token_index int32 [10, 4096]. The draft rows are remapped. fused_sample returns logprobs [10, 4096] and four tensors of shape [10].
  4. map_lookup turns the 10 column indices into vocabulary ids.
  5. get_accept_result: request 0 accepts 2 drafts, request 1 accepts 3 (all). is_final is true at rows 2 and 9.
  6. _prepare_top_info with k = max(0, 4) = 4: [10, 4] for every row, also for request 0.
  7. finalize_verification: last_valid_offset = [2, 3], sampled_token_ids [2], verified_token_ids [10] with 5 real ids and 5 times -1.
  8. DFlash: drafts [2, 5] and confidences [2, 5].

The CPU later appends 3 tokens to request 0 and 4 tokens to request 1.

Check yourself#

  1. 1
    In which two files is the sampler code, and which one holds the fused_sample call?
    easy
    Show answer

    layers/sampler.py (the Sampler class) and layers/sampler_utils.py. process_sampling in sampler_utils.py calls fused_sample (deepinfer/model_executor/layers/sampler_utils.py:185-194).

  2. 2
    A follower rank of context parallelism calls Sampler.forward in a decode step. What does it run, and what does it return?
    medium
    Show answer

    It gathers its rows and computes the logits, but does not use them. Then it runs DFlash.decode_forward without a driver input, and returns SamplerOutput(post_funcs=[]) (deepinfer/model_executor/layers/sampler.py:141-161). Inside DFlash, it gets the driver's new tokens by a broadcast (deepinfer/model_executor/models/mtp/dflash.py:358-365).

  3. 3
    Why does the decode path keep sampled_token_ids_gpu and num_accepted_tokens_gpu on the device?
    medium
    Show answer

    With ZOS, the next step is scheduled before the CPU sees these values. The worker uses the device copies to fix the next step's inputs and seqlens_k without a sync (deepinfer/model_executor/layers/sampler.py:258-291, deepinfer/worker/worker.py:220-243).

  4. 4
    In the worked example, request 0 has top_logprobs = 0. Why does its row still get a top-logprob tensor of width 4?
    hard
    Show answer

    max_top_logprobs is the maximum over all requests of the batch (csrc/engine/prepare_sample.cpp:157), and _prepare_top_info uses that one width for all rows (deepinfer/model_executor/layers/sampler.py:642-643). This is in the deep dive "Worked example".

Related pages

  • The samplerThe sampler turns the hidden states of the rows that need a token into float32 logits, applies temperature, top-p and top-k, and draws one token per request with a seeded hash. In decode steps it also verifies the draft tokens.
  • Speculative decodingA small draft model guesses the next 5 tokens. In the next decode step, the main model checks all 5 at the same time, keeps a prefix with rejection sampling, and samples one more token. The output distribution stays within a very small, proven bound of the target distribution (a 5e-5 penalty).
  • DSpark: DFlash drafts and confidence-scheduled verificationDSpark makes 5 drafts per request with the DFlash draft model and predicts how likely each draft is to pass. With DEEPINFER_ENABLE_MTP_VARLEN=1, the scheduler then sends only the drafts that give the most tokens per unit of device time.
  • Structured outputsA structured-output request carries a grammar (regex, JSON schema or EBNF). DeepInfer compiles it with xgrammar on a pinned CPU thread pool, then masks every token that the grammar does not allow, also on each draft row.
  • models/mtp/dflash.py: the DFlash draft modeldflash.py holds DFlash, the draft model of DSpark. It writes draft keys from main-model features during the forward pass, makes 5 drafts per request in one pass after the verification, and stores drafts, logprobs and confidences in the MTP info pool.
  • engine/prepare_sample.cpp: the sampler inputsprepare_sampler_inputs reads the scheduled sequences once and builds the arrays that the sampler needs: which model-output rows to sample, per-sequence temperature, top-p, top-k and seed, and the draft-token bookkeeping of speculative decoding.
  • worker/model_runner.py: the ModelRunner classModelRunner owns the model object on one rank. It builds the input metadata, runs the forward pass (eager or as a CUDA graph replay), prepares the sampler inputs, runs the memory profile and captures the graphs.
  • tilelang_ops/ soon
