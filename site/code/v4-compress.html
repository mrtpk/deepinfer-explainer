v4_modules/compress.py: the KV compressor

AdvancedCode mapabout 6 min read + 3 min deep dives

Code version: DeepInfer @ 9bd9cf2 · 2026-10-21

Before you read

This page uses ideas from these pages:

  • KV compression (C1 and C2) Advanced
  • MLA attention: one latent vector per token Advanced

Purpose#

compress.py makes the compressed cache entries of one layer: it mixes the token pairs of a C2 layer, then normalizes, rotates, casts and stores each entry.

Filedeepinfer/model_executor/models/v4_modules/compress.py, 167 lines. Role 2 "runtime adapter" (deepinfer/model_executor/models/v4_modules/__init__.py:10-15).
Main classesKProject (deepinfer/model_executor/models/v4_modules/compress.py:32), Compressor (deepinfer/model_executor/models/v4_modules/compress.py:56).
Runs inEvery worker process, inside the attention of each KV-source layer with compressed KV. All work is device kernels; decode runs inside a CUDA graph.
Called byV4Attention._store_main_kv (attn.py); MQA.store_index_kv (index_attn.py) for KProject.
CallsTileLang interface kernels compress_and_update_state_prefill, compress_and_update_state_decode, fused_norm_rope_hadamard_cast_store_kvcache, gather; get_kv_cache_format.
Not in this fileThe weights (mla_attn.py), the merged projection GEMM (attn.py), the index-K norm and store (index_attn.py), the kernel code (layers/tilelang_ops/), the cache layout (worker/cache_engine.py).

The module docstring says the same in three lines (deepinfer/model_executor/models/v4_modules/compress.py:1-6). The concept is on KV compression (C1 and C2).

Where it sits#

Who calls it#

  • V4Attention._init_compressor_and_indexer makes one Compressor per KV-source layer with compressed KV, from the container attn_module.PackedWkv (deepinfer/model_executor/models/v4_modules/attn.py:345-347).
  • V4Attention._store_main_kv calls forward_store_kv_cache with the projected KV, ca_cache and ca_state. It asks for pre_rope_kv only when the layer has its own indexer (deepinfer/model_executor/models/v4_modules/attn.py:509-523). This happens in the normal path and in the YOCO full-KV path (deepinfer/model_executor/models/v4_modules/attn.py:546, deepinfer/model_executor/models/v4_modules/attn.py:584, deepinfer/model_executor/models/v4_modules/attn.py:708).
  • MQA.__init__ makes a KProject in index-K source layers (deepinfer/model_executor/models/v4_modules/index_attn.py:91-94). MQA.store_index_kv calls forward_pre_norm and reads norm (deepinfer/model_executor/models/v4_modules/index_attn.py:144-145).

No code in the repo calls Compressor.forward or KProject.forward; the callers use the other methods.

What it calls#

  • Compression kernels in layers/tilelang_ops/compress.py: one for prefill, one for decode (deepinfer/model_executor/models/v4_modules/compress.py:16-19). ops.py picks the CUDA or Ascend version.
  • The fused transform fused_norm_rope_hadamard_cast_store_kvcache (deepinfer/model_executor/models/v4_modules/compress.py:20-26). This file passes no Hadamard arguments.
  • Helpers: gather for the CP reorder, get_kv_cache_format, convert_rmsnorm, ReplicatedLinear (deepinfer/model_executor/models/v4_modules/compress.py:11-29).

Compressor.__init__#

  1. Line 71: the container must be a SoftmaxAPEGatedColumnParallelLora (see v4_modules/mla_attn.py: the attention weight containers).
  2. Lines 75-76: only ratios 1 and 2.
  3. Lines 77-78: overlap and APE were removed. The default of use_ape here is True, so the config must say False; the HF loader does (deepinfer/hugging_face/config.py:41).
  4. Line 79: the RMSNorm weight of the container. Line 80: the layer's RoPE table, shared with V4Attention.

Compressor.forward_pre_norm#

  1. Lines 89-93 (C1). The input must be bf16 and there is no state. With context parallelism, mirror_cp_reverse_index puts the gathered rows back in sequence order.
  2. Lines 95-96 (C2). The input must be fp32 [T, 1024] with a state. chunk(2) gives score (the Gate output) and latent (the A output).
  3. Lines 98-109 (prefill). The kernel makes one entry per complete pair of the chunk, reads the first token of a pair from the state when it came in an earlier chunk, and stores the last tokens into the state (deepinfer/model_executor/layers/tilelang_ops/compress.py:178-209). CP is handled inside the kernel with the reverse index.
  4. Lines 111-119 (decode). One row per query token. max_seqlen_q = DEEPINFER_USE_NEXTN_DECODE + 1 lets the kernel check the state size (deepinfer/model_executor/layers/tilelang_ops/compress.py:98-100).

Compressor.forward_store_kv_cache#

  1. Line 144. positions_c[ratio]: the RoPE position of each entry, the position of its first token.
  2. Lines 145-146. Add a head axis of size 1; allocate pre_rope_kv only when the caller asks.
  3. Line 147. The cache format comes from the last dimension of ca_cache: 288 B (FP4) or 528 B (FP8).
  4. Lines 150-157. RMSNorm, then RoPE on the last rotary_dim values (offset = 512 − rotary_dim).
  5. Lines 159-165. Store at slot_mapping_store_ca[ratio]; slot −1 means no write. out_stage="norm" copies the vector after the norm and before RoPE into pre_rope_kv.
  6. Line 167. Remove the head axis: [rows, 512].

In decode, pre_rope_kv has one row per query token; rows where no entry ends are zero rows. The index-K store sends them to slot −1, so nothing is written for them.

Deep dive

Worked example: one decode step in a C2 layer

One sequence at positions 1,000 … 1,005 (1 token + 5 drafts), FP4 cache, state_id 7.

  1. projected_kv is fp32 [6, 1024]; score and latent are [6, 512].
  2. The decode kernel writes each token into state slot (context_len − 1) % 7: positions 1,000 … 1,005 go to slots 6, 0, 1, 2, 3, 4 (deepinfer/model_executor/layers/tilelang_ops/compress.py:227-232).
  3. Positions 1,001, 1,003 and 1,005 end a pair. Their rows of kv_compressed get the mix of (1,000, 1,001), (1,002, 1,003) and (1,004, 1,005); the other rows are zero (deepinfer/model_executor/layers/tilelang_ops/compress.py:236-248).
  4. C++ (or the ZOS device kernel) gave positions_c = [0, 1000, 0, 1002, 0, 1004] and slots −1 for the even positions (csrc/engine/input_metadata/prepare_tensor_input_v4.cpp:79-91).
  5. The fused kernel writes 3 entries of 288 B: entries 500, 501 and 502 of the sequence, at block_table[500 / 64] × 64 + 500 % 64 and the next two rows.

Check yourself#

  1. 1
    Which layers have a Compressor?
    easy
    Show answer

    Layers with compressed KV that are KV sources (deepinfer/model_executor/models/v4_modules/attn.py:345-346). SWA-only layers and share-KV consumers have none.

  2. 2
    What is pre_rope_kv, and who asks for it?
    medium
    Show answer

    The entry after the RMSNorm and before RoPE, bf16 [rows, 512] (deepinfer/model_executor/models/v4_modules/compress.py:159-167). A layer with its own indexer asks for it (return_pre_rope_kv=self.has_local_index, deepinfer/model_executor/models/v4_modules/attn.py:522); KProject projects it to the index keys.

  3. 3
    How does forward_store_kv_cache know whether to write FP4 or FP8 entries?
    medium
    Show answer

    It does not get a flag. get_kv_cache_format reads the last dimension of ca_cache: 288 means FP4, 528 means FP8 (deepinfer/model_executor/models/v4_modules/compress.py:147, deepinfer/model_executor/layers/tilelang_ops/cache_common.py:171-187).

  4. 4
    In a decode step at positions 1,000 … 1,005, which rows of kv_compressed are not zero, and what are the matching positions_c?
    hard
    Show answer

    The rows of positions 1,001, 1,003 and 1,005, because they end a pair (deepinfer/model_executor/layers/tilelang_ops/compress.py:236-248). Their positions_c are 1,000, 1,002 and 1,004: the first token of each pair (csrc/engine/input_metadata/prepare_tensor_input_v4.cpp:82-86). See the deep dive "Worked example".

Related pages

  • KV compression (C1 and C2)A compressed layer stores one 512-value cache entry per token (C1) or per 2 tokens (C2). C2 mixes the two tokens with a learned softmax gate and keeps the score and latent of the most recent tokens in a small fp32 state ring. Entries are FP4 (288 B) by default, or FP8 (528 B).
  • Sparse attention with an indexerIn a sparse layer, a small indexer scores all compressed keys for each query and keeps the best index_topk. The main attention then reads only those keys plus the sliding window.
  • YOCO and SWA bounded replayYOCO splits the main layers into producer and consumer layers. Consumer layers project their compressed KV from one shared hidden state. With the optional prefill truncation (README feature "Decoder SWA bounded replay"), a prefill computes the consumer layers only for the last KEEP_TOKENS prompt tokens (140 in the README), with the window cut at that range. Only their compressed KV still covers every token.
  • v4_modules/attn.py: the MLA attention runtimeattn.py turns the MLA weight container into runtime weights and runs one attention layer per call: projections, sliding-window and compressed KV stores, the indexer, the FlashMLA kernel and the output projection. It also holds the DFlash draft attention.
  • v4_modules/index_attn.py: the sparse-attention indexerindex_attn.py holds the class MQA. It stores the FP4 index keys, scores every compressed key for each query with DeepGEMM, and selects the top-k keys with DeepSelect, in prefill and in decode, with optional candidate blocks.
  • v4_modules/mla_attn.py: the attention weight containersmla_attn.py allocates the weights of one attention layer with their Hugging Face names and shapes: the low-rank Q and KV projections, the compressor, the indexer, the grouped output projection and the attention sinks. It has no forward.
