linear.py: ReplicatedLinear and the FP8 GEMM path

IntermediateCode mapabout 8 min read + 3 min deep dives

Code version: DeepInfer @ 9bd9cf2 · 2026-10-21

Before you read

This page uses ideas from these pages:

  • Number formats: BF16, FP8, FP4 Beginner
  • Low-precision formats in DeepInfer Advanced

Purpose#

layers/linear.py runs the dense, non-expert linear layers of the model and the logits GEMM on DeepGEMM, in BF16 or FP8; v4_modules/linear.py only describes the shapes of the checkpoint weights.

Filesdeepinfer/model_executor/layers/linear.py (185 lines) and deepinfer/model_executor/models/v4_modules/linear.py (34 lines).
Main classesRuntime: ReplicatedLinear(torch.nn.Module) (deepinfer/model_executor/layers/linear.py:36). Containers: ReplicatedLinear(nn.Linear) (deepinfer/model_executor/models/v4_modules/linear.py:8) and ParallelRoutedLinear(nn.Linear) (deepinfer/model_executor/models/v4_modules/linear.py:23). Two classes have the same name; this page says "runtime" or "container" each time.
Runs inThe worker process of each rank, on the current device stream. Decode steps run inside CUDA graphs.
Called byRuntime class: attention projections, the compressor, the MoE gate and shared expert, DFlash. bf16_gemm_nt: the logits. get_fp8_cast_params: norms, attention output, expert SwiGLU. Containers: the HF model builders and the loader.
CallsDeepGEMM: bf16_gemm_nt, fp8_fp4_gemm_nt, transform_sf_into_required_layout. tile_kernels.quant.per_token_cast.
Not in these filesRouted experts (grouped GEMM and mega-MoE in v4_modules/mlp.py), the attention einsum (attn.py), and weight loading (hugging_face/). There is no column- or row-parallel linear: no tensor parallelism exists.

Where it sits#

Who calls it#

  • Attention makes runtime layers from merged container weights, for example q_a_kv_swa_proj and q_b_proj (deepinfer/model_executor/models/v4_modules/attn.py:284-304) and out_proj (deepinfer/model_executor/models/v4_modules/attn.py:152-156). It calls them in the forward pass (deepinfer/model_executor/models/v4_modules/attn.py:394, deepinfer/model_executor/models/v4_modules/attn.py:458, deepinfer/model_executor/models/v4_modules/attn.py:225).
  • Packed-KV projections use use_fp32_output where needed (deepinfer/model_executor/models/v4_modules/attn.py:337-343). The compressor wraps its key projection (deepinfer/model_executor/models/v4_modules/compress.py:42-46).
  • MoE. The gate is a BF16 runtime layer with FP32 output (deepinfer/model_executor/models/v4_modules/mlp.py:222-227). The shared expert uses _replicated_linear (deepinfer/model_executor/models/v4_modules/mlp.py:144-145, deepinfer/model_executor/models/v4_modules/mlp.py:244-245) and adds its output into the MoE output with out_acc (deepinfer/model_executor/models/v4_modules/mlp.py:561-562).
  • DFlash, the draft model, makes four runtime layers (deepinfer/model_executor/models/mtp/dflash.py:57, deepinfer/model_executor/models/mtp/dflash.py:119, deepinfer/model_executor/models/mtp/dflash.py:148, deepinfer/model_executor/models/mtp/dflash.py:171).
  • The sampler computes the logits with bf16_gemm_nt into an FP32 tensor (deepinfer/model_executor/layers/sampler_utils.py:20-28).
  • FP8 producers share get_fp8_cast_params: RMSNorm (deepinfer/model_executor/layers/layernorm.py:50), the attention output (deepinfer/model_executor/models/v4_modules/attn.py:200), and the SwiGLU of the experts (deepinfer/model_executor/models/v4_modules/mlp.py:140-141). mHC also calls it, but only in a branch for a group size other than 32, which does not run in this release (deepinfer/model_executor/models/v4_modules/hc.py:311-313).
  • Containers. The MoE container uses ParallelRoutedLinear for the routed experts and the container ReplicatedLinear for the gate (deepinfer/model_executor/models/v4_modules/moe.py:67, deepinfer/model_executor/models/v4_modules/moe.py:97-108). prepare_meta_fp8 reads use_fp8_gemm (deepinfer/model_executor/models/v4_modules/containers.py:128).

What it calls#

  • deep_gemm.bf16_gemm_nt(a, b, d, c) (deepinfer/model_executor/layers/linear.py:33).
  • tile_kernels.quant.per_token_cast(x, **get_fp8_cast_params()) (deepinfer/model_executor/layers/linear.py:150).
  • deep_gemm.fp8_fp4_gemm_nt(x, weight, out, out_acc, recipe=(1, 1, 32)) (deepinfer/model_executor/layers/linear.py:165).
  • deep_gemm.transform_sf_into_required_layout(sf, n, k, recipe=(1, 32, 32), is_sfa=False) at construction (deepinfer/model_executor/layers/linear.py:70-76).

This page describes only the arguments. The kernels are in DeepGEMM and tile_kernels, which this site does not explain.

Walk through the main methods#

The two containers#

  1. Lines 8-20: an ordinary nn.Linear with weight [out, in], plus use_fp8_gemm. The model is built on the meta device, so no memory is used yet (deepinfer/model_executor/models/v4_modules/containers.py:1-5).
  2. Line 31: nn.Linear(h_out, h_in * n_local_experts) has the weight shape [h_in · n_local, h_out]: the experts are stacked along the first axis. The docstring calls this the "expert-major" 2-D metadata.
  3. Line 34: the weight carries n_experts. The loader needs it to allocate the packed FP4 layout int8 [n_local, h_out, h_in / 2] (deepinfer/model_executor/models/v4_modules/containers.py:72-87).

Each rank holds only its own experts, so the split is by expert, not inside one matrix. n_local = n_physical / ep_size (deepinfer/model_executor/models/v4_modules/moe.py:94-95).

Runtime __init__: prepare the scales once#

  1. Lines 61-62: use_fp32_output is allowed only for a BF16 weight.
  2. Line 65: the weight must be [output_size, input_size].
  3. Line 66: reconstruct_param makes a new parameter on the same data and keeps sf (deepinfer/model_executor/utils.py:22-26).
  4. Lines 67-76: a one-byte weight is FP8. If its scale is not yet in the platform dtype (int32 on NVIDIA, int16 on Ascend), DeepGEMM transforms it once, with the recipe (1, 32, 32). A loaded weight arrives with FP32 scales, one per 32 × 32 block (deepinfer/hugging_face/weights.py:418-420), so this transform runs at model build.

apply_weight_fp8: cast, check, multiply#

  1. Line 146: FP8 layers have no bias.
  2. Lines 148-150: a BF16 input must be 2-D and is cast here: one E4M3 row per token and one UE8M0 scale per 32 values. An input that is already a tuple (fp8, sf) skips the cast. For example, the attention gives q_b_proj the FP8 output of its norm (deepinfer/model_executor/models/v4_modules/attn.py:458, deepinfer/model_executor/layers/layernorm.py:49-50).
  3. Lines 154-162: the output is BF16. With out_acc, the GEMM writes into that tensor.
  4. Line 164: the scales of the input and of the weight must both have the platform dtype.
  5. Line 165: out_acc is also passed as the accumulator argument c. The MoE uses this to add the shared expert to the routed output in one GEMM (deepinfer/model_executor/models/v4_modules/mlp.py:526).

apply_weight_bf16 and apply_weight#

  1. Line 127: the output dtype is FP32 with use_fp32_output, else the input dtype.
  2. Line 135: the GEMM sees a 2-D view [m, k] of the input and a 2-D view of the output.
  3. Lines 136-137: the bias, if any, is added after the GEMM with a normal tensor add.

apply_weight selects the path: BF16 weight → line 175; one-byte weight → line 177; anything else → TypeError (deepinfer/model_executor/layers/linear.py:168-178).

Output allocation and the 32-byte row stride#

The output row stride must be a multiple of 32 bytes. _allocate_output rounds the physical row length up and returns a narrower view. The GEMM paths assert the stride before they run (deepinfer/model_executor/layers/linear.py:134, deepinfer/model_executor/layers/linear.py:163).

Data flow: types and shapes

TensorBF16 layerFP8 layer

inputbf16 [..., K]bf16 [M, K], or (e4m3 [M, K], packed sf)

Worked example (example sizes, not from the repository). An FP8 layer with N = 1,000, K = 7,168, and M = 256 tokens:

  • Weight: 7,168,000 bytes. Load-time scales: ceil(1,000/32) × 224 = 32 × 224 = 7,168 FP32 values.
  • Input cast: 256 × 7,168 bytes of E4M3, and 256 × 224 scale bytes = 256 × 56 int32 on NVIDIA.
  • Output: BF16, 16 values per 32 bytes, so the physical row is ceil(1,000 / 16) × 16 = 1,008 values. The tensor is [256, 1008], and the layer returns the view [256, 1000] with a row stride of 2,016 bytes.
  • The same layer with use_fp32_output (BF16 weight only): 8 values per 32 bytes; 1,000 is a multiple of 8, so there is no padding.
Deep dive

Merged weights

Attention merges several container weights into one runtime layer, for example Wq.A and Wkv.A into q_a_kv_swa_proj (deepinfer/model_executor/models/v4_modules/attn.py:281-288). merge_linear_weights concatenates the weights and their scales along the output axis, and frees the parts:

Line 55: every part except the last must have a multiple of 128 rows. Because 128 is a multiple of 32, each part then starts on a new 32-row scale block, so the concatenated scales (line 56) still belong to the right rows. The comment on line 54 says only that the last weight need not be a multiple of 128; the code does not say why the limit is 128 and not 32.

Deep dive

Configuration

These files read no environment variable. The FP8 group size is a constant: get_fp8_casting_granularity() returns 32 (deepinfer/model_executor/layers/linear.py:13-14). Other code asserts this value, for example the packed FP4 expert layout (deepinfer/model_executor/models/v4_modules/containers.py:82). The platform scale dtype comes from PLATFORM.fp8_sf_type (deepinfer/platform.py:63, deepinfer/platform.py:138). Whether a layer is FP8 comes from the checkpoint, through use_fp8_gemm on the container.

  1. 1
    Which DeepGEMM function does the runtime ReplicatedLinear call for an FP8 weight, and with which recipe?
    easy
    Show answer

    deep_gemm.fp8_fp4_gemm_nt(x, weight, out, out_acc, recipe=(1, 1, 32)) (deepinfer/model_executor/layers/linear.py:165).

  2. 2
    What is the weight shape of ParallelRoutedLinear(h_in=7168, h_out=4096, n_local_experts=8) on meta?
    easy
    Show answer

    nn.Linear(4096, 7168 × 8) gives the weight [57344, 4096]: the 8 experts are stacked along the first axis (deepinfer/model_executor/models/v4_modules/linear.py:31).

  3. 3
    When does apply_weight_fp8 skip per_token_cast, and why is that useful?
    medium
    Show answer

    When the input is already a tuple (fp8, sf) (deepinfer/model_executor/layers/linear.py:148-150). A kernel that runs just before the GEMM, such as an FP8 RMSNorm, can write FP8 output directly, so the layer does not read the BF16 data again (deepinfer/model_executor/layers/layernorm.py:49-50).

  4. 4
    A BF16 layer has output_size = 1000 and returns BF16. What is the physical row length of its output, and what row stride does the returned view have?
    hard
    Show answer

    32 bytes hold 16 BF16 values, so the row is rounded up to 1,008 values (deepinfer/model_executor/layers/linear.py:90-95). The view has 1,000 columns and a row stride of 1,008 elements = 2,016 bytes, which is a multiple of 32.

Related pages

  • Low-precision formats in DeepInferDeepInfer keeps most weights in FP8 E4M3 with 32 × 32 block scales, routed experts in MXFP4, activations in FP8 with one scale per 32 values, the compressed KV in FP4 and the window KV in MXFP8. Scales are UE8M0 bytes, packed 4 per int32 on NVIDIA and 2 per int16 on Ascend.
  • Weight loading: from a Hugging Face checkpoint to the deviceAt start-up, each rank parses config.json, builds the model with no memory, maps every checkpoint tensor name to a model parameter, checks that each parameter has a source, and copies only the bytes that this rank needs.
  • hugging_face/weights.py and loading.py: the coverage plan and the three load channelsweights.py and loading.py check the safetensors files, build the HFCoverage plan, compare shapes from the headers, and copy the bytes through three channels (ordinary parameters, routed experts, Engram tables), with the UE8M0 scale handling of each channel.
  • v4_modules/mlp.py: the DeepseekMoE layerDeepseekMoE is the runtime MoE layer of DeepInfer. It converts the moe.py containers into the runtime layout, runs the gate, and then either DeepEP dispatch, grouped GEMMs and combine, or one mega-MoE call.
  • v4_modules/attn.py: the MLA attention runtimeattn.py turns the MLA weight container into runtime weights and runs one attention layer per call: projections, sliding-window and compressed KV stores, the indexer, the FlashMLA kernel and the output projection. It also holds the DFlash draft attention.
  • Mega-MoE: the whole MoE layer in one callInside one NVLink domain, DeepInfer replaces dispatch, the expert GEMMs, the shared expert and combine with one DeepGEMM mega-MoE call that works on a symmetric buffer. The choice is fixed per layer at start-up.
  • Expert parallelism: dispatch, grouped GEMM, combineDeepInfer splits the expert slots of every MoE layer evenly over the EP ranks. DeepEP dispatch sends each token to the ranks of its experts, DeepGEMM runs grouped GEMMs there, and DeepEP combine brings the results back.
