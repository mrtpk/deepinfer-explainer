models/deepseek_vl.py: the vision-language model class

AdvancedCode mapabout 7 min read + 2 min deep dives

Code version: DeepInfer @ 9bd9cf2 · 2026-10-21

Before you read

This page uses ideas from these pages:

  • Vision encoder (VL) Intermediate
  • models/deepseek.py: the DeepSeek-V4.1 model Intermediate

Purpose#

DeepseekVLForCausalLM extends the text model with images: it owns the vision encoder, it turns the image part of a request into tensors, and it merges the image vectors into the prefill embeddings.

Filedeepinfer/model_executor/models/deepseek_vl.py, 267 lines of Python. Many comments are in Chinese.
Main classDeepseekVLForCausalLM(DeepseekForCausalLM) (deepinfer/model_executor/models/deepseek_vl.py:26).
Runs inTwo processes. multi_modal_mapper is a class method that runs in the forked multimodal worker process. Everything else runs in the rank process; the forward runs on the device.
Called byThe model loader (load_model), the model runner (forward), MultimodalProcessor (multi_modal_mapper).
CallsVisionLanguageInstructTuner (vision encoder), MMProcessor and the image helpers of ve/processor, DeepseekForCausalLM.
Not in this fileThe ViT and projector (vision_encoder/), the placeholder expansion and the worker loop (ve/multimodal_processor.py), the chunk slicing (ve/prepare_tensor_input_vl.py).

The registry maps the only supported architecture to this class (deepinfer/model_executor/models/__init__.py:15-17). So every engine uses it, also for text-only work.

Where it sits#

Who calls it#

  • Loading. get_model calls model_class.load_model (deepinfer/model_executor/model_loader.py:65-79). This class reads the image processor config first, then calls the parent (deepinfer/model_executor/models/deepseek_vl.py:236-245). The parent calls cls.from_model_cfg so that it builds the VL class (deepinfer/model_executor/models/deepseek.py:444-445, deepinfer/model_executor/models/deepseek.py:514).
  • The worker process. MultimodalProcessor binds multi_modal_mapper to its MMProcessor with functools.partial (deepinfer/ve/multimodal_processor.py:87) and calls it for each request (deepinfer/ve/multimodal_processor.py:201).
  • The engine. LLMEngine makes a MultimodalProcessor because this class has multi_modal_mapper and the engine type is not COMPLETION (deepinfer/engine/llm_engine.py:209-213).
  • Every step. The model runner calls forward with the input metadata.

What it calls#

  • VisionLanguageInstructTuner from vision_encoder/vl_aligner.py (deepinfer/model_executor/models/deepseek_vl.py:35-39).
  • MMProcessor.convert_segments_to_tensor_dict, ImageTensorLoader.load and pack_resized_images from ve/processor (deepinfer/model_executor/models/deepseek_vl.py:17-19).
  • DeepseekForCausalLM.forward with the computed hidden states (deepinfer/model_executor/models/deepseek_vl.py:234).

Walk through the main methods#

multi_modal_mapper (worker process)#

This method runs in another process

The worker is forked at start-up (deepinfer/ve/multimodal_processor.py:93-103). multi_modal_mapper must not touch the device or engine state. It gets a dict through a queue and returns a dict.

  1. Lines 110-111: no segment_input means that the engine did not expand the prompt. The dict goes back as it is.
  2. Lines 117-119: the cached counts come from MultimodalProcessor.add. In this release the engine passes no cache length, so num_cached_images is 0 (deepinfer/engine/llm_engine.py:625).
  3. Line 130: each segment goes to its processor. Text segments give mm_token_type zeros; image segments give the layout tensors and a lazy image loader (deepinfer/ve/processor/text_processor.py:10-13, deepinfer/ve/processor/image_processor.py:282-306).
  1. Line 149: _load_image_raw_bytes runs the lazy loaders: decode, then the CPU resize. With more than one image it uses a thread pool (deepinfer/model_executor/models/deepseek_vl.py:81-89).
  2. Lines 159-164: cu_raw_bytes is the running sum of width × height × 3 in int64. The comment says the byte offsets do not have the int32 limit of the token counts.
  3. Lines 170-171: image_starts and image_lens are the token spans of the images. The chunk slicer uses them, then drops them.
  4. Line 179: images_seq_mask is true where mm_token_type ≥ IMAGE: IMAGE, IMAGE_START, IMAGE_END, IMAGE_NEW_LINE and IMAGE_PAD (deepinfer/multimodal_tokens.py:31-41).
  5. Lines 184-186: the key set must equal MM_METADATA_KEYS of ve/schema.py, else AssertionError.

get_input_embeddings and forward#

  1. Line 200: the normal embedding. The comment says that the gather kernel gives zero rows for ids at or above vocab_size; the kernel itself is in TileLang.
  2. Lines 202-218: only when the batch has image bytes, the tuner runs the vision encoder and writes the image vectors in place. A chunk without images has images_raw = None.
  3. Lines 221-222: the mask always exists after this method.
  4. Lines 232-233: the VL class computes the embeddings in every prefill, also text-only. So the embedding line of DeepseekModel.forward runs only in decode (deepinfer/model_executor/models/deepseek.py:161-162).

load_model and derive_image_transform_cfg#

The device kernel rgb_pad_to_patches uses one mean, one std and one pad value for all three channels, so the method asserts equal channels and a nonzero std. It also asserts that the processor dtype is bfloat16. The HF processor config sets mean and std to 0.5 (deepinfer/hugging_face/processor.py:34-35). So the pad colour is int(0.5 × 255) = 127. The comment says int() truncates, to match the processor.

The tuner reads these keys with cfg["..."] and no default. A comment explains: a default would let the ViT silently get pixels in [0, 1] that are not normalized, so a missing value must raise KeyError (deepinfer/model_executor/models/vision_encoder/vl_aligner.py:22-27).

Deep dive

Cached image prefixes (not active in this release)

The mapper can skip images that the KV cache already holds. MultimodalProcessor.add counts the images that lie fully inside the cached token prefix and drops their bytes (deepinfer/ve/multimodal_processor.py:219-246). The mapper then replaces the cached segments with one TextLengthInput of the same length (deepinfer/model_executor/models/deepseek_vl.py:62-72). It adds zero rows in images_spatial_crop and images_input_size for the cached images, so that the per-image indices stay aligned (deepinfer/model_executor/models/deepseek_vl.py:133-158).

The only caller in the package, _enqueue, does not pass num_cached_tokens (deepinfer/engine/llm_engine.py:625). So in this release the cached count is always 0. A test calls only the first part, _compute_and_strip_cached_images, directly (tests/engine/test_mm_overwrite_prompt.py:128-137). No test in the repo calls _split_cached_prefix.

Check yourself#

  1. 1
    In which process does multi_modal_mapper run?
    easy
    Show answer

    In the forked multimodal worker process, not in the rank process (deepinfer/ve/multimodal_processor.py:197-201).

  2. 2
    A batch has only text prompts. Why does images_seq_mask still exist after get_input_embeddings?
    medium
    Show answer

    Lines 221-222 build it from the ids when the mapper made none. The comment says this keeps the MoE gate and Engram on the same masked path as a batch with images (deepinfer/model_executor/models/deepseek_vl.py:219-222).

  3. 3
    Why does derive_image_transform_cfg reject a mean of (0.48, 0.46, 0.41)?
    hard
    Show answer

    The device kernel rgb_pad_to_patches takes one scalar mean, one std and one pad value for all channels (deepinfer/model_executor/layers/tilelang_ops/image_embed_ops.py:51-53). So the method asserts equal channel values (deepinfer/model_executor/models/deepseek_vl.py:251-253).

Related pages

  • Vision encoder (VL)DeepInfer reads images in the prefill of the same engine. A worker process prepares each image, the scheduler keeps whole images in one chunk, and a ViT plus a projector turn the pixels into vectors at the image-token positions of the prompt.
  • vision_encoder/vit.py, vl_aligner.py, mlp_projector.py: the vision encodervit.py is the fixed 32-block ViT of V4.1. vl_aligner.py turns raw RGB bytes into patches, runs the ViT, joins blocks of patches, runs the MLP projector of mlp_projector.py, and writes the result into the image-token rows of the prefill embeddings.
  • deepinfer/ve/: the multimodal worker, the image processor and the schemaThe ve/ folder expands image placeholders into image tokens, runs a forked worker process that decodes and resizes images, plans the token layout of each image, moves the result through a shared pinned pool, and cuts the image data to each prefill chunk.
  • models/deepseek.py: the DeepSeek-V4.1 modeldeepseek.py holds DeepseekModel (embedding, N decoder layers, final mix and norm) and DeepseekForCausalLM (lm head, sampler, DFlash, EPLB, weight loading). The forward returns hidden states.
  • Model map: DeepSeek-V4.1-Flash in DeepInferThe hub page of the model. DeepInfer runs DeepSeek-V4.1-Flash as an embedding, N decoder layers (mHC, attention, mHC, MoE) and a final norm. This page shows the layer kinds, the optional parts and the file that holds each part.
