Sampling: temperature, top-k, top-p

BeginnerLearn the basicsabout 7 min read + 7 min deep dives

Code version: DeepInfer @ 9bd9cf2 · 2026-10-21

Before you read

This page uses ideas from these pages:

  • What an LLM does Beginner
  • Inside a transformer Beginner

In one sentence

Sampling selects the next token from the model's probabilities. Temperature, top-k and top-p shape the probabilities first; then a random number makes the choice.

The idea#

From scores to a choice#

The model gives one raw score per vocabulary token, the logits. Softmax turns them into probabilities. Sampling then selects one token. There are two simple choices, and neither is good alone:

  • Always take the most likely token (greedy decoding). The result is repeatable, but texts often become dull or repeat the same phrase.
  • Draw from the full distribution. The result is varied, but sometimes the draw selects a very unlikely token, and the text goes wrong.

Three settings give control between these two ends. They are fields of SamplingParams, one set per request.

Temperature#

Temperature T divides every logit before softmax: p = softmax(logits / T).

  • T = 1 keeps the model's distribution.
  • T < 1 makes it sharper: likely tokens get more probability.
  • T > 1 makes it flatter: unlikely tokens get more probability.
  • T close to 0 gives (almost) greedy decoding.

Example with six candidates (made-up logits 3.0, 2.5, 2.0, 1.5, 0.5, −1.0). At T = 1 the best token has probability 0.435. At T = 0.5 it has 0.641. At T = 2 it has 0.305.

Top-k and top-p#

These two filters remove the unlikely tail of the distribution. Then the probabilities of the remaining tokens are scaled up so that they add up to 1 again.

  • Top-k keeps the k most likely tokens. top_k = -1 keeps all.
  • Top-p (nucleus sampling) keeps the smallest group of most likely tokens whose probabilities add up to at least p. top_p = 1.0 keeps all. Top-p adapts: when the model is sure, the group is small; when it is unsure, the group is large.

The draw#

Put the kept probabilities side by side on a line from 0 to 1. Take a random number u between 0 and 1. The token whose part of the line contains u wins. A likely token has a long part, so it wins more often.

The random number comes from a seed. The same seed gives the same numbers, so the same request gives the same text. In DeepInfer, the seed is the field seq_seed. The deep dive shows how the number is made.

An everyday comparison#

Think of a raffle. Each token buys tickets in proportion to its probability. Temperature changes the ticket prices: a low temperature makes tickets cheap for the favourites and expensive for the rest. Top-k and top-p send the small buyers away before the draw. The seed decides which ticket the hand pulls out.

The comparison stops here: a real raffle is new each time. With a fixed seed, the "hand" always pulls the same ticket for the same request and position.

The picture#

Follow one token across panel 2. "sofa" survives top-p, because the mass before it (0.699) is still below 0.8. Top-k 2 then removes it. In panel 3, u = 0.70 is past the end of "mat" (0.622), so "floor" wins.

In DeepInfer#

This is a basics page, so this part is short. The page The sampler explains the full sampler, with draft tokens.

Step 1: the settings of one request#

The C++ engine copies the values into each sequence once (csrc/engine/sequence.hpp:103-115). For each step, the sampler gets one temperature, top-p, top-k and seed per sequence (csrc/engine/prepare_sample.cpp:158-161).

Step 2: logits only for the sampled rows#

Sampler.forward first selects the rows to sample, then computes their logits in float32 (deepinfer/model_executor/layers/sampler.py:140-142). process_sampling then calls one fused kernel for temperature, top-p, top-k, log-softmax and the draw (deepinfer/model_executor/layers/sampler_utils.py:185-194).

Temperature, with numbers

With logits zi and temperature T:

The ratio of two probabilities is exp((za − zb) / T). For "mat" and "floor" the logit gap is 0.5. The ratio is exp(0.5) = 1.65 at T = 1, and exp(1.0) = 2.72 at T = 0.5. A lower temperature makes every gap larger.

Temperature 0 in DeepInfer. Division by 0 is not possible. SamplingParams replaces any temperature below SAMPLING_EPS = 1e-5 with 1e-5, and also sets top_p = 1.0 and top_k = -1 (deepinfer/sampling_params.py:10, deepinfer/sampling_params.py:76-79). Then a logit gap of only 0.01 becomes 0.01 / 1e-5 = 1,000, and exp(−1,000) is 0 in float32. So the best token gets probability 1 in practice. Exactly equal logits still share the probability.

A negative temperature raises ValueError (deepinfer/sampling_params.py:94-95). The reference multiplies the logits by 1/T (deepinfer/model_executor/layers/tilelang_ops/fused_sample.py:209).

Deep dive

Top-p and top-k: the algorithm, step by step

The reference implementation of DeepInfer's kernel does this for each row (deepinfer/model_executor/layers/tilelang_ops/fused_sample.py:121-150):

  1. Compute p = softmax(logits / T) over the full vocabulary. The division by T happens just before this function (deepinfer/model_executor/layers/tilelang_ops/fused_sample.py:209).
  2. Sort the tokens by p, largest first. Ties keep token order (a stable sort).
  3. Top-p: for each token, compute the mass before it: the sum of the probabilities of all better tokens. Remove the token if that mass is greater than top_p (line 139). So the first token always stays.
  4. Top-k: rank the tokens that are left. Remove every token with rank ≥ top_k, unless top_k is −1 (line 149).
  5. Set the logits of removed tokens to −∞ and take log-softmax. The kept probabilities now add up to 1.

Worked example (panel 2 of the figure, T = 1, top_p = 0.8, top_k = 2):

TokenpMass beforeTop-p 0.8RankTop-k 2Final p
mat0.4350.000keep0keep0.435 / 0.699 = 0.622
floor0.2640.435keep1keep0.264 / 0.699 = 0.378
sofa0.1600.699keep2remove0
bed0.0970.859remove——0
roof0.0360.956remove——0
moon0.0080.992remove——0

Top-p alone keeps 3 tokens with mass 0.859, the smallest group that reaches 0.8. With top-k 2, the final group is {mat, floor}.

The order matters. DeepInfer measures top-p on the full distribution, then cuts to k. Some other engines cut to k first and measure top-p on the renormalized top-k probabilities. Example: p = (0.5, 0.3, 0.2), top_k = 2, top_p = 0.55.

  • DeepInfer order: mass before the second token is 0.5 ≤ 0.55, so it stays. Result: 2 tokens.
  • Top-k first: renormalized (0.625, 0.375). Mass before the second token is 0.625 > 0.55, so it goes. Result: 1 token.

The kernel tests check the DeepInfer rule (deepinfer/model_executor/layers/tilelang_ops/fused_sample.py:366-377). Without its smallest token, the kept prefix has a full-softmax mass of at most top_p. The prefix has at most k tokens.

Limits. top_p must be in (0, 1]; top_k must be −1 or between 1 and the int32 maximum, so top_k = 0 raises ValueError (deepinfer/sampling_params.py:96-99). A top_k larger than the vocabulary keeps all tokens (deepinfer/model_executor/layers/tilelang_ops/fused_sample.py:149).

Deep dive

The seeded draw and determinism

The draw in DeepInfer does not use a random generator with state. It makes the random number from a hash, so the result depends only on the inputs. The docstring says that the result is "deterministic in (seq_seeds, sample_positions, is_nextn_predict)", and independent of batch size and row order (deepinfer/model_executor/layers/tilelang_ops/random_sampling.py:17-20). The PyTorch reference shows the steps:

  1. Line 79: mix the token position with a case number: position · 3 + case, times a large odd constant. The case is 0 for a normal sample. Case 1 is the new sample after the main model rejects a draft token, and case 2 is the accept test of a draft (deepinfer/model_executor/layers/tilelang_ops/fused_sample.py:239, deepinfer/model_executor/layers/tilelang_ops/fused_sample.py:245).
  2. Line 80: mix the value once more with a shift and an XOR, and add the request seed seq_seed.
  3. Line 81: the SplitMix64 hash turns the 64-bit value into a uniform number u in [0, 1) (deepinfer/model_executor/layers/tilelang_ops/random_sampling.py:58-67).
  4. Lines 82-84: build the running sum (CDF) of the kept probabilities in float64. Return the first token whose running sum is greater than u × total.

Worked example (panel 3): kept probabilities (0.622, 0.378), CDF (0.622, 1.000). With u = 0.70: 0.622 is not greater than 0.70; 1.000 is. The sampler returns the second token, "floor". The value 0.70 is illustrative; the real u comes from the hash.

Which position? In a prefill step, the position is seqlen_k, the number of tokens in the sequence so far. That is the position of the token that the step makes (csrc/engine/prepare_sample.cpp:198). In a decode step, it is seqlen_k − seqlen_q + 1: the position of the token that the first new row predicts (csrc/engine/prepare_sample.cpp:206). The draft module samples with the tag "mtp", which adds the seed offset 1000000007, so its random numbers differ from those of the main sample (deepinfer/model_executor/models/mtp/dflash.py:329, deepinfer/model_executor/layers/tilelang_ops/fused_sample.py:15, deepinfer/model_executor/layers/tilelang_ops/fused_sample.py:93).

The default seed is random. If you do not set seq_seed, SamplingParams takes 64 random bits from Python's random module (deepinfer/sampling_params.py:85-91). So two runs differ. For repeatable output, the README asks for a fixed seq_seed together with DEEPINFER_BATCH_INVARIANT=1 and DEEPINFER_ENABLE_MTP_VARLEN=0, on NVIDIA only (README.md:28). The same seed alone is not enough: the logits themselves can differ slightly between batches. See Determinism and batch invariance.

Engine-wide settings that change sampling:

  • DEEPINFER_SAMPLER_FORCE_TOPK (default 0, off; deepinfer/environ.py:150): keep only the N largest logits of each row before all other steps (deepinfer/model_executor/layers/sampler_utils.py:166-167). This is faster, but tokens outside the N best can never be drawn.
  • DEEPINFER_DECODE_TOKEN_BLACKLIST (default empty; deepinfer/environ.py:151): token ids whose logits the sampler sets to −∞ (deepinfer/model_executor/layers/sampler.py:168-169).
Deep dive

What the returned logprobs mean

The fused kernel returns "processed target logprobs" (deepinfer/model_executor/layers/tilelang_ops/fused_sample.py:51-52). These are the log-probabilities after temperature, top-p and top-k. So the logprob of an output token is the log of its final probability, not of the raw model probability.

In the worked example, "floor" was drawn. Its returned logprob is ln 0.378 = −0.973. The raw model probability was 0.264 (ln = −1.332). A removed token, for example "sofa", has logprob −∞.

top_logprobs = n selects the n best entries of the same processed row (deepinfer/model_executor/layers/sampler.py:636-648). With top_k = 2 and top_logprobs = 4, only two entries are finite.

What can go wrong#

  • "Greedy" that is not exactly greedy. Temperature 0 becomes 1e-5. Tokens with exactly the same logit still share the probability, and the seed decides between them (deepinfer/sampling_params.py:76-79).
  • Different output on each run. Without seq_seed, each request gets a random seed (deepinfer/sampling_params.py:87-88). Set a seed, and read Determinism and batch invariance for the other conditions.
  • Invalid values. top_k = 0, top_p = 0, a negative temperature or top_logprobs above 1000 raise ValueError when you make the SamplingParams (deepinfer/sampling_params.py:93-105).
  • No logprobs. The parameter logprobs is ignored (deepinfer/sampling_params.py:63). Use top_logprobs for alternatives. Each output already carries the logprob of its token.
  • Logprobs that look too high. They are measured after the filters, not on the raw model distribution (deep dive "What the returned logprobs mean").

Why it matters. The same model can give careful or creative text, and repeatable or varied text, only through these few settings. The settings also change what the logprobs mean, and with speculative decoding they decide how many draft tokens the engine accepts.

Check yourself#

  1. 1
    What does a temperature below 1 do to the distribution?
    easy
    Show answer

    It makes it sharper: the likely tokens get more probability, the unlikely ones less. In the example, the best token goes from 0.435 at T = 1 to 0.641 at T = 0.5.

  2. 2
    Probabilities after temperature are (0.40, 0.25, 0.20, 0.10, 0.05). Which tokens stay with top_p = 0.6 and top_k = -1 in DeepInfer, and what are their final probabilities?
    medium
    Show answer

    The mass before each token is 0, 0.40, 0.65, 0.85, 0.95. A token goes when that mass is greater than 0.6, so the first two stay. Their final probabilities are 0.40 / 0.65 = 0.615 and 0.25 / 0.65 = 0.385. The rule is in deepinfer/model_executor/layers/tilelang_ops/fused_sample.py:139.

  3. 3
    You create SamplingParams(temperature=0). What values do temperature, top_p and top_k have afterwards?
    medium
    Show answer

    temperature = 1e-5, top_p = 1.0, top_k = -1 (deepinfer/sampling_params.py:76-79).

  4. 4
    Two runs send the same prompt with seq_seed=7, but in the second run the request sits in another position of the batch. Why does the draw itself not change, and what can still change the output?
    hard
    Show answer

    The random number is a hash of the seed and the token position only. It does not depend on the row order or the batch size (deepinfer/model_executor/layers/tilelang_ops/random_sampling.py:17-20, deepinfer/model_executor/layers/tilelang_ops/random_sampling.py:79-81). But the logits can differ slightly between batches, because kernels can sum in another order. A small change can move a token across u. The README therefore also asks for DEEPINFER_BATCH_INVARIANT=1 and DEEPINFER_ENABLE_MTP_VARLEN=0 (README.md:28).

  5. 5
    With p = (0.5, 0.3, 0.2), top_k = 2 and top_p = 0.55, how many tokens does DeepInfer keep? How many would an engine keep that applies top-k first and then top-p on the renormalized probabilities?
    hard
    Show answer

    DeepInfer keeps 2. It measures top-p on the full distribution: the mass before the second token is 0.5 ≤ 0.55. Then top-k 2 keeps both (deepinfer/model_executor/layers/tilelang_ops/fused_sample.py:137-150). The other order renormalizes to (0.625, 0.375); the mass before the second token is 0.625 > 0.55, so it keeps only 1.

Related pages

  • The samplerThe sampler turns the hidden states of the rows that need a token into float32 logits, applies temperature, top-p and top-k, and draws one token per request with a seeded hash. In decode steps it also verifies the draft tokens.
  • Determinism and batch invarianceFloating-point sums depend on their order, and many kernels choose the order from the batch. DEEPINFER_BATCH_INVARIANT=1 (NVIDIA only) fixes this. Deterministic sampling also needs DEEPINFER_ENABLE_MTP_VARLEN=0 and a fixed seq_seed.
  • Speculative decodingA small draft model guesses the next 5 tokens. In the next decode step, the main model checks all 5 at the same time, keeps a prefix with rejection sampling, and samples one more token. The output distribution stays within a very small, proven bound of the target distribution (a 5e-5 penalty).
  • Structured outputsA structured-output request carries a grammar (regex, JSON schema or EBNF). DeepInfer compiles it with xgrammar on a pinned CPU thread pool, then masks every token that the grammar does not allow, also on each draft row.
  • deepinfer/sampling_params.py: SamplingParamsSamplingParams holds the per-request settings: temperature, top-p, top-k, seed, length, logprobs, EOS rules, grammar and golden tokens. This page lists every field with its default and checks, and follows each one to the sampler.
  • layers/sampler.py: the Sampler classsampler.py holds the Sampler module. It turns selected hidden states into float32 logits, samples prefill tokens, verifies draft tokens in decode steps and calls DFlash. sampler_utils.py holds the logits, sampling and prompt-logprob helpers.
  • engine/prepare_sample.cpp: the sampler inputsprepare_sampler_inputs reads the scheduled sequences once and builds the arrays that the sampler needs: which model-output rows to sample, per-sequence temperature, top-p, top-k and seed, and the draft-token bookkeeping of speculative decoding.
