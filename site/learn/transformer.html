Inside a transformer

BeginnerLearn the basicsabout 6 min read + 4 min deep dives

Code version: DeepInfer @ 9bd9cf2 · 2026-10-21

Before you read

This page uses ideas from these pages:

  • What an LLM does Beginner
  • Tokens and tokenizers Beginner

In one sentence

A transformer turns token ids into vectors and changes them in a stack of identical layers. Then it turns each vector into one score per vocabulary token.

The idea#

Three parts#

Almost every LLM is a transformer. It has three parts:

  1. The embedding. The embedding is a table with one row per token id. The model looks up the row of each input token. Each row is a vector of d numbers, where d is the hidden size (often a few thousand). This vector is the hidden state of the token.
  2. A stack of N layers. Each decoder layer reads the hidden states of all tokens and writes new ones of the same shape. N is often between 30 and 100.
  3. The output head. A final norm, then the LM head: a matrix that turns each hidden state into one score per vocabulary token. These scores are the logits.

So a text of T tokens is a matrix of shape [T, d] inside the model. Every layer keeps this shape. Only the content changes: each layer adds information to each token's vector.

Inside one layer#

A decoder layer has two blocks:

  • Attention. Tokens exchange information. Each token looks at the earlier tokens and copies a weighted mix of their information. This is the only place where tokens see each other. The page Attention, step by step explains it step by step.
  • Feed-forward network (FFN). Each token alone goes through two or three large matrix multiplies. Most of the weights of a model are here. In an MoE model, this block has many "experts", and a router selects a few of them for each token (Mixture of Experts (MoE)).

Two more parts keep the stack stable:

  • Normalization. Before each block, a RMSNorm rescales the vector of each token to a standard size.
  • The residual stream. A block does not replace its input. It adds its result to the input: x = x + block(norm(x)). The hidden state that flows through all layers is the residual stream.

Where the order of the tokens comes from#

Attention by itself does not know which token comes first. A transformer adds position information. Most modern LLMs, also DeepSeek, use RoPE: it turns the query and key vectors by an angle that depends on the position. The attention scores then depend on the distance between two tokens.

An everyday comparison#

Think of a folder that goes along an assembly line, one folder per token. At each station, a worker reads the folder and adds a note. Some stations let the worker look into the folders of earlier tokens (attention). Other stations work on one folder alone (FFN). Nothing is removed; notes only accumulate. At the end, a clerk reads each folder and writes a guess for the next token.

The comparison stops here. The "notes" are numbers, not words, and nobody designed what each station does. Training found the numbers. Also, the real model sends all folders through a station at the same time, as one matrix.

Step 3: the three changes of DeepSeek V4.1#

  • MLA attention. All query heads share one key/value entry per token. The start-up code requires exactly one KV head (deepinfer/hugging_face/config.py:53-58). See MLA attention: one latent vector per token.
  • MoE feed-forward. Every layer is an MoE block. The decoder layer asserts this type; another block type stops with AssertionError (deepinfer/model_executor/models/decoder_layer.py:57, deepinfer/model_executor/models/decoder_layer.py:38-42). See MoE routing: the gate, top-k and the shared expert.

Deep dive

Worked example. A step with 3 sequences: one prefill of 1,000 tokens, two prefills of 12 tokens. Then T = 1,024. The embedding gives [1024, d]. The layers keep [1024, hc_mult, d]. The sampler selects 3 rows, one per sequence, and computes logits of shape [3, V].

Deep dive

RMSNorm and the residual stream, with numbers

RMSNorm. DeepInfer's class documents the formula (deepinfer/model_executor/layers/layernorm.py:15-18):

RMSNorm(x) = w ⊙ x / sqrt(mean(x²) + eps)

Worked example with x = (3, 4), w = (1, 1), eps ≈ 0:

  1. mean(x²) = (9 + 16) / 2 = 12.5.
  2. sqrt(12.5) = 3.536.
  3. x / 3.536 = (0.849, 1.131). The root mean square of the result is 1.

The value of eps comes from rms_norm_eps in the checkpoint config (deepinfer/hugging_face/config.py:281).

Pre-norm residual. A standard pre-norm layer computes:

h   = x + Attention(RMSNorm(x))
out = h + FFN(RMSNorm(h))

The input x reaches the output unchanged, plus two additions. This direct path lets training send its signal through many layers. It also means that a layer can learn to change only a little.

mHC in DeepInfer. mHC widens the residual stream to hc_mult paths. Before each block, learned weights mix the paths into one block input. After the block, the output goes back into the paths. At the end of the model, the paths are mixed back into one hidden state (deepinfer/model_executor/models/v4_modules/hc.py:57-68). The details are on mHC residual mixing.

Deep dive

The feed-forward network, and where the weights are

A standard FFN with the SwiGLU activation has three matrices. For one token vector x of size d, with an inner size dff:

FFN(x) = W2 · ( SiLU(W1 · x) ⊙ (W3 · x) )        W1, W3: [d_ff, d]   W2: [d, d_ff]
SiLU(z) = z · sigmoid(z)

DeepInfer requires this activation: the checkpoint must say hidden_act: silu, and the config maps it to swiglu (deepinfer/hugging_face/config.py:53-58, deepinfer/hugging_face/config.py:278).

Weight count per layer (standard dense layer, illustrative numbers):

BlockWeightsd = 4,096, dff = 11,008
Attention (Q, K, V, output; full multi-head)4 · d²67.1 million
FFN (SwiGLU)3 · d · dff135.3 million
Two RMSNorm weights2 · d8,192

So in this example the FFN holds about two thirds of the layer. An MoE layer replaces the one FFN with many expert FFNs. Each token uses only a few of them, so the model can be very large but the work per token stays small.

Simplified

The numbers are a generic example, not DeepSeek V4.1. MLA attention uses low-rank projections, so its weight count is different. DeepInfer reads all sizes from the checkpoint config (deepinfer/hugging_face/config.py:271-300).

Deep dive

DeepSeek V4.1 in DeepInfer: the checks at start-up

The config loader accepts only the variant that the run-time code supports:

  1. SwiGLU (hidden_act = silu), no attention bias, attention dropout 0.
  2. num_key_value_heads = 1: one KV head, the MLA design.
  3. BF16 parameters in the checkpoint.

Other start-up facts that a reader of the model code meets:

  • Head size. The KV entry has kv_lora_rank + qk_rope_head_dim numbers, and the config sets kv_lora_rank = head_dim − qk_rope_head_dim (deepinfer/hugging_face/config.py:287-289). The cache code asserts that the sum is the 512 elements of the KV cache format (deepinfer/worker/cache_engine.py:46-56, deepinfer/model_executor/layers/tilelang_ops/cache_common.py:109-111). So head_dim is 512 (inferred).
  • Head count. The attention kernels accept 64 or 128 query heads. Another count up to 128 is padded with zeros to the next allowed count; more than 128 raises ValueError (deepinfer/model_executor/layers/attention_backend.py:5-23).
  • One architecture. The registry maps DeepseekV41ForCausalLM to the vision-language class DeepseekVLForCausalLM (deepinfer/model_executor/models/__init__.py:14-17). The text model is inside it; see Vision encoder (VL).
  • Extra parts. Some layers also have Engram memory (deepinfer/model_executor/models/decoder_layer.py:80-83). A draft module (DFlash) shares the embedding and the LM head (deepinfer/model_executor/models/deepseek.py:300-302).

What can go wrong#

  • Another model. A checkpoint with several KV heads, attention bias or a non-BF16 dtype stops at start-up with ValueError (deepinfer/hugging_face/config.py:53-60).
  • Too many heads. More than 128 query heads raise ValueError in the attention backend (deepinfer/model_executor/layers/attention_backend.py:15-16).
  • A dense layer. The decoder layer accepts only MoE blocks. Another block type fails the assert in DeepseekDecoderLayer.__init__ (deepinfer/model_executor/models/decoder_layer.py:57). The helper that builds the MLP also raises NotImplementedError for other types (deepinfer/model_executor/models/decoder_layer.py:38-42).
  • Logits from the model. Code that expects the forward pass to return logits gets hidden states. Call the sampler path, or multiply by the LM head yourself (deepinfer/model_executor/models/deepseek.py:246-248).

Why it matters. All model pages of this site use this skeleton. A page can talk about MLA, MoE, mHC, Engram or YOCO. For each one, ask two questions: which part of the skeleton does it change, and does the shape [T, d] stay the same?

Check yourself#

  1. 1
    A step has 500 tokens and the hidden size is d. What is the shape of the hidden states between two decoder layers, in a plain transformer?
    easy
    Show answer

    [500, d]. Every layer keeps this shape. Only the LM head changes it, to [rows, V].

  2. 2
    In which block do tokens exchange information?
    easy
    Show answer

    In attention. The FFN works on each token alone.

  3. 3
    Compute RMSNorm of x = (1, 1, 1, 1) with weights of 1 and eps ≈ 0. Then compute it for x = (2, 2, 2, 2).
    medium
    Show answer

    Both give (1, 1, 1, 1). mean(x²) is 1 and 4, the roots are 1 and 2, and x divided by the root is 1 in both cases. RMSNorm removes the overall size of the vector.

  4. 4
    Why does DeepseekModel.forward in DeepInfer return hidden states and not logits? Give the reason from the code and a number.
    hard
    Show answer

    The sampler needs logits only for the rows that it samples: in a prefill step, the last token of each sequence (csrc/engine/prepare_sample.cpp:197). It gathers those rows first, then multiplies by the LM head weight (deepinfer/model_executor/layers/sampler.py:140-142, deepinfer/model_executor/models/deepseek.py:392-394). Take a prefill of 1,024 tokens and V = 129,280 (inferred). Logits for all rows would need 1,024 × 129,280 × 4 bytes ≈ 530 MB. One row needs about 517 KB.

Fewer KV heads (GQA, MQA, MLA) make the KV cache smaller; DeepInfer uses MLA with one shared KV entry per token.
  • Mixture of Experts (MoE)An MoE layer has many small feed-forward networks (experts). A router sends each token to only a few of them. DeepInfer's model uses MoE in every layer, with a top-k gate, shared experts and expert parallelism.
  • The KV cacheThe KV cache keeps the keys and values of earlier tokens, so each new token needs only its own keys and values. DeepInfer stores the cache in blocks of 128 tokens.
  • Model map: DeepSeek-V4.1-Flash in DeepInferThe hub page of the model. DeepInfer runs DeepSeek-V4.1-Flash as an embedding, N decoder layers (mHC, attention, mHC, MoE) and a final norm. This page shows the layer kinds, the optional parts and the file that holds each part.
  • MLA attention: one latent vector per tokenIn DeepInfer's MLA, all query heads of a layer read one 512-value vector per token. This vector is the key and also the value, so the KV cache keeps one small entry per token.
  • MoE routing: the gate, top-k and the shared expertIn each MoE layer, a gate scores every expert for every token. DeepInfer sends each token to its top-k routed experts and to one shared expert, and maps each choice to a physical expert slot.
  • mHC residual mixingDeepSeek-V4.1 keeps the residual stream as hc_mult parallel streams. Before each sub-layer, learned weights mix the streams into one input. After it, the output goes back into all streams. The model ends with one fold.

  • models/deepseek.py: the DeepSeek-V4.1 modeldeepseek.py holds DeepseekModel (embedding, N decoder layers, final mix and norm) and DeepseekForCausalLM (lm head, sampler, DFlash, EPLB, weight loading). The forward returns hidden states.
